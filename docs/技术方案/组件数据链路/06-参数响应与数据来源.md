# 组件数据链路参数、响应与数据来源

本页消费静态归属和 runtime observation (见 doc-id:data-flow-04-static-attribution)、(见 doc-id:data-flow-05-runtime-observation)，模型只使用候选契约 (见 doc-id:data-flow-07-model-protocol-config)，所有值策略和上限以 (见 doc-id:data-flow-10-security-performance) 为准。

## 请求表示

每个请求依赖分别表示：

- protocol kind：HTTP、GraphQL、RPC、Server Action、unknown。
- direction：read、write、read-write、unknown；不得只按 GET/POST 粗暴推断业务语义。
- method/operation。
- declared URL template 和当前 mode 分支。
- observed sanitized URL；若动态值敏感则只显示结构。
- request callsite、trigger/call path、事实状态。
- parameters、response contract、consumed fields、data locations。

相同 URL 的不同 callsite、参数来源或 operation 分开保留；同一 callsite 的重复 observation 在 UI 聚合次数，但原记录可展开。

## URL 规则

| 情况 | 展示 |
| --- | --- |
| 静态字面量 path | `/wechat/query` |
| baseURL + path 当前 mode 可证 | `https://api.shengsuanyun.com/wechat/query` + “当前 mode 声明” |
| template 动态 path | `/modelmash/${params.id}`；当次值默认隐藏或按策略脱敏 |
| query | key 保留，value 默认 `•••` |
| signed URL/identifier | origin 可安全识别时保留；签名 path/query 隐藏 |
| 多 build 分支 | 逐分支展示，当前运行分支单独标记 |
| 无法解析 | expression 摘要 + unknown，不执行表达式 |

fragment 永不存储。用户名/密码式 authority、token-like path segment、长熵值和配置命中的敏感字段在进入 observation store 前删除或替换，不能先存原值再等 UI 隐藏。

## 参数模型

参数按 `path/query/body/header/cookie/variable/form/unknown` 分组。每个参数包含：

- name 或安全 JSON path。
- static type、runtime primitive/shape（若支持）。
- source kind：prop/state/route/form/context/store/constant/derived/unknown。
- source expression 的有界摘要和 evidence location。
- required/conditional/branch 信息。
- sensitive classification 和 value policy。
- declared/observed 状态。

默认展示 key、类型、来源和结构，不展示值。例如：

```text
body.phone        string   ← Form values.phone       值已隐藏
body.password     string   ← Form values.password    敏感，永不采集
body.callback_url string?  ← URLSearchParams         条件字段，值已隐藏
header.x-token    string?  ← dev auth adapter        敏感，永不采集
```

object spread 要保留来源：`{ ...values, inviteCode, from }` 不能假装已经知道 `values` 的全部 key；只有 Form schema、类型或运行时支持证据补齐后才展开。

## Runtime shape 的严谨边界

任意 JavaScript 对象可能是 Proxy，任何属性枚举、descriptor 或序列化都可能触发用户代码。因此首版不得承诺“安全遍历任意 props/state/request body”。规则为：

1. 参数以静态 key/type/来源为主；运行时只记录 primitive type 和平台明确的 body kind。
2. runtime deep shape 只接受经过锁定 parser/result tap 产生、在支持契约中确认的 JSON-compatible 数据。
3. 不调用 getter、`toJSON`、iterator、自定义 inspect、对象方法或应用 serializer。
4. 无法证明对象来源时只显示 `object (not inspected)`。
5. 达到深度、字段、数组样本、字符串或总字节预算时截断并标 warning。

这意味着“响应有哪些字段”在首版由**源码实际读取字段 + 可选安全 observed shape**共同回答，而不是对所有任意值强行深拷贝。

## 响应的三层答案

| 层级 | 证据 | 展示语义 |
| --- | --- | --- |
| consumed fields | AST/def-use 中实际读取的 property path | 当前代码使用了哪些字段 |
| declared contract | TypeScript/OpenAPI/GraphQL schema 等授权声明 | 声明可能返回哪些字段 |
| observed shape | 支持 result tap 的当次 JSON-compatible 结果 | 本次响应出现的安全结构 |

三者不可合并成一个没有来源的“返回字段”。例如 `result: any` 仍可从 `data.open_id` 等访问得到 consumed fields；observed shape 只是补强。字段存在不代表值非空，observed 也不代表 API 永久契约。

shape 节点只保存 type、optional/null、field count、array length bucket 和 truncated/sensitive 标志。token/手机号/订单等值不保存；string 默认不保存内容。

stream、Blob、ArrayBuffer、File、FormData 只显示 transfer type、可安全获得的 MIME/size bucket 和“内容未读取”。

## request-origin 与 data-fed-by

### request-origin

证明请求由哪个 trigger/component 发起：

```text
componentSourceId
  → triggerCallsiteId
  → function/call edges
  → requestCallsiteId
  → observationId（若执行）
```

### data-fed-by

证明响应的哪个字段供给选中组件渲染：

```text
requestCallsiteId.responsePath
  → assignment/setter/reducer/store/cache write
  → selector/parent expression/child prop
  → selected JSX binding
```

两条链可以指向不同组件。父组件请求、子表格展示时，origin 是父组件，selected child 的关系是 upstream。

## Def-use 支持

首发静态数据边：

- 变量声明、赋值、解构、可证明 property access。
- `useState` setter 与 state binding。
- `useReducer` 仅在 adapter 能解析 action/reducer 分支时。
- JSX prop 从 parent expression 到 child parameter。
- Zustand `set`/selector/action，按锁定版本和项目 binding。
- TanStack Query query key、queryFn、returned data、selector，按锁定版本。
- `map/filter` 等纯内置转换仅保留“transformed”边和可证字段，不宣称对象 identity。

动态 property、别名逃逸、mutation through unknown function、反射或不可解析 reducer 会断开确定链，并提供 frontier diagnostic。

## Runtime 引用 provenance

对已支持、已 materialize 的 response object/array，可在 WeakMap 中登记 `requestCallsiteId + observationId + responsePath`，不修改业务对象。选中后若 React Adapter 安全返回的已授权 binding 引用与 WeakMap 相同，可补强 data-fed-by。

该能力不能遍历 Fiber 或 Store 寻找相等对象；只能比较已经由 adapter 明确交付的有限引用。spread/map/JSON round-trip 产生新引用后，除非静态 def-use 证明，否则 provenance 终止。

## 数据位置分层

| kind | 示例 | 可以声称 | 不得声称 |
| --- | --- | --- | --- |
| `component-local` | useState/useReducer | state binding、读写位置、shape | 数据库 |
| `react-context` | Context | provider/consumer 和声明 type | 全局持久化 |
| `client-cache` | TanStack Query | cache key expression、query/mutation | 已发网络请求（cache hit 时） |
| `client-store` | Zustand/Redux | slice/field/action/selector | 默认持久化 |
| `browser-persistent` | local/sessionStorage、IndexedDB | key/db/store 名和读写调用 | 已有值内容 |
| `server-handler` | 同仓 route/service | handler 位置和调用路径 | 数据库表 |
| `server-persistence` | Prisma/Drizzle | ORM operation、model/table/provider 声明 | 生产实例、凭据、执行成功 |
| `external-unknown` | 外部 API/BFF | endpoint/contract 证据 | 后端内部存储 |

Store 只有在 persist/storage adapter 可证明时才增加 `browser-persistent` 边。Zustand state 本身不能自动等同 localStorage。

## 服务端持久化的硬条件

只有全部满足才能显示 model/table/provider：

1. endpoint/action 解析到当前授权 projectRoot 内 handler。
2. 有界调用图到达受支持 ORM/SDK import symbol。
3. operation、model/table/provider 来自实际 schema 或 symbol，不来自命名猜测。
4. 所有文件通过 realpath、保护文件、大小和 sourceRoots 规则。
5. 不读取/返回 `.env*`、连接字符串、host、用户名、密码或运行时数据库内容。

Prisma `provider="postgresql"` 只能说明声明 provider；`model User` 与 `@@map("users")` 可说明 schema model/table。它仍不证明当前请求成功写入某个生产实例。

## 页面接口分类

页面接口总览默认只显示业务 dependency：

- `observed-assigned`：真实请求且归属可证。
- `observed-unassigned`：真实请求但组件归属未知。
- `declared-not-observed`：当前 route 静态声明但未执行。
- `background`：polling/refresh/mount。
- `resource`：图片/脚本/字体等，单独可选页签。

同一 endpoint 的不同 callsite 不合并；同一 callsite 的重复 polling 可以聚合次数、最近状态和频率，同时保留每次 observation。

## 事实合并优先级

1. 当次 request frame + callsite/invocation observation。
2. 已解析静态调用/def-use 边。
3. adapter 贡献的版本化语义。
4. runtime 引用 provenance。
5. source map/stack/时间只作为 diagnostic。

证据冲突时不按优先级静默覆盖：报告进入 `conflict` warning，保留双方 evidence 并降级关联，直到实现或用户解决根因。
