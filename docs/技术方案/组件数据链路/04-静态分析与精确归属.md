# 组件数据链路静态分析与精确归属

本算法遵守专题包边界 (见 doc-id:data-flow-03-architecture-packages) 和现有源码定位语义 (见 doc-id:06-source-resolution)；运行时 token 合并与响应数据边分别由 (见 doc-id:data-flow-05-runtime-observation)、(见 doc-id:data-flow-06-data-provenance) 维护。

## 准确性的根规则

`direct`、`transitive` 和 `upstream` 只能由稳定源码 ID、解析后的符号边、显式 invocation provenance 或 def-use 边证明。以下信号只能用于诊断/候选，不得单独升级为确定事实：

- 相同 endpoint 或 URL 前缀。
- 请求与 click 在时间上接近。
- `Error.stack` 中出现组件文件。
- 函数名、文件名或变量名相似。
- AI 判断“看起来是”。
- React owner/Fiber 栈里出现某组件。

## Source Anchor 与 ID

每个纳入分析的源码版本生成以下 anchor：

- `componentSourceId`：函数/类组件定义或可证明的组件 expression。
- `hostElementSourceId`：intrinsic JSX callsite，兼容现有 marker。
- `compositeElementSourceId`：业务/第三方复合 JSX callsite，只作源码定位，不向宿主组件透传业务 prop。
- `triggerCallsiteId`：事件、form submit、effect、timer/loader 等触发边界。
- `functionSourceId`：项目内可解析函数定义。
- `callEdgeId`：项目内确定调用边。
- `requestCallsiteId`：真正创建请求的 call expression。
- `dataBindingId`：response/state/store/cache/prop/JSX 间的数据边。

ID 是 session 内 opaque 值，不含绝对路径。推荐输入为：

```text
registryEpoch
fileId
sourceContentHash
AST node kind
AST structural path / ordinal
schemaVersion
```

Node Registry 负责登记并返回 opaque ID。HMR 修改 content hash 后生成新 ID；旧 observation 保留旧 `sourceVersion`，不得映射到新源码位置。目标是“同一源码版本内稳定、可授权、不可伪造”，不是承诺跨任意编辑永久不变。

### DOM 到业务组件/复合 callsite

`componentSourceId` 不能只存在 Node 图里，否则选中 AntD 内部真实 `<button>` 时仍无法回到业务组件。当前 Beta 已实现：compiler 在开发构建中把已识别的业务组件 binding 与 opaque ID 交给 Runtime 的 WeakMap registry；不修改函数对象、不包装组件、不改变引用 identity。React Adapter 从目标 DOM 对应 Fiber 向 owner 方向查找最近的已登记 component type，只返回 ID 和受限语义，不把 Fiber 暴露给 Runtime/UI。

复合 JSX callsite 的确定映射只有两条允许路径：React 18 adapter 提供的 callsite 坐标能与同 sourceVersion 的 `compositeElementSourceId` 唯一匹配；或 DOM/form 语义与当前组件内唯一兼容 trigger 能共同证明。否则只定位到 component-level，具体 trigger 保持 possible，等待用户真实操作产生 invocation evidence。

不得为此给任意第三方组件盲目注入 `data-*`/私有 prop、ref 或 wrapper；这可能被转发到 DOM、覆盖用户 prop、改变 tree/identity。component binding 注册本身也必须通过 module evaluation、tree-shaking、HMR、memo/forwardRef/lazy 和匿名 default export 的 POC；不通过的形态明确降级。

## 分析流水线

### 1. 授权目标

从选中 DOM 的 marker/React probable source 得到已注册 fileId 与起始位置，再定位最小业务组件边界。只有 Registry 已授权的 sourceRoots 才可扩图；找不到精确 component 时报告 source unavailable/approximate，不自动扩大 root。

### 2. 增量模块图

- 解析 static import、export、re-export、barrel、相对路径、alias 和 package exports。
- Vite 首发以宿主 resolver 为准，记录每条 resolution evidence。
- dynamic import 只有可常量折叠的 specifier 才入确定图；其余 diagnostic。
- type-only import 不生成运行时调用边，但可贡献参数类型证据。
- 循环依赖用 visited set 和 SCC 终止，不能无限递归。

### 3. 符号与调用图

- 基于 binding identity，而不是 callee 文本匹配。
- 跟踪局部函数、import binding、对象方法、可证明的解构/别名和 re-export。
- 对高阶函数、动态属性、反射、未知 override 返回 unresolved edge。
- 同名 `get`、`useQuery`、`save` 若 import source 不匹配适配器必须是负例。
- 调用深度、模块数、callsite 数达到预算即截断并返回 frontier，不偷偷丢失。

### 4. 请求 callsite 识别

首发识别：window/global fetch、解析后的 Axios instance/method，以及目标项目声明的窄 Axios binding descriptor。每个 callsite 提取 method、URL expression、config/body expression、source anchor 和 transport capability。

静态 constant folding 仅允许字面量、模板字面量的常量部分、同模块 const、已解析只读 import 常量和明确 build-mode 分支。不得执行项目配置、getter、函数或任意模块求值。

### 5. 事件/生命周期图

首发 trigger 类型：

- intrinsic/composite JSX 的 `onClick` 等事件 prop。
- `<form onSubmit>`，以及锁定 adapter 下的 AntD `Form.onFinish` + submit button。
- `useEffect`/`useLayoutEffect` callback。
- route/page loader 的显式入口。
- `setTimeout`/`setInterval`/Promise callback 的显式来源传播。

AntD 语义由版本化 adapter 贡献 `Button htmlType=submit → nearest Form.onFinish` 边。不能只看到按钮文本就推断 submit，也不能把同一 Form 里的“获取验证码”点击归到提交链。

## Invocation provenance

静态图能证明“可能调用”，但共享 Store/API callsite 可能被多个组件使用。为区分当次 origin，当前 Beta 采用已测试的显式来源传播，不依赖尚未标准化的全局异步上下文。

概念模型：

```ts
interface InvocationToken {
  readonly invocationId: string;
  readonly pageEpoch: string;
  readonly componentSourceId: string;
  readonly triggerCallsiteId: string;
  readonly sourceVersion: string;
}
```

编译期变换遵守以下语义：

1. trigger 函数体入口创建/恢复 token，不改变对外参数和返回值。
2. 被分析的项目函数入口捕获当前 token 到局部不可变变量。
3. 跨项目函数调用通过极短同步作用域恢复该 token；callee 入口再次捕获。
4. 请求 callsite wrapper 显式接收局部 token 与 `requestCallsiteId`，原表达式只执行一次并原样返回。
5. callback/timer/Promise continuation 只有在编译器能安全插入恢复边界时才继续 token；否则该边标记 unsupported，不能用时间窗口补成 direct。
6. 并发 invocation 使用不同 ID；相同 URL、同一 callsite 同时执行也不得串线。

变换前后必须保持函数参数长度需求、`this`、`arguments`、constructor、generator、async reject、Promise identity、函数 identity 和 source map。无法证明语义等价的函数形态不变换，进入静态 declared 或 unassigned。

## 不改变函数 identity 的原则

优先在函数体内注入进入/捕获逻辑，不在每次 React render 中创建新的 handler wrapper。对于无法修改定义体的第三方 callback，只能使用经 POC 证明的 WeakMap/cached wrapper；若 wrapper 会改变 referential equality、removeEventListener 或 memo 行为，则该路径不进入首发支持。

所有辅助符号使用 compiler 生成的无冲突 binding，并通过单一虚拟模块导入；不得把 `window.__SPOTPATCH_*` 名称散落到业务模块。

## 关联状态机

执行、证明与关联是三个正交字段，不能把 `declared` 塞进 association：

| execution | proof | association | 必需证据与 UI 含义 |
| --- | --- | --- | --- |
| `observed` 或 `declared-not-observed` | `proven` | `direct` | trigger/component 与 request callsite 在同组件且边全部解析；当前组件直接请求 |
| `observed` 或 `declared-not-observed` | `proven` | `transitive` | component → 确定项目调用边 → request callsite；当次 origin 还需 token/callsite observation；经 Hook/Store/API Client |
| `observed` 或 `declared-not-observed` | `proven` | `upstream` | response → state/store/cache/parent prop → selected binding 完整；上游请求提供数据 |
| 任意 | `candidate` | `possible` | 至少一条边不满足证明规则；只在候选/AI 辅助显示 |
| `observed` | `unavailable` | `unassigned` | 有真实 observation/callsite，但无 origin 证据；页面请求尚未归属组件 |
| `unknown` | `unavailable` 或 `conflict` | `unknown` | source/adapter/budget/权限不足或证据冲突；无法证明 |

`possible` 不得在默认组件“相关接口”数量中计为已确认；它只在展开诊断或 AI 辅助中显示。

## 静态证据链

每条确定链必须携带：

- evidence ID 和 kind。
- sourceVersion、fileId、相对显示路径、行列。
- AST/binding edge 类型。
- adapter ID/version（若有）。
- 从 component/trigger 到 request 或从 response 到 binding 的有序边。
- 截断、解析失败或不支持节点。

UI 打开源码时继续走现有受控 fileId endpoint；报告里的相对路径只用于显示，不能反向当作读取参数。

## 关键降级

- source map 丢失：保留 request observation，source 为 unavailable。
- HMR 版本变化：旧 observation 显示 stale，不映射到新行列。
- 动态 property/callee：显示 expression 与 unresolved reason，不选择“最像”的函数。
- 第三方包内部请求：可观测但若无项目 requestCallsiteId，进入 page-level external/unassigned。
- 相同 URL 多调用点：按 callsite 分开；若 runtime 无 callsite 证据不合并。
- effect 与用户操作并发：按 invocation token/trigger type 分开；缺 token 不按时间猜。

## POC 通过条件

在进入公共实现前，必须用真实 AntD Form + Zustand + Axios wrapper 证明：

- `onFinish → smsLogin/login → http.post` 的组件、trigger、callsite ID 完整。
- 两个组件并发请求同一 URL 不串线。
- handler 中 `await` 前后、timer、第三方 callback 各自符合已声明支持/降级。
- 变换不改变 function/Promise identity、异常、abort、HMR 和 source map。
- 无证据 observation 始终 unassigned，错误归属为零。

任何一项失败都必须缩小首发支持语法或重新设计，不能用 `Error.stack`/时间相关性填洞。
