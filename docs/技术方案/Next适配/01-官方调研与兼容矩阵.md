# Next.js 官方调研与兼容矩阵

## 调研快照

调研初版日期为 2026-08-08，编码前于 2026-08-09 复核。npm Registry 复核时 `next` 的 `latest` 为 `16.3.0`、`canary` 为 `16.3.1-canary.8`，Next 15 维护标签包括 `15.3.9` 和 `15.5.23`。版本会变化，因此发布包不得把“调研当日最新版本”复制为代码常量；支持范围使用 semver，CI fixture 使用锁定版本，并通过依赖更新评估新版本。

## 已确认的框架事实

| 事实 | 架构影响 |
| --- | --- |
| Next 16 默认使用 Turbopack，webpack 需显式 `--webpack` | 正式适配必须同时验证两个构建器 |
| Turbopack 不支持 webpack plugin，但支持有限的 webpack loader | source transform 必须是 Loader 兼容内核，不能依赖 webpack plugin |
| Turbopack Loader 只支持返回 JavaScript，且 Loader API、文件系统和 option 类型受限 | Loader 选项必须可序列化；资源注册和 source map 必须通过真实 POC |
| webpack 配置会为客户端、Node 服务端和 Edge 服务端多次执行，且官方不承诺自定义配置的 semver 稳定 | 包装器必须幂等、区分目标并以 CI 发现破坏性变化 |
| App Router 的 page/layout 默认是 Server Component | 不能把浏览器 Fiber 当成完整组件树；服务端输出也必须携带 host marker |
| `instrumentation-client` 自 Next 15.3 引入，在 hydration 前执行 | Next 首版最低版本选择 15.3；React hook 在这里同步安装 |
| 官方要求 `instrumentation-client` 初始化尽量控制在 16 ms 内 | 同步入口只能安装最小 hook；网络、配置和 Runtime 动态加载必须后移 |
| `rewrites` 可以代理外部 URL并保持浏览器地址 | 可把固定同源 API 前缀代理到 loopback Sidecar，但 NDJSON 流与 header 透传仍需实测 |
| 当前 `next dev` 默认 hostname 为 `0.0.0.0` | loopback Sidecar 不等于浏览器隔离；首版 CLI 必须显式绑定 loopback 并拒绝 LAN hostname |
| Next 会把 `.env*` 加载到服务端 `process.env`；`next.config.env` 会把值固定进 JavaScript bundle | 配置包装器可在服务端解析环境引用，但 Key 禁止进入 `next.config.env`、alias、Loader option 或客户端 |
| Next 16 默认启用隔离的 `.next/dev` 和 Turbopack 开发文件系统缓存 | fileId 不能跨 CLI Session 盲目复用；Loader cache key 必须含非敏感启动 epoch |
| Custom Server 会失去 Automatic Static Optimization，并与 standalone 输出存在限制 | 不采用 Custom Server 承载 SpotPatch |
| Deployment Adapters 面向构建/部署平台；稳定顶层 `adapterPath` 只存在于较新的 Next 16 | 不占用宿主唯一部署适配器入口，也不以它作为 Next 15 兼容基础 |
| Bippy 支持 React 17–19，但 React 19 的 Fiber 源码位置需要额外 JSX runtime 配置 | 不强迫宿主改 `jsxImportSource`；精确源码依靠 SpotPatch marker，Fiber source 允许降级 |

## 计划支持矩阵

以下矩阵是首个 `@spotpatch/next` 正式版本的目标，不代表当前已交付：

| 维度 | 计划正式范围 | 说明 |
| --- | --- | --- |
| Next.js | `>=15.3.0 <17` | 15.3 是 `instrumentation-client` 下限；Next 17 需独立评审 |
| Node.js | `>=20.9.0 <25` | 取 Next 16 官方下限；Node 25+ 先观察，不以本机偶然运行作为支持证据 |
| React / React DOM | `>=18.2.0 <20` | React 18/19 均需 fixture；React 19 的 Fiber source 可降级，host marker 不降级 |
| Router | App Router、Pages Router | App Router 必测 RSC、Client Component、Portal、动态路由与 streaming |
| Bundler | Turbopack、webpack | Next 15 显式 `--turbopack` 与默认 webpack、Next 16 默认 Turbopack 与显式 `--webpack` 都要验证；不发布“仅 webpack 可用”的正式版本 |
| 源码扩展名 | `.jsx`、`.tsx` | `.js` 中 JSX 是否纳入首版由 POC 后确定；不得默认为已支持 |
| 浏览器 | Chromium 最新两个主版本 | 与核心 Runtime 一致；Firefox/WebKit 先观察 |
| 操作系统 | macOS、Ubuntu、Windows | Sidecar、信号、编辑器、路径和 Git 都需平台测试 |
| 运行阶段 | `next dev` | `next build`、`next start`、静态导出必须无 SpotPatch 能力和产物残留 |
| 包管理器 | npm、pnpm | yarn、Bun 未进入首版承诺，成功安装不能替代完整验收 |

## 明确不支持或不承诺

- Next `<15.3.0`：缺少统一的预 hydration 客户端入口；不增加 Pages/App 两套手工注入方案扩大维护面。
- Next canary/preview：只作为非阻断观察，不允许替代正式版本 CI。
- Next 17：在官方发布、peer/Node 要求和构建器变化审计前保持不支持。
- 自定义 Next Server、非标准 fork、修改过的 webpack/Turbopack runtime：不承诺兼容。
- React Server Component 的完整浏览器组件栈：RSC 不在客户端形成等价 Fiber 树，只承诺 host marker 精确定位和明确降级。
- `next/image`、MDX、编译器生成 host DOM 的原始业务调用点：必须通过专项 fixture 后逐项进入支持表，不从普通 `<img>` 结果推断。
- Edge runtime 中运行 SpotPatch 本地文件或 Agent 服务：禁止；Sidecar 始终是独立 Node/loopback 进程。
- 生产环境、Vercel Preview、远程开发容器和 Codespaces：首版不承诺。远程开发需要新的网络与编辑器信任模型。
- Next 应用目录之外的 workspace/symlink 源码：首版不自动授权；在多 root 路径模型通过安全 POC 前不承诺精确定位或修改。
- `next dev -H 0.0.0.0`、LAN hostname 与 `allowLan: true`：首版明确拒绝，不以 Sidecar 绑定 loopback 推断为安全。

## 发布矩阵阻断项

以下内容必须由 required fixture 给出可重复证据。本地预览或单一宿主已经覆盖的子项会明确标注，但不能据此把整个矩阵描述为已解决：

1. Turbopack 自定义 Loader 对 `.tsx/.jsx` 的执行顺序、source map、HMR 和多 worker 行为；锁定 Next 15/16 Loader POC 已通过，仍需由正式包矩阵持续守护。
2. Loader 到 Sidecar 的内部 source 注册已实现并在 Next 16 双 bundler宿主取得 marker/source-context；冷启动吞吐、重试、崩溃和多 OS 仍缺 required evidence。
3. `beforeFiles` 外部 rewrite 对 POST、认证 header、NDJSON streaming、中断和 `basePath/trailingSlash` 的真实语义。
4. `instrumentation-client` 中 hook 安装是否始终早于 React 18/19 hydration，且与既有 instrumentation 文件可组合。
5. App Router Server Component 注入 `data-spotpatch-source` 后的 HTML、RSC 导航、hydration 和缓存一致性。
6. webpack 私有宿主已验证生产移除 client hook、marker、API 字符串、Sidecar 与内部环境标识；Turbopack、standalone、static 和完整矩阵仍未完成。
7. Next 自定义 webpack 配置、Turbopack rules、MDX/Babel/React Compiler 等宿主配置的冲突检测。
8. CLI 已改用后代进程可访问的认证 loopback 配置请求，并覆盖 schema、ack、超时和冲突；对象/同步/异步 host config、`.env*` 与零落盘矩阵仍需正式 fixture。
9. Next 默认对外监听、external rewrite、IPv4/IPv6、Host/Origin/Fetch Metadata 组合下，非本机页面无法借由 Next 代理访问 Sidecar。
10. Loader POC 已证明 Turbopack/webpack cache epoch 隔离，正式 Loader也在注册失败时 fail-open；仍需由正式包的跨进程/多 OS fixture复核。

门禁、fixture 和失败判定 (见 doc-id:next-08-testing-delivery)。任何一项失败都必须回到架构评审，不得通过降低安全或零残留标准“兼容”。
