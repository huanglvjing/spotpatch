# 上下文问答：总体架构与包边界

## 总体链路

```text
Selected DOM elements
  → Runtime SpotSelectionContext
  → POST /ask/jobs（loopback + Session auth）
  → ContextualAskManager（唯一 Job/状态/TTL 所有者）
  → SourceAuthorizer + ReadSnapshot
  → executor registry
      ├─ configured-key → @spotpatch/agent Ask engine
      └─ managed-codex → @spotpatch/bridge Codex Ask adapter
  → AskAnswerDraft（不可信）
  → server validation + source-handle resolution
  → AskAnswerResult（可信协议投影）
  → Runtime Answer card + open-editor
  → optional local ChangeDraft conversion
```

Manager 只依赖窄 `ContextualAskExecutor` 端口，不分支解析 Provider SSE 或 Codex JSONL。执行器只能返回草稿和读取证据；Manager 负责 Job 状态、关联、最终 Schema、stale 判定、结果保留和 HTTP 投影。

## 包职责

### `@spotpatch/shared`

新增纯数据和 Schema：

```text
src/model/contextual-ask.ts
src/protocol/contextual-ask.ts
src/protocol/contextual-ask-constants.ts
```

拥有 `SpotSelectionContext`、`SpotTaskEnvelope`、`AskAnswerResult`、Job/event/capability、endpoint 和稳定错误码。不得依赖 Node、DOM、Provider、Codex 或 Git。

Browser 专用导出使用 `./contextual-ask-browser` 子入口，只暴露请求/响应 DTO 和常量；Node executor 端口不进入 browser chunk。

### `@spotpatch/runtime`

新增独立开发期扩展：

```text
src/contextual-ask-panel-entry.ts
src/controller/contextual-ask-workflow.ts
src/ui/contextual-ask-contract.ts
src/ui/contextual-ask-panel.ts
src/ui/answer-renderer.ts
```

核心 controller 只持有最小 extension contract 和状态投影。Vite/Next 在 bootstrap capability 表明 Ask 启用时加载 `@spotpatch/runtime/contextual-ask-panel`，再 mount 唯一 Runtime。不得把完整 Ask panel、Markdown renderer 或厂商协议加入核心 Runtime。

### `@spotpatch/dev-server`

新增：

```text
src/contextual-ask/manager.ts
src/contextual-ask/read-snapshot.ts
src/contextual-ask/http.ts
src/workspace/activity-coordinator.ts
```

拥有 Browser HTTP、Job 幂等/单飞、Source Registry 重新授权、短期 read snapshot、executor registry、结果校验、TTL 和 cleanup。Q3 将授权与安全打开集中在 `read-snapshot.ts`，避免 authorizer 与 reader 各做一套路径判断；若未来拆文件，必须保持同一安全入口。Q4 通过 `configured-key-executors.ts` 从已解析 AI 配置统一构造并排序 Key executors；仍不得新增对 `@spotpatch/bridge` 的依赖。

### `@spotpatch/agent`

Q3 已新增无厂商依赖的端口：

```text
src/ask/executor-port.ts
```

Q4 已新增正式 Key 实现：

```text
src/ask/configured-key-executor.ts
src/ask/configured-key-prompt.ts
src/ask/configured-key-tools.ts
```

`executor-port.ts` 拥有 `ContextualAskExecutor`、`AskSourceGrant`、`ContextualAskReadSnapshot` Node 端口和稳定 executor error。Q4 实现共享 Provider session、凭据、SSE、Abort 与脱敏原语，但不 import worktree/change-set/prepared-change/check-runner，也不调用 Change engine。

### `@spotpatch/bridge`

新增：

```text
src/active/codex/ask-adapter.ts
src/active/codex/ask-runtime.ts
src/active/codex/answer-events.ts
```

实现同一 executor 端口。复用 executable、JSONL、auth/model/config isolation、process cleanup 和 thread cleanup primitives；不复用 `ManagedCodexAppServerAdapter.deliver()`、managed execution 或 write grant。

### `@spotpatch/vite` 与 `@spotpatch/next`

两者只做 composition root。Q3 已完成公共 option transport、同一 middleware/Manager 和 workspace coordinator 装配；Q4 已在 flag 开启时向 registry 注册已配置的 Key Provider/model 对，并按显式 Ask 默认项或 AI 默认项稳定排序；Q5 已完成同一 Runtime Ask extension 的条件加载。Managed Codex 装配仍属于 Q6：

- 解析公共 `contextualAsk` 开关；
- 从已解析 AI 配置构造 Key executor（Q4 已完成）；
- 从 Bridge 构造 Managed Codex executor（若启用且 capability 通过）；
- 把 executor registry 注入 dev-server；
- 条件加载同一个 Runtime Ask extension（Q5 已完成）；
- production 不注入 Runtime、endpoint、Provider/Codex 代码。

框架入口不得各自复制 Ask manager、Schema、UI 或错误文案。

## 依赖方向

```text
shared ← agent ← bridge
   ↑        ↑
runtime   dev-server
   ↑        ↑
   └── vite / next（唯一装配层）
```

`dev-server` 通过 `ContextualAskExecutor` 接收 Bridge 实现，不能反向 import Bridge。Runtime 只消费 shared browser protocol，不 import agent/bridge。`shared` 不导出进程、路径或 secret 类型。

## 执行器端口

```ts
interface ContextualAskExecutor {
  readonly executorId: string;
  capability(signal: AbortSignal): Promise<ContextualAskExecutorCapability>;
  execute(input: ContextualAskExecutorInput, signal: AbortSignal): Promise<AskAnswerDraft>;
  dispose?(): Promise<void> | void;
}

interface ContextualAskExecutorInput {
  readonly jobId: string;
  readonly envelope: SpotAskTaskEnvelope;
  readonly grant: AskSourceGrant;
  readonly snapshot: ContextualAskReadSnapshot;
}
```

端口不包含任意 cwd、command、sandbox、URL、header、model 字符串或 writable roots。执行器选择来自服务端枚举的 opaque executor ID；Browser 不能构造实现配置。

## 源码上下文分层

1. **Selection facts**：页面选择时已清洗的 DOM/React/CSS/code context。
2. **Source grant**：Node 根据当前 Session、Registry、sourceRoots、realpath、保护文件和限制签发。
3. **Read snapshot**：本 Job 的不可变/内容寻址读取视图；文件变化不会被悄悄混入同一答案。
4. **Source handles**：每个初始片段或工具读取结果对应 opaque ID、相对路径、行范围、hash 和 target 关联。
5. **Answer projection**：模型只回 handle；服务端投影为 UI 引用并在打开时再次授权。

Read snapshot 不等于 Git worktree。Key executor 可以通过受控读取端口按需获得冻结内容；Managed Codex 需要文件系统时由同一 snapshot builder 创建临时只读投影。两者共享授权语义，不复制路径规则。

## 并发与生命周期

- 每个 dev Session 最多一个活动 Ask；busy 时拒绝，不排队、不 latest-wins、不 turn/steer。
- Ask 与 Change 是否可以并行由同一 workspace activity coordinator 决定；首阶段采用互斥，避免同一选择在写入时产生陈旧答案。
- Job 创建后 selection、executor 和 model snapshot 固定；UI 改动只影响下一 Job。
- Abort 后 generation 增加；迟到 Provider chunk、Codex item 或 result 不得覆盖新状态。
- dispose 必须取消 active executor、删除临时 snapshot/thread、清空文本结果并释放事件订阅。

## 复用与去死代码纪律

- 抽取真正通用的 read/path/redaction primitive；不得复制整份 `ToolExecutor` 后把写分支留成不可达代码。
- Ask 工具数组必须由只读定义常量正向构造，不能从全工具数组运行时 filter。
- 旧 `SpotAnnotation v3` 在所有 Change 消费者迁移完成前保留；最后一个消费者删除后，在同一 PR 删除兼容 adapter、测试和导出。
- 新旧 endpoint 不做双写；协议迁移使用 server-side adapter，并有明确删除里程碑。
- 不预建 Claude/Cursor 空 adapter、feature flag 或 UI 占位。后续 Gate 开始时再增加实现，避免死代码。
