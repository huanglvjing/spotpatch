# 组件数据链路检查器方案入口

> 本文是方案与状态入口。当前工作区已完成 Vite + React 18 development-only Beta，但尚未完成全部目标 Gate，也尚未提交或发布。完整目标规范位于 [组件数据链路专题目录](./组件数据链路/00-索引与交付边界.md)，当前代码事实、启用方式与未实现清单以 (见 doc-id:data-flow-13-beta-implementation) 为准。

现有产品、架构、公共模型、安全、编码、测试和 ADR 的活动约束继续分别由 (见 doc-id:01-product-boundary)、(见 doc-id:02-architecture-stack)、(见 doc-id:03-public-api-models)、(见 doc-id:09-local-protocol-security)、(见 doc-id:11-coding-standards)、(见 doc-id:12-testing-acceptance)、(见 doc-id:15-risks-adr) 维护；本入口不覆盖它们。

## 最终工程结论

需求可以高准确度实现，但“百分百”必须定义为可自动验收的**零误归属**，不能解释为对任意框架、任意动态代码、任意外部后端都无条件知道答案。

SpotPatch 可以承诺：在声明支持且被测试覆盖的调用形式内，所有已经报告为 `direct`、`transitive` 或 `upstream` 的组件—请求关系都有确定性证据，错误关联为零；不能证明的请求进入“页面接口 / 未归属”，动态值进入“等待运行时观测”，外部数据库进入“服务端持久化未知”，绝不猜测。

推荐能力名称为 **Component Data Flow Inspector / 组件数据链路检查器**。它同时回答两类不同问题：

```text
请求发起链：组件/事件 → Hook/Store/API Client → 请求调用点 → 实际请求
数据供给链：响应字段 → state/store/cache/props → 选中组件的渲染输入
```

只做 Network 面板、只包裹 `fetch`、只读 React Fiber、只看 `Error.stack` 或只让 AI 搜代码，都无法同时满足“准确定位组件”“参数来源”“响应使用字段”和“零错误归属”。推荐方案必须组合：

1. 编译期稳定 ID 和显式调用来源传播。
2. Node 侧有界静态模块图、符号图与 def-use 数据流。
3. 页面最早期的 `fetch`/XHR 真实请求观测。
4. 证据化合并、未知分流和可审计 UI。
5. 只消费结构化证据的可选 AI 解释层。

## 调研基线与当前实现事实

- 2026-08-12 冻结基线中的 SpotPatch 没有网络 recorder、模块调用图、请求报告模型、数据链路 UI 或数据层适配器；这是立项依据，不再代表当前工作区。
- 当前工作区已经加入 component/source 稳定 ID、TypeScript semantic analyzer、开发期 fetch/XHR dispatch recorder、证据 merger、组件/页面 UI 和严格只读 endpoint。
- compiler 与 React Adapter 已能让选中 Ant Design `<Button>` 内部真实 DOM 优先回到最近的已登记业务组件；无法取得 exact identity 时才回退到授权源码坐标。
- inspecting 状态会阻止宿主 click，因此“选中登录按钮”本身不会提交表单或产生登录请求。
- 匿名外部调研确认真实项目会同时出现自定义 Axios client、直接 Axios、原生 fetch、动态 URL、Store 间接调用和父组件经 props 供给等形态；具体第三方标识和业务清单不进入本仓库。
- 大量 HTTP 结果可能缺少可靠类型，因此“返回了哪些数据”不能只靠 TypeScript，必须把运行时安全 response shape 与源码读取字段合并。
- 仓内可移植 oracle 固定覆盖 Store 间接认证、effect/timer 轮询、表格数据供给和 React Query declared/observed 分离，不依赖任何外部目录。

当前自动化 oracle 已覆盖四组关键链路，但尚未覆盖所有框架、client 和传输组合。完整差异见 (见 doc-id:data-flow-13-beta-implementation)。

匿名调研方法、通用结论和可复现 fixture 见 (见 doc-id:data-flow-02-repository-audit)。

## 关于实际接口与按钮归属

仓内中性示例使用 `POST /auth/session/query` 表达组件挂载后的 effect/timer 轮询。它可以被准确找出，但不能错误地归给同页面的登录提交按钮：

- 轮询参数键为 `session_id`、`state`，源码消费 `data.session`、`data.token`。
- 运行模式可能改变 Axios `baseURL`；未观测当前运行模式时，报告只能展示 path 和构建分支，不能拿某个生产域名覆盖开发环境事实。
- 页面进入、验证码、登录提交和成功后的 follow-up 请求必须按 trigger 分组，不能全部算成按钮接口。
- 示例域名统一使用保留域 `example.test`，不指向真实服务。

## “百分百”验收口径

仓内固定 fixture 的最终发布目标门禁如下；下表不是对任意外部项目无条件覆盖的承诺：

| 指标 | 目标 | 解释 |
| --- | ---: | --- |
| fixture 请求 callsite 识别 | 100% | 每个调用点都有稳定 ID；动态 URL 仍可标为动态 |
| 支持范围内已执行 fetch/XHR 捕获 | 100% | 不把静态资源混入业务接口 |
| 已证明组件归属准确率 | 100% | `direct/transitive/upstream` 零误归属 |
| 错误归属 | 0 | 无证据必须 `unknown/unassigned` |
| 已执行请求 method/安全 URL 表示 | 100% | 非敏感 origin/path 精确；签名/query/敏感片段先清洗 |
| 支持请求的参数 key/shape | 100% | 默认不展示敏感原值 |
| 安全 JSON 响应 shape | 100% | 流/Blob/二进制/超限明确标注，不伪造 JSON |
| fixture 表格的数据来源准确率 | 100% | 分清 request-origin 与 data-fed-by |
| 敏感值泄漏 | 0 | UI、日志、草稿、协议、AI 全链路 |

这些指标以冻结 fixture、代码快照和自动化 oracle 为分母。新增不支持语法必须先明确降级，不允许通过减少分母或静默漏报制造“100%”。详细定义见 (见 doc-id:data-flow-11-testing-acceptance)。

- 产品代码：Vite + React 18 Beta 已进入发布候选；是否发布只由最新完整验证、远端 CI 与 Changesets 发布流程决定。

## 编码启动条件复核

本次实现按照以下条件启动；完成状态与差异必须结合 `data-flow-13` 复核：

1. 专题文档 Gate D0 评审通过，术语、分母、隐私策略和首发矩阵冻结。
2. `data-flow-07` 中候选 Schema/配置的所有权迁入既有活动唯一事实源，或明确采用专题规范作为临时唯一来源。
3. 关键登录/微信/表格 oracle 与敏感数据 fixture 已进入自动化；147-callsite 与 17-table 全量 oracle 尚未完成，因此当前只能称 Beta，不能通过最终 D6。
4. POC 分支或实验目录被明确授权；POC 失败可直接删除，不向公共包泄漏半成品接口。
5. 可丢弃 POC 已迁移后删除；当前实现需要在交付前重新通过结构扫描、production leakage、lint、typecheck、全量回归与 package validation。
