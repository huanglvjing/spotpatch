# 上下文问答：安全、隐私、性能与可观测性

## 信任边界

| 数据/主体 | 信任级别 | 处理 |
| --- | --- | --- |
| framework config、Source Registry、server limits | 可信控制面 | 只在 Node 构造 |
| Browser selection/request | 不可信 | 严格 Schema、Session 和 Registry 复验 |
| question、DOM、CSS、源码、注释、规则文件 | 不可信项目数据 | 清洗、预算、prompt injection 边界 |
| Provider/Codex 输出和 tool calls | 不可信 | 严格 Schema、source handle 和限制 |
| Provider Key/Codex auth | secret | Node/子进程最小传递，永不进 Browser |
| AnswerResult | 校验后的展示数据 | 仍以安全 DOM 渲染，不视为系统事实 |

“read-only”必须由可调用能力和 OS/工具边界证明，不能由 system prompt、按钮名称或模型承诺证明。

## 主要威胁与控制

### Ask 被升级为写任务

控制：显式 `task.kind`；独立 endpoint/executor/profile；Key 无写工具；Codex read-only 投影；任何 diff/fileChange/permission upgrade 触发 `ASK_WRITE_ATTEMPTED`；转修改只构造本地 draft，并重新走 Change 授权。

### Browser/模型扩大读取范围

控制：sourceRoots 和候选文件由 Node 构造；sourceId 是唯一读取参数；realpath、普通文件、symlink、保护文件、大小和总量校验；问题中的路径/glob 不改变 grant；Codex 只能看到临时投影。

### Prompt injection

页面文案、源码注释、字符串和所谓 `AGENTS.md` 都是数据。Key prompt 明确边界，工具权限不可变；Codex 投影排除 instruction 文件并验证 `instructionSources` 为空。任何内容要求读取 secret、联网、写文件或调用外部工具都不会获得能力。

### 伪造源码引用

模型只能提交本 Job sourceId 和行范围。服务端验证 sourceId、文件 hash、行界、target 关联和结果限制，再填充 fileId/relativePath；Browser 不接受模型绝对路径。打开时再次验证 Registry 和当前 hash，变化即 stale。

### Secret 泄漏

保护集合至少包括 `.env*`、认证/Key 文件、私钥、VCS 元数据、包管理 credential 配置、用户 home 和配置 runtime。Key 不进入 Prompt、工具、错误、日志、子进程或 Browser；Codex 临时 runtime 只以受控 auth 机制连接，不把 auth 文件复制到源码投影。fake secret corpus 必须覆盖正常、错误、取消、超限和 cleanup 日志。

### 跨 Session/迟到结果污染

Job、selection、request、event 和 result 均绑定 dev Session；高熵 ID 不是单独认证。Manager 使用 generation/sequence 拒绝迟到事件；另一个 tab/Session 不能读取、取消或转换结果。HMR/重连只能恢复当前 Job snapshot，不能枚举历史。

## 数据发送范围

可能发送到配置 Provider 或 Codex 上游模型：

- 用户问题；
- 已清洗的选中元素、页面、React、DOM、CSS 和 code 摘要；
- 最多协议上限的授权源码内容，包括当前未提交内容；
- 只读工具的有界结果；
- sourceId、相对路径和行号。

默认不发送：Key、Base URL、绝对路径、完整 env、Cookie/storage/header/body 值、原始敏感 URL、整个仓库、Git Diff、检查命令/输出、业务请求数据、Provider 原始错误或模型 reasoning。

UI 同意必须明确第三方中转站/模型的数据政策不由 SpotPatch 保证。Responses 可请求 `store: false` 时继续请求，但不能把它描述成第三方绝不保留。

## 保留与清理

- Runtime：仅当前页内存中的 question/result；不写 localStorage/sessionStorage/IndexedDB；Start over/page unload/dispose 清除。
- Manager：每 Session 最多一个当前结果，TTL 见 (见 doc-id:context-qa-04-model-protocol)；不写正文磁盘、不提供 list/history endpoint。
- Key：Provider session 在 Job 后释放；不缓存 Prompt/Answer 正文。
- Read snapshot：Job 终态立即删除；清理失败记录安全错误，不记录内容。
- Codex：优先 ephemeral thread；否则隔离 runtime + thread delete + opaque cleanup journal；journal 不含问题、答案、路径或源码。
- 日志：只留 job/request/executor 的 opaque ID、状态、大小 bucket、耗时、错误码和清理结果。

“不做长期历史”不意味着错误时可以不留可诊断状态；诊断元数据可在当前 dev 进程有界保留，但正文与源码不得进入持久日志。

## 性能策略

- selection 编辑和模式切换不触发模型、文件 snapshot 或 Codex probe；
- capability 在用户打开 selector/诊断或首次提交时惰性获取，并按配置/版本摘要缓存；
- source candidate 构建和 snapshot 在 Node，按目标优先并支持 Abort；不在主线程扫描仓库；
- Key 同轮独立只读 calls 可并发，读取内容按 Job cache；
- Codex 只复制候选文件，不 clone 全仓或 Git；
- Answer 在服务端完整校验后一次提交 UI；可显示阶段但不流式把半答案插入 DOM；
- source chips/list 使用有界 DOM，长 code 延迟展开；
- Ask UI 保持独立 browser chunk，未启用时不加载。

协议限制的唯一数值源见 (见 doc-id:context-qa-04-model-protocol)。Q5 没有上调核心 Runtime 门禁：本机 Node 26 level-9 gzip 实测 `runtime-client.js` 48,894 B（门禁 48 KiB），独立 `runtime-contextual-ask-panel.js` 12,783 B（门禁 14 KiB）；production leakage 证明未启用/生产构建不携带 Ask UI/endpoint，40,000 字答案 jsdom 渲染断言低于 250 ms。Node snapshot、首事件和总 Job 的发布级跨平台基线仍由 Q7 完成，不能用本机数值替代发布矩阵。

## 可观测性

本地结构化指标只记录：

```text
ask.job.created / terminal
ask.context.authorized_files_bucket / bytes_bucket / truncated
ask.executor.kind / capability_state
ask.provider.first_event_ms / total_ms
ask.codex.thread_start_ms / first_item_ms / cleanup_ms
ask.answer.blocks / sources / characters_bucket
ask.cancel.latency_ms
ask.error.code / stage
```

不记录 question、answer、source text、DOM、selector、路径、model raw response、reasoning、Key 或 auth。默认零遥测；如未来增加远程 telemetry，必须另立 opt-in ADR。

UI 展示真实阶段、executor/model label、读取文件数量、截断、耗时和稳定错误。不得把 token usage 缺失估成费用，不得展示 Codex raw reasoning 或 Provider chunk。

## 故障与降级

- Key 不可用：保留 Managed Codex（若独立 ready）；反之亦然。
- 全部不可用：Ask composer 可查看但提交禁用，Change/Prompt 不受影响。
- source snapshot 失败：不发远程请求。
- 输出/引用无效：丢弃答案，显示协议错误，不用自由文本降级。
- 取消超时：UI 进入取消中；Manager 最终清理，迟到 answer 丢弃。
- Codex cleanup warning：答案可在内存显示，但 executor 进入 degraded，下一 Job 前先完成 cleanup；若可能残留正文则 fail closed。
- Answer stale：仍可查看/copy/转 draft，但标记；打开引用和 Change 执行都重新授权。

任何降级都不能从 Ask 切到 Change、从 read-only 切到 workspace-write、从已选目标切到全仓，或从结构化结果切到猜 Markdown。

## 安全验收

- 对所有写 API、权限升级和 root 外读取进行主动攻击，业务仓库 hash/Git status 保持不变；
- secret corpus 在 Browser、Provider fake server、Codex投影、事件、错误、日志、result 和 cleanup journal 泄漏为零；
- symlink/hardlink、TOCTOU、Unicode/大小写、路径空格、超限和并发变化 fail closed；
- 两个 Session/tab 互相访问 Job 全部拒绝；
- Prompt injection 不能改变 tools/profile/source grant/result Schema；
- production bundle、HTML、endpoint 和进程中无 Ask/Provider/Codex 残留。
