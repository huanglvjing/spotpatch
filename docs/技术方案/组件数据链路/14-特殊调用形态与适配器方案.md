# 组件数据链路特殊调用形态与适配器方案

## 结论先行

这类能力不能用一个全局 `fetch` monkey patch 就宣称“百分百找到组件接口”。严谨实现必须同时区分：

1. **源码声明**：组件代码、Hook 或业务函数中存在接口调用。
2. **逻辑调用已调度**：例如 tRPC 的 `user.byId` 已进入 tRPC Link。
3. **浏览器传输已 dispatch**：`fetch`/XHR 已收到清洗后的浏览器 URL。
4. **上游代理目标**：Vite proxy、网关或 Service Worker 可能把浏览器 URL 改写到另一地址。
5. **后端已接收/成功/写库**：只有服务端 trace、日志或同仓服务端证据才能证明。

SpotPatch 只能把具有同一稳定 callsite、sourceVersion 和 invocation 证据的层级合并。缺少任何关键边时保持 `declared-not-observed`、`unassigned` 或 `unknown`，不能按 URL 相同、发生时间接近或 AI 猜测归属。

“百分比”也必须有分母：

- **准确率目标**：在已声明支持的语法、版本和宿主中，报告为 `proven` 的关联以零已知误归属为发布门槛。
- **覆盖率现状**：不是所有框架、传输和动态元编程都已支持；未支持项必须显式降级，不能纳入“已实现百分百”的口径。
- **后端事实**：纯前端插件无法证明反向代理后的最终服务、服务端成功或数据库落点。要达到这一层，必须另接服务端 OpenTelemetry/trace 或受信同仓分析。

## 本轮代码实际补齐的能力

| 场景 | 当前代码行为 | 证据强度 |
| --- | --- | --- |
| 组件函数体直接 `fetch` | render 创建独立 trigger token；请求 callsite 与 analyzer 的 render trigger 对齐 | 可静态证明；实际 dispatch 可精确升级 |
| render 调用自定义 Hook/本地函数后请求 | render token 经同步调用和现有 async 边界传播 | 支持范围内可精确升级 |
| `window.fetch`、`globalThis.fetch`、`self.fetch` | analyzer 校验全局符号后识别，不把普通对象的同名方法当 fetch | 静态证明；compiler/runtime 继续按稳定 request callsite 观测 |
| `onClick={() => fetch(...)}` | concise handler 由 `bindTrigger` 包裹，请求使用调用时 token；保留返回值、参数、`this` 和 Promise | 可归到具体 JSX trigger |
| React Query v3 positional queryFn | 识别 `react-query` 的 `useQuery/useInfiniteQuery/useMutation` 导入；queryFn 真执行时才建立 token | cache hit/`enabled:false` 不会误报 observed |
| TanStack Query object queryFn | 支持 `queryFn`/`mutationFn` 对象属性的直接函数或可解析函数引用 | 同上 |
| tRPC procedure 静态识别 | 支持常见 vanilla、classic React Query、TanStack Options 的 query/mutation/subscription 终结方法 | 显示逻辑 procedure、输入键和源码消费字段 |
| tRPC 实际逻辑调度 | 对直接字面量 `links: []` 的已识别 client，在开发态变换中前置零依赖 pass-through Link | 只记录 `op.path/op.type`，不记录 input/context/result |
| tRPC bound mutation | 能从 `mutation.mutate(...)`/`mutateAsync(...)` 回溯到 `useMutation` 或 `mutationOptions` 对应 procedure | 触发器、参数键和逻辑 dispatch 可闭环 |

共享的 Query/tRPC 模块名、factory 和 terminal 名称集中在 `packages/shared/src/model/data-flow-adapters.ts`；compiler 与 analyzer 使用同一清单，项目域名、接口名和 Store 名不进入产品代码。

## 直接在组件里 fetch

### 支持形态

```tsx
function Profile() {
  const request = fetch("/api/profile");
  return <ProfileView request={request} />;
}
```

analyzer 把组件函数本身作为 `render` 根。compiler 为每次组件调用创建新的 render invocation，直接请求通过同一 `componentSourceId + renderTriggerId + requestCallsiteId + sourceVersion` 观测。因此它不再只是“静态看到”，而能在真实 dispatch 时升级。

下面的同步自定义 Hook 也沿同一个 render token：

```tsx
function Profile() {
  const profile = useProfile();
  return <ProfileView profile={profile} />;
}

function useProfile() {
  return fetch("/api/profile");
}
```

### 必须明确的语义

- render 内发起副作用本身是 React 反模式；React 18 StrictMode 开发态可能重复执行 render，所以面板可能看到两个真实 dispatch。这不是 SpotPatch 去重后可以伪装成一次的请求。
- 一次 render 只证明“组件 render 触发了请求”，不证明某个按钮触发了它。
- module scope 的 `fetch` 在组件执行前发生，不能归给后来选中的组件；只能进入页面接口或保持未归属。
- `const f = fetch; f(url)`、动态 Proxy、`eval`、运行时替换的 client 尚无完整静态别名算法；仅有全局 recorder 时应显示 unassigned。
- `Response` body、stream、status 和 success 仍不读取；render 适配没有改变 dispatch-only 安全边界。

## React Query / TanStack Query

### 为什么要有专用 trigger

以下代码不能简单地把 `useQuery` 调用等同于网络请求：

```tsx
useQuery("payStatus", () => http.post("/user/payQuery", { orderId }), {
  enabled: payStatus,
  refetchInterval: 1500,
});
```

`enabled:false`、cache hit、去重、staleTime、取消、重试和窗口聚焦重拉都可能让“Hook 已执行”和“网络已 dispatch”不一致。正确模型是：

```text
组件声明 Query
  ├─ queryFn 未执行 -> declared-not-observed
  └─ queryFn 真执行
      └─ fetch/XHR 真 dispatch + exact callsite -> observed
```

### 当前支持

- `react-query@3` 的 `useQuery(key, queryFn, options)`、`useInfiniteQuery` 和 `useMutation` 常见位置参数。
- `@tanstack/react-query` 的 `{ queryFn }`、`{ mutationFn }` 直接对象写法。
- named import 及别名；符号必须来自已知 Query 模块，应用自己定义的 `useQuery` 不会命中。
- queryFn 为块体、concise arrow、唯一可解析的函数引用。
- 目标实仓 `ChargeModal` 的 `POST /user/payQuery` 已加入真实源码 oracle；报告保持 `declared-not-observed`，只有 queryFn 真调用才升级。

### 尚未承诺

- `useQueries` 的多 query 数组、动态 spread 配置、运行时生成 queryFn。
- QueryClient 的 `fetchQuery/prefetchQuery/ensureQueryData` 全矩阵。
- Query cache 内部内容、cache key 原始值和缓存数据 shape；默认不收集 value。
- Devtools 插件内部状态或 React Query 私有 API；适配不得依赖私有字段。
- background refetch 精确归到某个已卸载 DOM 实例；它可归到声明 callsite/组件类型，但不应伪造当前 DOM instance。

## tRPC 适配

### 两层模型不能合并成一个 URL

tRPC 11.x 官方文档明确说明，`httpBatchLink` 会把多个独立 operation 合并为一个 HTTP 请求；`httpBatchStreamLink` 仍批处理但流式返回。一次物理 HTTP 因此可能对应多个逻辑 procedure。classic `useQuery` 又继承 Query 的 `enabled` 等选项，Hook 调用也不代表已经发网。

所以 UI 必须分开显示：

```text
逻辑接口
  QUERY user.byId
  input keys: userId
  tRPC Link: observed / declared

物理传输
  GET|POST /api/trpc/user.byId,...?batch=1
  browser dispatch: observed
  batch members: unknown / proven list
```

不得把一个 batch URL 按时间拆给最近点击的按钮，也不得把 `queryOptions()` 的创建标成网络请求。

### 当前静态识别语法

- vanilla：`client.user.byId.query(input)`、`.mutate(input)`、`.subscribe(input)`。
- classic：`trpc.user.byId.useQuery(input)`、`useInfiniteQuery`、`useMutation`、`useSubscription`、Suspense 变体。
- TanStack Options：`trpc.user.byId.queryOptions(input)`、`mutationOptions()`、`subscriptionOptions()`。
- mutation/refetch binding：从 `mutation.mutate(input)`、`mutateAsync(input)`、`query.refetch()` 回溯唯一的 tRPC Hook/Options 初始化。
- root 必须能追溯到 `@trpc/*` 官方 factory 或类型实现；普通对象的 `.query()` 不会静态判为 tRPC。

展示字段：

- `kind = rpc`
- `method = QUERY | MUTATION | SUBSCRIPTION`
- `operation = router.procedure`
- input 只展示字段名、位置 `variable`、敏感标记和 `not-collected`
- output 只展示源码对返回结果实际消费的字段
- 后端 procedure 内部数据库、队列或第三方请求，除非同仓服务端 adapter 另行证明，否则仍为 unknown

### 当前运行时 Link

开发态 compiler 对以下直接配置前置 `dataFlowRuntime.createTrpcLink()`：

```ts
createTRPCClient({ links: [httpBatchLink(...)] });
trpc.createClient({ links: [httpBatchLink(...)] });
```

Link 是透明 pass-through：

- 原样把同一个 `op` 传给 `next`，原样返回下游 observable/result。
- 只读取有界的字符串 `op.path` 和枚举 `op.type`。
- 不读取、序列化或保存 `op.input`、context、headers、result、error 或 response。
- metadata 读取失败时放弃观测，不能影响业务链。
- procedure、callsite、sourceVersion、component/trigger invocation 全部一致才升级。

动态配置不会被猜测：

```ts
createTRPCClient({ links: createLinks() });
createTRPCClient(optionsFromRuntime);
```

这类代码生成 `DATA_FLOW_TRPC_LINK_CONFIG_UNSUPPORTED` 并在 Vite development 日志中去重提示，仍可做静态 procedure 报告和原始 fetch/XHR 页面观测，但不能宣称逻辑 dispatch 已被 tRPC adapter 捕获。该 compiler diagnostic 尚未进入组件报告 DTO；UI diagnostic 接线完成前不能写成“面板已提示”。

### tRPC 仍需完成的发布 Gate

- 安装真实 `@trpc/client` v10/v11、classic React Query 和 TanStack integration 的类型/运行时矩阵 fixture；当前是基于官方公开 Link 契约的结构测试，尚未宣称全部版本发布级兼容。
- `httpLink/httpBatchLink/httpBatchStreamLink/httpSubscriptionLink/wsLink/splitLink/retryLink` 的真实 host 测试。
- batching、maxItems 拆批、retry、abort、unsubscribe、stream、WebSocket reconnect 的非干扰测试。
- 对物理 transport 与多个 logical operation 建立“批组”协议；在证据不足时只并列展示，不一对一强绑。
- SSR、RSC、Server Action 和服务端 caller 不属于当前 Vite + React 18 浏览器 Beta。

官方依据：

- tRPC 11 HTTP Batch Link：<https://trpc.io/docs/client/links/httpBatchLink>
- tRPC 11 HTTP Batch Stream Link：<https://trpc.io/docs/client/links/httpBatchStreamLink>
- tRPC classic `useQuery`：<https://trpc.io/docs/client/react/useQuery>
- tRPC TanStack React Query：<https://trpc.io/docs/client/tanstack-react-query/setup>
- tRPC Logger Link 的 operation/direction 模型：<https://trpc.io/docs/client/links/loggerLink>

## 代理、网关与“实际接口域名”

浏览器看到 `/api/auth/session/query` 时，Vite 可能代理到 `https://api.example.test/auth/session/query`。fetch recorder 只能直接证明浏览器请求 URL，不能仅凭浏览器信息证明 proxy 后的最终 upstream。

UI 后续应显示三个独立字段：

| 层级 | 示例 | 证明来源 |
| --- | --- | --- |
| 源码 endpoint | `/auth/session/query` | AST/常量传播 |
| 浏览器 dispatch | `http://localhost:5173/api/auth/session/query` | fetch/XHR observation |
| 配置推导 upstream | `https://api.example.test/auth/session/query` | Vite proxy 的静态 target/rewrite |

只有静态字符串 `target` 和可确定 rewrite 才能标 `proven-from-config`。动态函数、按 header/tenant 决定的 target、Service Worker、浏览器扩展、CDN redirect 和后端网关二次转发均保持 unknown。AI 不得把配置推导改写成“后端已收到”。

## 组件、具体按钮与多实例

### 组件类型不等于具体 DOM 实例

当前 `componentSourceId` 标识源码组件类型。同一组件渲染十个实例时，它们共享源码 request callsite；如果没有稳定的实例证据，面板必须说明“该组件类型在本次会话的观测”，不能声称就是被点击的那一个实例。

### 具体按钮需要 trigger scope

一个组件可能同时包含：

- mount Query
- “短信登录”按钮
- “密码登录”按钮
- “刷新表格”按钮

组件报告可以列出全部接口，但“选中登录按钮”必须优先显示与该 JSX `onClick` trigger 精确匹配的依赖，并另设“组件全部依赖”视图。当前 concise/block/imported handler 已有稳定 trigger；仍需把选择目标的 JSX source marker 与 `selectedTriggerCallsiteId` 接入报告请求，未接入前不能对多按钮组件宣称按钮级百分百。

组件库内部 DOM、Portal、render props、HOC、virtualized row、Context 上游数据和 parent props 还需要独立 fixture。不能用按钮文字、className 或最近请求时间替代 trigger 证据。

## 参数、响应与数据存储特殊情况

| 类别 | 严谨处理 |
| --- | --- |
| URLSearchParams/URL mutation | 追踪可证明的 key；computed key 保持表达式/unknown，不收集 value |
| FormData | 只取静态 append/set key；File/blob/value 不读取 |
| Axios interceptor | 只有同仓可解析的 config def-use 才显示追加 header/query；运行时默认不读 headers/body |
| auth/cookie | 仅显示敏感键存在；Authorization、Cookie、token value 永不进入 DTO |
| GraphQL variables | 需专用 AST adapter；operation、selection set、variables 与 HTTP transport 分层 |
| tRPC input | procedure input keys；服务端 Zod schema仅在同仓、版本和 router symbol 可证明时补充 |
| streaming/blob/text | 不 clone/read body；源码消费字段可能 unknown |
| React state/Zustand | 已有 def-use 证明后显示 binding |
| Query/SWR/Apollo cache | 需要专用 cache adapter，不能写成 React state |
| Redux/RTK Query | 需要 action/endpoint/cache adapter |
| local/session storage | 只显示静态 key，不显示 value |
| IndexedDB/Cache API/cookie | 当前未实现；必须区分客户端持久化与后端数据库 |
| 后端数据库 | 前端源码不能证明；需要同仓服务端分析或 trace metadata |

## 其他传输与框架适配矩阵

| 场景 | 当前状态 | 正确后续方案 |
| --- | --- | --- |
| Axios methods/create | Beta 支持 | 补 callable `axios(config)`、interceptor 数据边 |
| 原生 XHR | runtime dispatch 支持，static 未归属 | 以实例 symbol 串联 `open/send`，不替换 constructor |
| `sendBeacon` | 未实现 | fire-and-forget transport adapter |
| EventSource/SSE | 未实现 | 记录连接 URL；事件 payload 默认不读 |
| WebSocket | 未实现 | 连接和 logical subscription 分层；不解析任意消息 |
| GraphQL fetch | 只会看到 HTTP | Apollo/urql/Relay/原生 document 专用 operation adapter |
| SWR | 未实现 | fetcher trigger + cache-hit/revalidate 语义 |
| RTK Query | 未实现 | endpoint definition、initiate action、cache binding adapter |
| OpenAPI generated client | 可能沿函数追到 fetch/Axios | 增加生成器 symbol/operation adapter，不按函数名猜 |
| gRPC-web/Connect/JSON-RPC | 未实现 | logical method 与 HTTP/stream transport 分层 |
| native form/navigation/resource | 不作为业务 API 默认收集 | 单独 opt-in 资源/导航视图 |
| Worker/Service Worker/iframe | 未实现 | 每 realm recorder + message provenance；跨域仍受浏览器权限限制 |
| Next/RSC/Server Action | 当前 Beta 不支持 | framework adapter + server sidecar，不复用浏览器结论 |
| Remix/React Router loader | 未实现 | route trigger 与组件消费边分开 |
| MSW/mock | fetch dispatch 可见 | 标注“浏览器 dispatch”，不能宣称真实后端收到 |

## 适配器组织规范

每个新增 adapter 必须提供同一能力描述，而不是在 analyzer、compiler、runtime 各写一组无法校验的字符串分支：

```text
shared adapter descriptor
  ├─ id / adapterVersion
  ├─ package names + supported version range
  ├─ syntax terminals / capability flags
  └─ privacy classification

analyzer adapter
  ├─ symbol proof
  ├─ logical operation + params + consumed fields
  └─ source evidence

compiler adapter
  ├─ trigger/request anchor
  ├─ semantic-preserving instrumentation
  └─ unsupported diagnostic

runtime adapter
  ├─ minimal dispatch metadata
  ├─ no-value policy
  └─ dispose / coexistence
```

当前先把跨层语法清单集中进 shared；当 adapter 数量超过本轮 Query/tRPC 两类时，应把 `request-extractor.ts` 和 `data-flow-instrumentation.ts` 中对应逻辑移动到 `adapters/` 子目录，并保留单一 registry。不得新建未接线 package、空配置或只返回“未配置”的死 UI。

版本策略：读取项目 lockfile/包解析结果，只有 adapter 声明的版本范围才能启用专用 runtime 变换；未知版本生成 diagnostic 并退回静态/原始 transport，不静默套用“最像”的旧规则。

## AI 辅助的可选边界

AI 可以做：

- 用自然语言解释已证明的调用链。
- 在 unresolved frontier 中建议下一批需检查的文件/symbol。
- 根据已有 evidence 对候选 adapter 排序。
- 生成“为什么目前只能 unknown”的可读说明。

AI 不能做：

- 把 URL 相似或时间邻近升级为组件归属。
- 编造未读取的请求/响应 value、后端字段或数据库表。
- 把 `declared-not-observed` 改成 observed。
- 自动执行接口、登录、 mutation 或修改业务数据。
- 未经预览上传源码、payload、headers、cookie 或用户数据。

AI 上下文必须只由已通过公共 Schema 和 collection limiter 的 DTO 生成，包含：reportId、baseline、completeness、component/trigger/request IDs、sanitized endpoint、参数键、consumed fields、binding、diagnostic、evidence 引用；不包含 raw source、raw values、Response、Fiber、函数引用和绝对路径。模型输出中的每条事实需引用现有 evidence ID，校验失败只能显示为“AI 建议/待验证”。

当前代码仍将 `aiAssistance` 保持 `disabled`：在上下文预览、用户显式同意、provider 数据边界、只读任务、引用校验和错误回退全部通过前，不暴露一个看似可用但会混淆事实与推断的开关。AI 是后续可选 Gate，不是 tRPC/Query 适配缺口的兜底。

## 每个 adapter 的发布门禁

1. **正例与负例**：同名普通对象、shadowed global、动态配置和错误版本不得误命中。
2. **语义不干扰**：返回值、Promise/observable identity、`this`、参数、abort、unsubscribe、retry 和 error 必须保持。
3. **生命周期**：mount、event、timer、cache hit、background refetch、unmount、HMR、route change 均有断言。
4. **并发归属**：共享 service、多个组件、多个 trigger、同组件多次 invocation 不串线。
5. **传输特性**：batch、stream、WebSocket/reconnect、proxy、mock 分别验收，不互相替代。
6. **隐私**：fixture 中放入 canary secret，所有 report、日志、错误和 AI context 均不得出现。
7. **预算**：transform、analyzer、runtime 条目/字节、gzip 和 report 上限继续通过，不靠提高预算过关。
8. **真实项目 oracle**：至少一个真实仓正例和一个不会误归属的邻近负例。
9. **版本矩阵**：实际安装并运行支持范围内的最低/最高主版本；仅靠类型或 mock 不算发布级兼容。
10. **降级可见**：unsupported/partial/unassigned/unknown 均有诊断与 UI 文案。

## 实施优先级复核

### P0：准确性闭环

- 已完成：render fetch token、concise handler、Query trigger、tRPC logical Link 和共同语法常量。
- 下一步：selected trigger 接入报告、同组件多实例范围文案、browser URL 与 proxy upstream 分层。
- 下一步：XHR 静态归属、fetch alias、Axios callable/interceptor。

### P1：数据获取生态

- tRPC 真实 v10/v11 host 矩阵与 batch group。
