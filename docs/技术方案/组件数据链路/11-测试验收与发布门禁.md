# 组件数据链路测试、验收与发布门禁

测试分母来自实仓审计 (见 doc-id:data-flow-02-repository-audit)，覆盖归属、观测、UI、AI 和安全性能 (见 doc-id:data-flow-04-static-attribution)、(见 doc-id:data-flow-05-runtime-observation)、(见 doc-id:data-flow-08-ui-interaction)、(见 doc-id:data-flow-09-ai-assistance)、(见 doc-id:data-flow-10-security-performance)，并作为既有全仓测试门禁 (见 doc-id:12-testing-acceptance) 的 proposed 增量。

## “百分百”的正式定义

该功能采用**准确率优先、覆盖率显式、未知不算错误也不算成功**的三组指标：

```text
proven association precision
  = 正确的 proven direct/transitive/upstream 关系数
    / 所有被产品声明为 proven 的关系数

supported callsite recall
  = 正确识别的锁定支持请求调用点数
    / fixture manifest 中 expected=supported 的调用点数

unsupported false-positive rate
  = 被错误声明为 proven/supported 的不支持样本数
    / 所有 expected=unsupported/unknown 样本数
```

硬门禁：

- proven association precision = **100%**。
- supported callsite recall = **100%**。
- unsupported false-positive rate = **0%**。
- 敏感值泄漏 = **0**。

unknown/unassigned 不进入 precision 分子或分母，但必须单独报告数量和原因，不能用大量 unknown 隐藏覆盖率。每份 CI 报告同时输出 supported、proven、possible、unknown、unassigned、truncated、unsupported 的数量。

## 分母治理

每个 fixture 使用版本化 manifest：

```ts
interface DataFlowOracleEntry {
  readonly id: string;
  readonly sourceAnchor: OracleSourceAnchor;
  readonly expectedCapability: "supported" | "unsupported" | "runtime-only";
  readonly request?: OracleRequest;
  readonly origin?: OracleOrigin;
  readonly suppliedBindings?: readonly OracleBinding[];
  readonly sensitivePaths?: readonly string[];
  readonly expectedDiagnostics?: readonly string[];
}
```

- manifest 与 fixture 同 commit，人工复核关键链路。
- 生成器只能发现候选，不能用 analyzer 自己的输出自动生成 expected，否则形成自证。
- 可移植 fixture manifest 记录 fixture version、dependency lock hash、generator/analyzer/adapter version。
- 新语法出现时必须显式归入 supported/runtime-only/unsupported；不得静默排除文件或调用点。
- 分母变化必须在 PR 展示新增、删除、分类变化和理由。

## 测试金字塔

### 1. Shared Schema 与纯函数

- 所有合法/非法 enum、未知字段、递归深度、数组/字符串/字节边界。
- evidence 正反向引用一致性、重复 ID、缺失 ID、循环/冲突。
- association 状态机：observed 不自动变 proven；AI 不可升级；stale 不为 current。
- URL sanitizer：userinfo、query、fragment、signed URL、JWT/base64/高熵/Unicode/畸形 URL。
- redaction 词形、大小写、分隔符、嵌套 path 和高熵 key。
- shape merger/truncation 为纯函数、输入不变、输出 deterministic。
- merger 对同 URL 不同 callsite、相同 callsite 不同 sourceVersion、不同 route epoch 不串线。
- property-based/fuzz 覆盖任意字符串和有界 JSON；永不抛到宿主。

### 2. Compiler transform

正例：

- `.js/.jsx/.ts/.tsx`、JSX classic/automatic dev transform。
- function/arrow/class component、nested/local function、async/await。
- direct fetch、Axios instance/method、alias、re-export、barrel。
- click、form submit/AntD onFinish、effect、timer、Promise callback。
- request expression 在 variable、return、conditional 和 try/catch/finally 中。

语义负例：

- 同名 fetch/get/post 但 binding 不是平台/Axios。
- dynamic property、eval、Proxy、未知 high-order wrapper。
- generator/constructor/decorator 等未进入支持契约的形态。
- node_modules、保护文件、未授权 root、虚拟模块。

每个变换同时断言：

- source map 回到原始 callsite。
- 表达式只执行一次。
- `this`、`arguments`、参数、return/reject、function/handler identity 符合契约。
- 无命名冲突；重复 transform/HMR 不重复 instrumentation。
- dataFlow disabled 和 production 返回无增量。

### 3. Analyzer 与 Adapter contract

- import/export/re-export/alias/package exports、循环依赖、dynamic import。
- 内容 hash cache、反向依赖失效、registry/source epoch。
- 图深度/模块/callsite/timeout/字节截断，frontier 完整。
- React state/props、parent-child prop、Zustand、TanStack Query 锁定版本。
- project Axios binding；同名非 Axios negative fixtures。
- direct/transitive/upstream/possible/unknown 的 golden report。
- adapter exception/冲突不影响其他 adapter，输出稳定 diagnostic。
- adapter version 超出范围时 unavailable，不乐观支持。

每个 adapter 目录必须具备 positive、negative、version-boundary、conflict、budget 五类 fixture；没有这些 fixture 不得注册为 supported。

### 4. Recorder 单元与差分测试

fetch：

- 字符串/URL/Request input、GET/POST、同步抛错、resolve/reject。
- Promise identity、微任务顺序、`unhandledrejection`、bodyUsed、Request clone 行为。
- AbortController pre-abort/mid-flight、redirect、credentials/cache/mode/signal 不变化。
- streaming response、Blob/ArrayBuffer/FormData 不被读取。

XHR：

- open/send/setRequestHeader、sync/async、abort/timeout/network error。
- readyState/event 顺序、listener `this`、status/statusText/responseURL/responseType。
- JSON/text/blob/arraybuffer；禁止额外读 responseText/body。

组合：

- SpotPatch 在 MSW/Sentry 风格 wrapper 前后安装。
- Axios fetch/XHR adapter、interceptor、重试。
- HMR 多次、两个 Runtime bundle、安装/卸载/第三方后装 wrapper。
- recorder 内部抛错时业务 trace 与未 instrumented fixture 一致。

差分 oracle 对比返回引用、事件序列、异常、网络请求数、headers/body hash、abort 和应用状态；除额外 SpotPatch 内存 DTO 外必须相同。

### 5. Invocation 并发与异步

- 两组件同 endpoint、同组件两次并发、同 callsite 不同 invocation。
- `await` 前后、多层项目函数、Store action、callback、timer、Promise continuation。
- StrictMode effect 重跑、debounce/throttle、retry、polling。
- click 同时触发 effect/background 请求。
- token 缺失/过期/跨 route/source/session 时 unassigned/stale。
- 第三方延迟调用不在支持契约时不得用时间补归属。

测试必须主动构造最容易串线的交错调度，重复随机调度并保留失败 seed。

### 6. 数据来源

- response path → useState → JSX。
- response → Zustand set → selector → Table。
- parent state → child prop → nested Table `dataSource`。
- TanStack Query network、cache hit、select transform。
- destructuring、optional chain、map/filter/spread、mutation、unknown function escape。
- WeakMap 同引用补强；clone/spread 后无静态边则断链。
- local/sessionStorage/IndexedDB 只识别 key/db/store 和操作，不读值。
- 同仓 handler + ORM positive；外部后端和无 schema 为 persistence unknown。

### 7. 协议与安全

- Origin/token/Content-Type/method/JSON/size/unknown field 全部复用并扩展现有安全 fixture。
- 伪造/过期 fileId、sourceVersion、root/path/glob/adapter 注入、symlink/root escape。
- report 超限返回完整 truncated envelope，不返回半截或 stack。
- 请求/响应/错误/日志/DOM/selection session 不含绝对路径和 secret corpus。
- hostile Proxy/getter/toJSON/iterator 在 shape 流程中调用次数为 0。
- malformed/恶意 adapter contribution 被 Schema 拒绝且不污染 cache。

### 8. UI 与无障碍 E2E

| 场景 | 断言 |
| --- | --- |
| Tab/lazy load | 修改说明功能不变；首次打开才加载；关闭功能无 chunk |
| 直接按钮 | direct/transitive 请求、参数和证据准确 |
| AntD 登录 | submit → onFinish → Store → Axios；辅助/follow-up 分开 |
| Table direct | origin 和 data-fed-by 均为当前组件 |
| Table Store | 经 Zustand，显示 Store field |
| Table parent | selected child 显示 upstream，不标 direct |
| 页面接口 | observed/declared/unassigned/background/resource 分组准确 |
| observe next | 选择不提交；用户二次操作才执行；超时/取消可恢复 |
| 参数详情 | 分组、来源、条件、敏感策略，无 value |
| response | consumed/declared/observed 三块不混淆 |
| 状态矩阵 | loading/empty/stale/truncated/conflict/unsupported/disabled 全覆盖 |
| 双语 | 所有固定文案、aria label、状态同步；项目文本不翻译 |
| 响应式 | 560px 与 <520px；操作和详情不越视口 |
| 键盘/读屏 | tab、列表、字段树、详情返回、焦点恢复、aria-live |
| HMR/route | 旧记录 stale；筛选/目标不串位 |

不使用固定 sleep；等待真实可观察状态。截图只验证视觉，语义和数据必须用 DOM/协议断言。

### 9. AI contract

- context Schema、二次清洗、预算、source freshness、evidence 引用完整性。
- UI 预览与 fake provider 收到的 normalized payload 相同。
- prompt injection corpus 不能启用额外工具或改变系统规则。
- Explain 无源码工具；Assist Find 只有 read/search/list/evidence。
- write/check/process/network 工具调用一律稳定拒绝。
- 假 evidence、无 evidence fact、未知字段、超长输出、HTML/script 均安全降级。
- AI 结果不改变 report、计数、badge、association 或业务文件。
- AI disabled/not configured/refused/timeout/cancel 保持确定性页面完整。

### 10. 性能、内存和生产

- cold/warm analyzer 基准分别验证预算，不以 cache 伪装 cold。
- 1/10/100 observation 下 recorder 和 UI 基准。
- HMR/navigation/open-close 100 次后的 listener、wrapper、timer、WeakMap 可达性与 heap trend。
- Inspector lazy chunk、prelude、核心 Runtime 分别测 gzip。
- dataFlow false 与 production build 扫描 marker/ID/endpoint/message/adapter/prelude/chunk 零残留。
- Node analyzer/runtime/browser package 依赖扫描阻止跨边界导入。

## 可移植项目 oracle 门禁

required CI 只使用仓库内声明的中性 fixture，或由测试在操作系统临时目录中创建的 fixture：

| 指标 | Required |
| --- | ---: |
| fixture 中请求 callsite | 100% 已分类且有稳定 ID |
| 已执行支持 fetch/XHR capture | 100% |
| proven 组件归属 precision | 100% |
| proven 错误归属 | 0 |
| executed method/安全 URL 表示 | 100%；非敏感 origin/path 精确，敏感片段按策略隐藏 |
| 支持形式参数 key/shape | 100% |
| 支持的 response consumed fields | 100% oracle 正确 |
| 表格 request-origin/data-fed-by | 100% oracle 正确 |
| secret canary 泄漏 | 0 |

必须单独断言 Store 间接调用、条件 endpoint、effect/timer 轮询、表格 state destination 和 Query declared/observed 分离。fixture 不得包含第三方品牌、真实域名、外部仓库路径或真实业务数据。

外部项目只能进入独立的私有评估流程，不能成为 required CI 的文件系统前置条件。测试不得以“本机目录存在时才运行”的 `skipIf` 方式伪装跨平台覆盖，也不得读取真实 `.env*` 或发真实 API 请求。网络由浏览器 mock/fake server 提供，敏感值使用专用 canary。

## 不得伪造通过

- 不得通过把失败样本改成 unsupported 来保持 100%，除非支持矩阵和变更理由先经评审。
- 不得删除 unknown/unassigned/truncated 统计。
- 不得让 analyzer 输出自动生成同一 analyzer 的 expected oracle。
- 不得只测一个 `onClick → fetch` demo 代表目标项目。
- 不得以 Chrome DevTools 中“看起来正确”代替自动 assertion。
- 不得用真实 token、用户数据或生产接口做 required CI。
- 不得因性能失败直接提高预算或排除慢样本。

## Gate

| Gate | 必须通过 | 失败动作 |
| --- | --- | --- |
| D0 文档 | 语义、SSOT、矩阵、预算、测试分母评审 | 不编码 |
| D1 POC | 复合组件/submit、invocation、并发、Promise/fetch 非干扰 | 重设方案或缩小支持范围 |
| D2 静态内核 | compiler/analyzer/adapter contract + manifest | 不接 UI |
| D3 Runtime | prelude/recorder/result tap/生命周期/泄漏 | 只保留静态能力或停止 Beta |
| D4 产品闭环 | Schema/endpoint/UI/双语/无障碍 | 不进真实项目 Beta |
| D5 AI | 只读工具、context/output/同意/泄漏 | AI 保持关闭，不阻断核心 Beta |
| D6 发布 | 实仓、兼容、性能、生产、package validate | 不发布支持声明 |
| D7 Next | Next 独立 POC/矩阵 | Vite 不受影响；Next 保持 0.x 公共预览已验证边界，不升级为正式支持 |

## Required commands

最终应增加聚合脚本而不替换现有门禁，例如：

```text
pnpm format:check
pnpm lint
pnpm typecheck
pnpm test:unit
pnpm test:data-flow
pnpm test:data-flow:real-host
pnpm test:e2e:chromium
pnpm test:performance
pnpm test:production-leakage
pnpm package:validate
```

新增脚本复用已有测试 runner/setup，不在 CI workflow 复制 pnpm/Node/浏览器版本。D0/D1 期间脚本尚不存在，文档不得声称已经通过。

## PR 增量清单

每个 data-flow PR 除现有清单外必须回答：

- 是否新增采集值、sourceRoots、adapter、transport 或 AI 内容？
- 是否改变 supported 分母、证据升级规则或 unknown 行为？
- 是否改变业务 Promise/function/event/network 可观察语义？
- 是否新增/保留临时 flag、兼容分支、旧实现或未引用 export？退出 Gate 是什么？
- 是否新增 magic number、第三方路径/URL/变量名或双语硬编码？
- 是否为 positive/negative/concurrency/security/production 同时增加测试？
- 是否更新 baseline manifest、性能 artifact、Changeset 和活动规范？
