# 当前项目接入

## 目标项目实际约束

- React 18.3.1
- Vite 6.x，当前本地启动解析为 6.4.3
- `@vitejs/plugin-react-swc`
- React Router 懒加载
- Ant Design 5
- Tailwind 3
- Framer Motion
- SVGR
- StrictMode
- Vite `host: true`、`cors: true`
- pnpm 10.20.0
- 可用验证脚本：`pnpm lint`、`pnpm build`；当前未定义独立 `typecheck` 或测试脚本

正式支持边界仍以产品支持矩阵为准 (见 doc-id:01-product-boundary)；本节只描述当前目标项目。

## 接入顺序

推荐使用 `pnpm dlx @spotpatch/vite@latest setup` 一次完成最新版安装/升级与配置初始化。需要拆分执行时，先运行 `pnpm add -D @spotpatch/vite@latest`，再运行 `pnpm exec spotpatch-vite init`；显式 `@latest` 用于避免已有依赖范围和锁文件继续复用旧版本。初始化器支持静态配置对象和唯一顶层对象返回的 `defineConfig` 回调，对多分支返回、动态插件集合等无法确定安全改写的结构必须无写入失败，再由用户手动接入。

```tsx
plugins: [
  spotPatch(),
  react(),
  compressionBuildOnly,
  svgr(),
  nodePolyfills(),
  viteStaticCopy(),
]
```

保存配置后照常执行 `pnpm dev`。浏览器右下角出现 SpotPatch 后即可选择元素；快捷键是 `Mod+Shift+S`（macOS 上为 `⌘⇧S`）。

公共选项的定义和默认值见公共 API (见 doc-id:03-public-api-models)，插件顺序的通用要求见 Vite 插件规范 (见 doc-id:04-vite-plugin)。

目标项目采用公共安全默认值，不在 Vite 配置复制 `editor`、`redact`、`allowLan`、`locale` 或 `maxTargets`。编辑器默认按 `auto` 识别当前可用的 Cursor/VS Code；只有自动识别与实际工作流不一致时才显式配置 `editor: "cursor"` 或 `editor: "vscode"`。工具语言按 `auto` 初始化，主要操作者可在工作台标题栏即时切换中文且草稿不丢失；需要固定语言或容量时再显式覆盖相应字段。值域和含义只由公共模型定义 (见 doc-id:03-public-api-models)。

依赖安装需要代理时，代理地址由操作者在当前 shell 提供；代理只作用于安装命令，不得把个人代理地址写入 Vite 配置、项目脚本或仓库文档：

```bash
: "${https_proxy:?Set https_proxy in the current shell}"
: "${http_proxy:?Set http_proxy in the current shell}"
: "${all_proxy:?Set all_proxy in the current shell}"
pnpm install
```

## AI Agent 接入

目标项目默认使用 `spotPatch()` + 被 Git 忽略的 `.env.local` 约定式接入，不在 Vite 配置复制 Provider 树。必要变量名、默认协议和认证方式只由 Provider 规范定义 (见 doc-id:17-model-provider-credentials)；本文件不复制 URL、Key、模型或 limits 的事实。接入时必须满足：

1. Key 放在被 `*.local` 规则忽略的本地 env 文件或启动 shell 中，并使用不以 `VITE_` 开头的环境变量名；仓库、截图、Prompt 和 Vite client env 中都不能出现真实 Key。
2. URL、模型和 Key 三个必要值必须完整；当前中转站需要的协议与认证使用约定式可选变量覆盖，不在源码硬编码供应商密钥；用无源码 capability probe 验证中转站的真实工具调用能力 (见 doc-id:17-model-provider-credentials)。
3. 默认保持 `review` 且不猜测 checks。扩大到真实业务修改前，应通过简洁配置的 `execution` 登记该项目真实存在的 `pnpm lint` 与 `pnpm build`；只有 required check 完整时才可另行评估 auto。
4. 因目标项目使用 `host: true`、`cors: true`，必须从 loopback 与真实局域网地址分别验证 token、Origin、Host 和 Agent endpoint 拒绝路径。
5. 工作区干净时直接运行；存在 staged、unstaged 或有界普通 untracked 修改时，必须先核对健康检查的分类计数并显式同意纳入隔离基线。Agent 不得在业务仓库 stash、reset、checkout、commit 或改变 index；冲突、进行中的 Git 操作、不支持的未跟踪项和规模超限必须先由用户处理。
6. 首个 smoke task 只修改一个可回滚的 UI fixture，完整观察 capability、worktree、Diff、检查、Apply、HMR 和 Revert，再扩大到真实业务元素。

本地修改与 Git 门禁见 Agent 执行规范 (见 doc-id:16-ai-agent-execution)，浏览器与文件安全边界见本地协议 (见 doc-id:09-local-protocol-security)，验收矩阵见测试规范 (见 doc-id:12-testing-acceptance)。

## 特别验证

1. SpotPatch `pre` transform 不处理 `.svg?react` 虚拟转换结果。
2. 懒加载路由模块进入页面时才注册 source ID，选择前一定已注册。
3. AntD Portal 的 DOM 虽在 `body` 下，picker 仍可命中；React Adapter 用 Fiber 关系回溯。
4. Tailwind 规则可能来自统一生成 CSS，Prompt 优先保留 class 和 computed style。
5. 登录页所有 input value、token、callback URL 敏感参数必须清洗。
6. StrictMode 不得产生双工具栏和重复事件。
7. 因原配置 `host: true`，安全测试必须使用真实局域网 Host 发起拒绝用例。
8. AI 环境完全不存在时，现有选择/定位/Prompt/编辑器流程均不退化；环境只配置一部分或 Key 缺失时，Vite 必须 fail-fast 并列出缺少的变量名。capability 失败和 provider 拒绝同意不得触发远程源码传输或本地修改。
9. Agent Job 的检查命令与 package scripts 一致，且检查子进程环境不含 provider Key。
10. Apply 后 React Router、Tailwind、AntD Portal 与 StrictMode 场景的 HMR 行为正常；旧选中节点不被继续复用。
11. 分别选择普通 JSX、Tailwind 元素和 AntD Portal 元素，为每项填写不同说明；切换活动项和中英文后草稿不串位，Prompt/Agent 请求保持相同顺序与逐项语义。
12. 在实际安装的 Cursor 与 VS Code 环境分别验证目标行快捷入口和底部入口可精确打开行列；至少同时打开两个不同项目窗口，确认源码进入拥有目标文件的既有窗口而非最后活跃的无关窗口。命令不可用时显示失败，Agent 审阅和 Apply 后入口仍可用。
13. 标题栏 GitHub 入口只指向官方仓库，不带追踪参数，且不影响语言切换、关闭和键盘焦点顺序。
14. 分别以 clean、staged+unstaged 同文件、untracked、无关文件并发变化和 Agent 触及文件并发变化验证健康检查、纳入同意、Apply 与 Revert；前三者保留用户原内容和 index，无关变化不阻断，触及路径变化必须拒绝覆盖。

上述场景分别遵循 Runtime (见 doc-id:05-runtime-lifecycle)、源码解析 (见 doc-id:06-source-resolution)、DOM/CSS 采集 (见 doc-id:07-dom-css-collection) 和安全规范 (见 doc-id:09-local-protocol-security)，测试入口统一见测试与验收规范 (见 doc-id:12-testing-acceptance)。

最初的 v1 接入不直接修改该仓库的 198 个 TSX/JSX 文件，只修改一处 Vite 配置并安装 devDependency。所有源码标记均由开发服务器内存转换产生。v1.1 Agent 只有在用户明确发起 Job 后，才可以按审阅通过的 Diff 修改与该任务相关的业务文件；两阶段边界不得混淆。
