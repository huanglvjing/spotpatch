# 组件数据链路数据接口页面与交互规范

本页把需求、数据语义和候选 DTO 投影为界面 (见 doc-id:data-flow-01-requirements)、(见 doc-id:data-flow-06-data-provenance)、(见 doc-id:data-flow-07-model-protocol-config)，不重定义它们；AI 操作遵守 (见 doc-id:data-flow-09-ai-assistance)，基础视觉与工作台行为继续遵守 (见 doc-id:10-ui-diagnostics)。

## 产品位置

Inspector 继续存在于现有 Shadow DOM ContextWorkbench 内，不创建第二个悬浮工具。工作台顶层使用四个语义 tab：

```text
[修改说明] [数据链路] [页面接口] [诊断]
```

- **修改说明**：现有目标说明、Prompt、Agent 主流程，不因新功能降级。
- **数据链路**：当前活动目标的请求、数据来源和数据位置。
- **页面接口**：当前 route/page 的所有业务接口，不要求先选目标。
- **诊断**：现有能力状态，加 data-flow capability/预算/降级原因。

Tab 切换不丢失目标、说明、筛选、滚动和 observation；只有首次打开数据链路/页面接口时才加载 lazy UI 和静态报告。功能关闭时不显示前两个新增 tab，也不加载 chunk。

## 信息层级

```text
工作台标题 / 当前页面
  ├─ Tab
  ├─ 当前目标身份或页面 route
  ├─ 能力/新鲜度/范围摘要
  ├─ 筛选与主操作
  ├─ 内容列表
  │   └─ 请求卡片 / 数据位置卡片
  └─ 详情抽屉
      ├─ 概览
      ├─ 参数
      ├─ 响应与使用字段
      ├─ 数据来源/位置
      ├─ 调用与触发
      └─ 证据/诊断
```

首屏回答“是什么、是否执行、为什么与当前组件有关”。原始证据、完整调用链和所有 observation 进入详情，不在首屏堆满路径。

## 数据链路页

### Header

```text
ResultsTable · Table                          源码已解析
2 个已确认依赖 · 1 个上游来源 · 当前页已观测 1 个
src/features/models/ResultsTable.tsx:42

[观测下一次操作] [刷新静态分析] [AI 解释链路]
```

- 组件名、元素角色、相对源码位置和 source freshness 必须可见。
- 数量只统计 proven direct/transitive/upstream，不把 possible/unassigned 混入。
- “观测下一次操作”只在 runtime observation available 时启用；不会自动 click。
- “AI 解释链路”只在显式开启且上下文可预览时显示。

### 分组顺序

1. **本组件发起**：direct。
2. **经 Hook / Store / API Client 发起**：transitive。
3. **上游提供的数据**：data-fed-by/upstream。
4. **源码声明，当前未执行**：declared-not-observed。
5. **数据位置**：local state、cache、Store、browser storage、server persistence。
6. **候选与限制**：possible/unknown；默认折叠，不计入确认数。

没有某一分组时不渲染空容器。没有确认依赖但有 upstream 时，空态是“本组件未发起请求；显示数据由上游提供”。

### 请求卡片

```text
GET  /models/:id                          已观测 · 上游提供
ModelPanel → useEffect → http.get          200 · 84 ms · 1 次

提供字段  data.channels → props.tableData → Table.dataSource
参数      path.id ← route params.id       string
数据位置  Parent state: modelInfo

[查看详情] [打开请求源码] [打开数据绑定]
```

卡片规则：

- method 使用固定宽度技术标签；未知 method 显式显示 `UNKNOWN`。
- endpoint 主行优先 template，observed URL 作为次级；query value 默认隐藏。
- 状态 badge 用“已观测 / 源码声明 / 上游提供 / 尚未归属”等文字，不只靠颜色。
- status/duration 只在 observation 有值时显示；不以空值补 `200` 或 `0ms`。
- polling 卡片显示次数、最近状态与频率；可展开单次记录。
- dynamic/conditional endpoint 显示 expression/分支，不截成似是而非的静态 path。

### 数据位置卡片

```text
Zustand Store · user                         已证明
读取  user / redirectUrl
写入  login() / smsLogin()
持久化  localStorage: user（token 已排除）

Server persistence                          未知
当前授权仓库没有后端 handler 或 schema；未猜测数据库表
```

“未知”必须附原因和下一步，不渲染成红色错误。敏感 key 可以显示名称，value 永远不出现。

## 页面接口页

### Header 与范围

```text
/login · 当前路由
已观测 4 · 已归属 3 · 未归属 1 · 声明未执行 5
[当前路由 ▾] [全部业务请求] [搜索 method / endpoint / component]
```

范围切换：当前 route epoch（默认）、本次 document、当前选中组件。资源请求通过独立“资源”筛选查看，不能默认混入业务接口计数。

### 分组

- 已观测并已归属。
- 已观测但未归属。
- 源码声明但本次未执行。
- 后台/轮询。
- 可选资源请求。

列表默认按“最近活动”排序；可切换源码顺序、method、endpoint、组件、耗时。搜索只在内存中匹配已清洗文本，不把查询发给宿主或 provider。

### 行信息

| 列/区域 | 内容 |
| --- | --- |
| 请求 | method + template/sanitized endpoint |
| 归属 | component/route/background/unassigned |
| 触发 | submit/click/effect/timer/unknown |
| 执行 | status、最近耗时、次数、最后时间（相对） |
| 数据 | 请求参数数、响应 shape/consumed fields 摘要 |
| 状态 | observed/declared/stale/truncated/conflict |

窄视口改成卡片，不做横向不可读表格；主要 endpoint 和状态保持在首屏。

## 请求详情抽屉

详情是同一工作台内的可返回视图，不在宿主页面再弹一个 modal。标题固定显示 method、template、execution/proof/association 三个正交状态。

### 概览

- 当前 mode 声明 URL 与 observed sanitized URL 分开显示。
- transport、operation、方向、状态、耗时、次数、route/source freshness。
- “为何相关”：一句系统生成摘要，引用 evidence ID，不由 AI 生成。

### 参数

按 path → query → body/form/variables → header/cookie 排序：

| 路径 | 类型/shape | 来源 | 条件 | 值策略 |
| --- | --- | --- | --- | --- |
| `body.phone` | `string` | Form `values.phone` | required | 已隐藏 |
| `body.callback_url` | `string` | URL query `redirect` | conditional | 已隐藏 |
| `header.x-token` | `string` | dev auth | development | 永不采集 |

不存在参数时显示“此调用点未声明参数”，而不是空白。未知 object 只显示 `object (not inspected)`。

### 响应与使用字段

三个区块不可混合：

- **代码实际使用**：例如 `data.open_id`、`data.user`。
- **类型/契约声明**：若有，注明来源文件/Schema。
- **本次安全结构**：若支持，显示字段树、type、optional/null 和截断；否则说明原因。

字段树默认展开两层，键盘可操作。敏感字段显示锁图标与“值未采集”，不能用星号暗示系统曾保存原值。

### 数据来源与位置

用纵向证据链而不是可拖拽大图：

```text
GET /models/:id
  ↓ result.data
Parent useState: modelInfo
  ↓ modelInfo.channels
Child prop: rows
  ↓
Table.dataSource
```

每个节点可打开源码；转换节点标记 map/filter/spread；断链位置显示“此处之后无法证明”。首版不做自由布局节点图，避免空间、交互和可访问性复杂度。

### 调用与触发

显示 `Button submit → Form.onFinish → authenticate → http.post`，区分 primary/parallel/follow-up/background。每条边显示 source location、adapter 和 proof；URL/时间相关性若出现只在诊断区标候选。

### 证据与诊断

显示 evidence ID、kind、相对位置、sourceVersion、adapter、truncation frontier、unsupported reason。普通用户无需理解 AST，但必须能复制一份**已清洗诊断摘要**；不得复制原始 stack/body。

## 中性 fixture 验收原型

以下是对审计案例的 UI 期望，不是第二份接口事实定义；接口证据以 (见 doc-id:data-flow-02-repository-audit) 为准。

### 选中“登录”按钮

```text
Login · 提交按钮                            源码已解析
1 个主请求 · 1 个条件辅助请求 · 2 个成功后续分支

主请求
POST /auth/login                            源码声明
Button submit → Form.onFinish → authenticate → http.post
body  account, password, state?
值    默认未采集；password/token 永不采集

条件辅助
POST /auth/challenge                        challengeRequired=true

成功后续（不计为主登录接口）
GET /account/profile                        普通成功路径
GET /auth/continue                          授权续流路径
```

`POST /auth/session/query` 不出现在该按钮的确认依赖中。它可以出现在“页面接口 → 后台/轮询”，归属 `SessionStatus mount → timer`；只有用户选中会话状态组件时才进入其数据链路。

### 选中 ResultsTable 表格

```text
ResultsTable · Table                        上游提供
当前组件未发起请求

GET /models/:id                             ModelPanel 已观测
  response.data
    → Parent state: modelInfo
    → modelInfo.rows
    → props.rows
    → Table.dataSource

[打开上游组件 ModelPanel] [打开 Table 数据绑定]
```

这个状态不能简化为“ResultsTable 调用了 `/models/:id`”；UI 始终保留 `origin=ModelPanel`、`consumer=ResultsTable`。

## 状态和空态矩阵

| 状态 | 主文案 | 操作 |
| --- | --- | --- |
| lazy loading | 正在加载数据链路模块 | Cancel/关闭保持可用 |
| analyzing | 正在分析已授权源码 | Cancel；显示已扫描数量 |
| no-declared | 当前分析范围未发现数据依赖 | 查看页面接口/诊断 |
| declared-only | 源码中存在，当前页面尚未观测执行 | 观测下一次操作 |
| observed-unassigned | 已看到请求，但没有证据归到当前组件 | 查看页面接口/AI 辅助 |
| upstream-only | 当前组件未发请求；数据由上游提供 | 打开上游组件 |
| source unavailable | 无法授权到精确源码 | 打开诊断/重新选择 |
| runtime unavailable | 静态结果可用；运行时观测不可用 | 查看原因 |
| truncated | 报告达到安全/性能上限 | 查看 frontier；不提供“无限扩大” |
| conflict | 静态与运行时证据冲突 | 显示双方证据，不选胜者 |
| stale | 页面/HMR 后源码已变化 | 重新分析 |
| unsupported | 当前语法/框架不在支持矩阵 | 查看支持范围/AI 辅助 |
| capability disabled | 功能未启用 | 显示安全的配置指引 |

网络/分析错误不替换整个工作台；已有静态或 observation 事实继续可看，并注明部分不可用。

## 观测模式交互

- 按钮文案是“观测下一次操作”，不是“自动调用接口”。
- 进入后工作台收起为不遮挡的状态条：`请在页面执行一次操作 · {剩余时间} [取消]`。
- 用户真正操作后，只有 invocation token 匹配的请求高亮；其他请求仍进入页面接口。
- 超时显示“未捕获到可归属请求”，并列出可能原因；不自动重试或延长。
- 支付、删除等操作不做特殊绕过；页面自身确认仍生效。

## AI 入口

AI 操作不占据首要位置，只有以下入口：

- `AI 解释链路`：解释已证明报告。
- `AI 辅助查找`：对 possible/unknown 用只读工具搜索授权源码。

点击后先展示上下文预览：证据数、文件数、字符预算、清洗项、是否会远程发送。用户确认后运行；输出中的每条事实/推断必须有标签和 evidence citation。详见 (见 doc-id:data-flow-09-ai-assistance)。

## 双语消息

所有固定文本使用 `DataFlowMessageKey`，集中加入现有 `zh-CN`/`en-US` 类型化消息表。示例：

| key | zh-CN | en-US |
| --- | --- | --- |
| `dataFlow.tab.component` | 数据链路 | Data flow |
| `dataFlow.tab.page` | 页面接口 | Page APIs |
| `dataFlow.action.observeNext` | 观测下一次操作 | Observe next action |
| `dataFlow.state.observed` | 本页已观测 | Observed on this page |
| `dataFlow.state.upstream` | 上游提供 | Supplied upstream |
| `dataFlow.state.unassigned` | 尚未归属组件 | Not assigned to a component |
| `dataFlow.value.neverCollected` | 敏感，永不采集 | Sensitive, never collected |
| `dataFlow.persistence.unknown` | 服务端持久化未知 | Server persistence unknown |

自由 endpoint、component、path、field、adapter 名不翻译。组件中禁止三元表达式硬编码双语。

## 可访问性与键盘

- 顶层使用语义 `tablist/tab/tabpanel`，方向键切换；选中 tab 的 panel 有关联 ID。
- 请求行和字段树使用 button/tree/grid 的正确语义，不用可点击 `div`。
- 详情打开后管理焦点；返回恢复原请求行；关闭工作台恢复宿主先前焦点。
- observation/分析状态通过 `aria-live="polite"`，高频 polling 不逐条朗读。
- method、状态、关联均有文字；颜色、图标、虚线不是唯一表达。
- endpoint/path 可水平软换行或受控滚动，不缩到不可读字号。
- `prefers-reduced-motion` 移除倒计时以外的非必要动画。

## 响应式和视觉

- 沿用现有 560px 基准宽度和设计 token，不创建新的颜色/圆角/z-index 常量。
- 详情最多占工作台正文，不超出既有 viewport clamp；标题和返回/关闭固定可用。
- 小于 520px：筛选纵向排列、请求行卡片化、参数表转 definition list。
- 技术文本使用既有等宽 token；endpoint 和 JSON path 可选择复制，复制内容仍是已清洗文本。
- skeleton 只用于已知布局；分析时间较长时显示真实阶段与 cancel，不无限 shimmer。

## 交互验收

- 用户从选中 Table 到找到上游接口、参数和 response path 不超过 3 次明确操作。
- 用户从无选中状态进入页面接口不超过 1 次操作。
- 任一事实可在 1 次操作内展开证据，在 2 次内打开源码。
- 语言切换、HMR、route 切换、关闭/重开不串目标或把 stale 记录显示为 current。
- 所有空态与错误态都有精确原因，任何位置不出现未经证明的“该组件没有接口”。
