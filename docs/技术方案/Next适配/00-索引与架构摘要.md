# Next.js 适配索引与架构摘要

## 文档状态声明

本目录是 SpotPatch Next.js 适配的活动架构提案，不是“已经支持 Next.js”的发布声明。`implementation-status: planned` 表示文档已进入评审和后续实现依据，但只有完成全部阻断式验证、实现、发布和验收后，产品支持矩阵才能从“不支持”改为“正式支持” (见 doc-id:01-product-boundary)、(见 doc-id:next-08-testing-delivery)。

本阶段只更新架构与规范，不创建实现包、不修改现有适配器行为、不发布 npm 版本。当前用户仍只能把 `@spotpatch/vite` 用于 Vite 项目；Next.js 项目不得把该包当作 Next 插件使用。

## 仓库决策

不创建第二个 Git 仓库。规划在现有 Monorepo 增加 `@spotpatch/next`，并把 Vite/Next 共用但当前位于 Vite 包内的源码转换和开发服务能力抽成框架无关内核。原因和包依赖边界 (见 doc-id:next-02-package-architecture)，正式 ADR (见 doc-id:15-risks-adr)。

仓库边界与 npm 边界不是同一个概念：

- 一个 Git 仓库维护共同协议、Runtime、Agent、安全规则、测试和版本图。
- 每个框架保留独立用户入口包；Vite 用户安装 `@spotpatch/vite`，Next.js 用户安装 `@spotpatch/next`。
- 用户不需要手动安装内部公共包；发布图必须闭合。
- 框架适配器不得相互依赖，Next 适配器不得通过安装 Vite 来复用实现。

## 目标架构摘要

```text
Next source modules
  → SpotPatch loader（Turbopack / webpack）
  → source marker + internal source registration
  → Next rendered HTML / RSC payload / hydrated DOM
  → @spotpatch/next/client（pre-hydration hook）
  → @spotpatch/runtime
  → same-origin /__spotpatch/v1/**
  → Next beforeFiles rewrite
  → loopback-only SpotPatch Sidecar
  → source/editor/Agent/Git/provider core
```

该图只说明责任流，不重复 marker、HTTP endpoint、Agent 工具或公共配置的定义；这些事实继续分别由现有主题文档管理 (见 doc-id:03-public-api-models)、(见 doc-id:09-local-protocol-security)。Next 专属承载方式由本目录子文档定义。

## 阅读与变更顺序

1. 先确认支持版本和不支持边界 (见 doc-id:next-01-research-compatibility)。
2. 再确认包边界和复用方式 (见 doc-id:next-02-package-architecture)。
3. 接入 API、转换、Sidecar 和 Runtime 分别在其唯一主题文档中演进。
4. 任何影响现有协议、安全或公共配置的决定，必须先修改其既有唯一事实源，不得在 Next 文档中复制定义。
5. 只有阻断式 POC 全部通过，才允许进入公共内核迁移和适配器实现 (见 doc-id:next-08-testing-delivery)。

## 核心工程判断

- Next 16 默认 Turbopack，因此只支持 webpack 不构成正式 Next 支持。
- Next 默认存在 Server Component，浏览器 Fiber 不能完整表达服务端组件树；精确 host marker 是主链路，React Adapter 只能增强。
- Bippy 必须在 React hydration 前安装 hook；使用 Next 官方 `instrumentation-client`，不能等待页面挂载后再初始化。
- Next 没有 Vite `configureServer` 等价公开钩子；本地文件、编辑器和 Agent 能力由独立 loopback Sidecar 承载。
- 不占用面向部署平台的 `adapterPath`，不使用会削弱 Next 优化的 Custom Server。
- 生产零残留是发布条件，不接受仅靠 `NODE_ENV` 运行时判断的“代码存在但不执行”。

上述判断对应的证据、细节和替代方案均在子文档及 ADR 中追溯，本文不维护第二份实现规则。
