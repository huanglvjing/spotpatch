# 测试与验收

本文件定义测试覆盖、CI 矩阵、性能预算、功能/性能验收和 PR 门禁。测试数据采用公共模型与默认预算 (见 doc-id:03-public-api-models)。安全规则及安全验收只有一个事实来源 (见 doc-id:09-local-protocol-security)。产品正式支持范围见产品边界 (见 doc-id:01-product-boundary)。

## 测试方案

### Transform 单元测试

每个 fixture 同时保存 input、expected output 和 source map 断言：

- 原生 div/button/input
- self-closing tag
- 多行 props
- spread props
- 已有同名属性
- Fragment
- 自定义组件
- JSXMemberExpression
- Web Component
- SVG
- map/list 重复元素
- 条件表达式
- 注释与字符串中的伪 JSX
- parser 错误 fail-open
- Windows 路径
- Vite query id

transform 与 source marker 的规范定义见 Vite 插件实现 (见 doc-id:04-vite-plugin)。

### Registry 与安全单元测试

- 相同文件得到相同 ID。
- 不同文件得到不同 ID。
- 未登记 ID 不可解析。
- `../` 目录穿越被拒绝。
- 符号链接逃逸被拒绝。
- root 自身与子文件允许。
- 删除文件返回 SOURCE_NOT_FOUND。
- 超大文件被拒绝。
- token、Origin 和 Content-Type 校验。
- `editor` 仅接受 `auto | vscode | cursor`，分别映射自动识别、`code`、`cursor`，任意字符串不能成为命令。
- 编辑器适配器即时启动失败时 endpoint 返回失败；成功响应的编辑器字段仍需 Runtime 枚举校验。
- Cursor 集成信号优先于通用 `TERM_PROGRAM=vscode`；显式和自动识别路径都只产生 `--goto absolute-file:line:column`，参数中不得出现 `--reuse-window`、`--new-window` 或 shell。
- 多个编辑器工作区同时打开时，用实际 Cursor/VS Code CLI 验证源码文件进入拥有该路径的既有项目窗口，并精确到请求行列；CLI 缺失和非零退出均不得返回成功。
- Agent provider/model 仍是带可访问名称的原生 `SELECT`；深色 `color-scheme` 与 option 配色存在，切换 provider 后模型值、同意状态和 capability 门禁一致更新。

Registry 行为见 Vite 插件规范 (见 doc-id:04-vite-plugin)；文件、错误码、token、Origin 和 Content-Type 的期望值见安全规范 (见 doc-id:09-local-protocol-security)。

### Collector 单元测试

- 密码和值脱敏。
- token/authorization/cookie 脱敏。
- DOM 深度和节点数预算。
- base64/SVG path 截断。
- computed style 白名单。
- 跨域 stylesheet SecurityError 降级。
- selector 语法错误不影响其他规则。
- Prompt 段落顺序和预算稳定。
- 多目标 Prompt 保持选择顺序和不同说明，在紧预算下仍完整保留每个目标的说明、编号和源码位置，且不修改输入对象；预算无法容纳全部说明时明确失败，不能静默截断。

DOM/CSS 范围见采集规范 (见 doc-id:07-dom-css-collection)，脱敏见安全规范 (见 doc-id:09-local-protocol-security)，Prompt 顺序和预算见 Prompt 规范 (见 doc-id:08-code-prompt)。

### Provider contract 测试

配置层必须覆盖：无 `SPOTPATCH_AI_*` 变量时 AI 关闭；URL、模型和 Key 完整时 `spotPatch()` 自动生成单 Provider；任一必要值缺失时 fail-fast 且错误不含 Key；显式 `ai: false` 覆盖环境；简洁配置应用公共默认值；完整配置继续保持兼容。Vite 5/6/7 分别从 `.env.local` 冷启动，证明 config hook 在 transform、Runtime 注入和 server 装配前完成最终解析。

传输层对 `bearer` 和 `x-api-key` 分别断言唯一认证 Header，禁止同时发送；能力缓存键包含认证类型。Runtime 虚拟模块、生产 bundle、日志、错误、Agent checks 和 Git Diff 都不得包含 Key、Base URL、真实模型名或认证环境变量名。

所有 required CI 测试使用进程内 fake HTTP server，不依赖真实 Key、外网、模型可用性或中转站余额。Responses 与 Chat Completions adapter 分别覆盖：

- 正常非流式/流式工具调用、多轮 tool result 和最终完成；Responses 与 Chat Completions 都必须覆盖后续轮次复用相同 provider `toolCallId`。
- SSE chunk 任意切分、多事件同 chunk、UTF-8 边界、注释行、流中断和缺失终止事件。
- 畸形 JSON、未知事件、未知字段、错误 tool name、同轮冲突 `toolCallId` 和无法关联的 tool result；工具参数错误与调用 ID 冲突分别断言稳定错误码。
- 401/403、404 模型或 endpoint 不存在、429、5xx、连接失败、首字节/空闲/总超时和超限 body。
- 能力探测成功、只支持文本、不支持工具、工具参数不稳定以及协议配置错误。
- 取消传播、允许重试的读取阶段、已产生副作用后的幂等恢复。

adapter 必须只输出归一化内部事件；测试不得让 Agent Engine 分支断言 provider 原始 chunk。协议与凭据期望见模型提供商规范 (见 doc-id:17-model-provider-credentials)。

### Agent、worktree 与检查测试

- clean Git 仓库可按默认 `require-clean` 创建 detached worktree；staged、unstaged、untracked 在未同意时安全拒绝，在 `include-local-changes` 明确同意后形成可审计隔离基线。未初始化仓库、非顶层 root、无法解析 HEAD、Git 操作中、冲突、符号链接/非普通未跟踪项、未跟踪数量或总体积超限分别返回稳定原因。
- 绝对路径、`..`、NUL、分隔符混淆、大小写变体、符号链接、保护路径、二进制、超大文件和 root 外路径均拒绝。
- 六个工具分别覆盖合法 Schema、未知字段、预算耗尽、取消与有界输出。
- 严格 Schema 字段错误覆盖“零文件变化 → 结构化可重试结果 → 新 ID 修正成功”；`read_file` 同时覆盖保护路径与缺失路径的统一脱敏拒绝、零读取/零修改、活动失败后改用允许路径并完成任务。畸形 JSON、同轮 ID 冲突和任何写工具路径拒绝继续覆盖终止性失败。
- `replace_text` 覆盖唯一精确命中、零命中、多命中、无变化、UTF-8/BOM、保护路径、超限结果、过期内容、Git whitespace 回滚、同轮重复幂等、同轮冲突拒绝、跨轮相同 ID 独立执行和实际 Diff 一致性。
- `apply_patch` 覆盖新增、修改、删除、上下文冲突、同轮重复幂等、同轮冲突拒绝、部分失败回滚和实际 Diff 不一致。
- `run_check` 只解析登记 ID，验证 `shell: false`、最小环境、超时、信号、非零退出码、ANSI 清洗和日志截断。
- Job 覆盖所有公共状态、非法转换、并发写 Job、取消、Vite 退出和清理失败。
- schema v3 覆盖缺少 locale、旧全局 `note`、空说明、公共单项目标/整组说明边界、空数组、协议硬上限和配置上限；服务端覆盖逐目标授权、不同说明保持原顺序、重复源码坐标拒绝、任一目标失败则整批失败，以及浏览器 `CodeContext` 被丢弃并重新读取。具体值只引用公共模型 (见 doc-id:03-public-api-models)。
- review/auto 的 required check 必须有当前变更版本中由宿主实际执行的结果；同版本 `run_check` 可复用，任一写入必须使其失效并在最终阶段补跑。失败时 auto 不应用，review Apply 也不可用。trusted-auto 的验收必须证明模型工具列表不含 `run_check`、项目检查未执行、隔离 Diff 仍经过原子写回与冲突门禁。
- 首次直接运行不调用独立 capability probe；首轮纯文本必须失败。同轮多个只读工具先全部发出 started 事件再完成，混合写入仍严格串行。文件目录缓存覆盖结构变更失效，文件内容和 check 缓存覆盖变更版本失效。
- 项目规范上下文覆盖最近目录与根配置、manifest 仅保留元数据、测试/生成文件不作为实现样例、总 Prompt 预算、敏感值脱敏，以及 check 命令/参数不进入 provider 请求。
- Apply 覆盖 HEAD、Agent 触及文件基线哈希、并发变化、patch check 冲突与全有或全无；无关文件允许并发变化且必须保留。脏基线覆盖同一文件 staged+unstaged、staged 新增/删除、untracked 输入和 index 内容前后不变。Revert 覆盖只撤 Agent 增量、恢复脏基线、保留无关修改，以及 Agent 触及文件后续编辑时安全拒绝。

测试 fixture 必须在测试创建的临时 Git 仓库中运行，不能读取或修改开发者真实仓库。工具和 Git 行为见 Agent 执行规范 (见 doc-id:16-ai-agent-execution)，保护路径与错误码见安全规范 (见 doc-id:09-local-protocol-security)。

### Playwright E2E

| Fixture | 核心断言 |
| --- | --- |
| 原生 JSX | exact 文件和行列 |
| 自定义组件 | 组件名正确、host marker 正确 |
| memo/forwardRef | 组件显示名合理 |
| lazy route | 首次加载及 HMR 后正确 |
| Fragment | 多根节点可分别选择 |
| list/map | 实例 DOM path 不同、源码位置相同 |
| AntD Button | 能回溯业务组件或明确 probable |
| AntD Modal | Portal 中选择正常 |
| Tailwind | class 和关键计算样式存在 |
| CSS Module | 匹配运行时 class 规则 |
| Framer Motion | 可选择且降级清晰 |
| SVG | SVG 元素可选 |
| 登录表单 | 密码、token 不出现在 Prompt |
| StrictMode | 页面只有一个 runtime 实例 |
| HMR | 修改前后 source line 更新 |
| 上下文工作台 | 大选区内居中、小选区邻近停靠、始终不越出视口 |
| 直接输入 | 选中后活动目标说明自动聚焦，无额外保存步骤；全部目标说明有效后才可预览 |
| 多目标选择 | 每个目标填写不同说明；切换、追加、异步刷新和去重后草稿不串位；编号高亮与 TargetList 一致；可逐项删除；Prompt 含全部目标及其说明；达到数量或字符上限不破坏原集合 |
| 双语界面 | `auto`、显式中英文和标题栏切换均确定；切换后固定文案、错误码和 Prompt 标题更新，目标草稿、provider/model、同意状态与 Job 不丢失 |
| 视觉与响应式 | 560px 桌面层级、目标/正文最小字号、总字符预算状态、520px 以下单列布局、正文滚动和底部操作可见均通过截图与可访问性检查 |
| AI 未配置 | 无 Agent 网络/路由副作用，Prompt 回退完整可用 |
| Provider 同意 | 首次远程传输必须明确同意，拒绝后不发请求 |
| 工作区健康与本地修改同意 | clean 直接就绪；dirty 显示 staged/unstaged/untracked 计数且独立勾选前不可运行；blocked 展示精确原因且不能绕过；运行前重新检查；Apply/Revert 保留用户原修改 |
| Provider/Model 展开 | Chromium customizable select 的 picker 出现在字段下方、打开/关闭状态可观察、选中后自然收回；不支持浏览器保持原生键盘和读屏语义 |
| Agent 成功 | fake provider 驱动读取、patch、required checks、Diff 审阅和 Apply |
| Agent 取消 | 流、工具和检查取消，业务工作区保持不变 |
| Agent 失败 | 协议、工具、检查与冲突错误准确展示，不可 Apply |
| Auto 门禁 | 仅全部门禁通过时自动应用，否则降级 review 或失败 |
| Apply 后 HMR | 文件更新触发页面刷新，陈旧元素失效并要求重新选择 |
| Revert | 文件未继续变化时成功撤销，存在后续编辑时安全拒绝 |
| 源码导航 | 每个有源码坐标的目标和底部活动目标入口都打开正确行列；Agent 锁定与 Apply 后仍可用；启动失败显示可见反馈 |
| GitHub 入口 | 指向官方仓库，以新窗口打开并包含 `noopener noreferrer`，不带追踪参数 |

Playwright 使用独立 BrowserContext，避免测试之间共享 localStorage 和选择状态；不使用固定 sleep，依赖 locator 与可观察状态等待。

Runtime/HMR 行为 (见 doc-id:05-runtime-lifecycle)、置信度语义 (见 doc-id:06-source-resolution) 和 UI/无障碍行为 (见 doc-id:10-ui-diagnostics) 均由本表对应 fixture 验证。

### 生产零残留测试

对 playground 执行 `vite build` 后扫描全部产物：

扫描目标从各自唯一事实源读取，不在测试中复制常量：

```text
SOURCE_MARKER_ATTRIBUTE  → 0  (见 doc-id:04-vite-plugin)
SPOTPATCH_API_BASE       → 0  (见 doc-id:09-local-protocol-security)
spotpatch.runtime        → 0
SPOTPATCH_TOKEN_HEADER   → 0  (见 doc-id:09-local-protocol-security)
```

任意一项非零，CI 失败。

AI 扩展启用与禁用各构建一次。除上述扫描项外，还必须确认生产产物不含 Agent endpoint、provider adapter、Secret 环境变量名、模型配置、worktree/check runner、Agent UI 启动代码和 Key fixture；具体秘密值与协议路径仍从各自唯一事实源生成测试样本，不在测试代码复制常量。

### 兼容矩阵 CI

- Node 20、22
- Vite 5、6、7
- React 18.2、18.3
- macOS、Ubuntu、Windows 至少覆盖构建和单测
- Chromium E2E 作为 required check

所有 CI 与发布 Job 必须复用仓库内同一个 setup composite action，执行顺序固定为：checkout → 按根 `packageManager` 安装 pnpm → 配置 Node/pnpm 缓存 → frozen lockfile 安装。`setup-node` 不得在 pnpm 可执行文件存在前尝试解析 pnpm 缓存。pnpm 版本只在根 `packageManager` 定义，workflow 不维护第二份版本常量。

仓库文本统一以 LF checkout，Windows 不得因 Git 自动转换为 CRLF 而产生 Prettier 假失败。兼容性脚本只验证显式发出的 HTTP 请求；没有真实浏览器继续爬取静态导入时，必须关闭自动依赖发现且不得等待 Vite 的完整模块图 crawl idle，否则冷启动优化器或顶层 await 可能在 Node 20/22 无活动句柄时以退出码 13 结束。Action 本身使用的平台 Node runtime 与被测 Node 矩阵相互独立，前者必须跟随 GitHub 支持的非弃用主版本。

### npm 发布预检

`package:validate` 负责构建、publint 与 Are the Types Wrong；仓库结构单测同时验证：

- 五个公共包的 npm 名称、仓库 URL、Monorepo 子目录、主页、问题地址、公开 registry 和非空包级 README。
- 所有 `workspace:` 依赖都指向声明过的公共 workspace 包，入口包的发布依赖图可闭合。
- 首次发布前，所有版本为 `0.0.0` 的公共包都包含在 pending Changeset，禁止漏发内部依赖。

发布 Job 必须先执行格式、Lint、类型、单测和包验证，再允许 Changesets 创建版本 PR 或发布。首次发布还需人工确认 npm scope 所有权、GitHub `NPM_TOKEN`、Actions 写权限和允许 Actions 创建 PR；这些外部状态不能由本地测试伪造。发布后必须从 npm registry 安装 `@spotpatch/vite` 到空白 fixture，验证其传递依赖、ESM/CJS、类型声明和生产零残留；可信发布者迁移与凭据规则以模型/凭据安全边界为同类最小权限原则，不在测试夹具中保存真实 token。

## 性能预算

### Transform

- 只解析符合过滤条件的 JSX/TSX。
- 相同 `id + code hash` 可使用会话内缓存。
- 不扫描整个项目，只处理 Vite 实际请求的模块。
- 单文件转换时间记录在 debug 指标中。

目标：中位数 < 5 ms，P95 < 20 ms；超大文件单独记录，不以隐藏缓存伪造数据。

### Runtime

- pointermove 每动画帧最多执行一次 hit test。
- hover 时不读取源码、不遍历 stylesheet、不生成 Prompt。
- 重操作只在点击选中后执行。
- CSS 采集可分帧或异步，让高亮先显示。
- 大页面 stylesheet 很多时，只在选中后采集、缓存 stylesheet 索引、分帧。
- 不常驻持有整棵 Fiber 树的副本。
- Runtime 无持续增长的 Element/Fiber 引用。

目标：高亮反馈一帧内出现；选择摘要 < 100 ms；完整上下文普通页面 < 300 ms。

### 包体

包体是开发依赖，但仍需监控：

- runtime gzip 目标 < 40 KiB，不含可选 React adapter；新增的有界会话草稿负责跨同源页面恢复已清洗目标，决策与旧预算关系见 ADR-020、ADR-032 (见 doc-id:15-risks-adr)。
- 体积门禁必须在 CI 支持的操作系统上以同一发布产物、同一压缩级别执行；本地结果必须为压缩库的跨平台差异保留明确余量，禁止仅凭某一平台的临界通过发布，也禁止通过提高预算掩盖新增交互的体积回归。
- 构建必须生成独立的核心 Runtime 与 React Adapter 浏览器产物；核心产物不得内联 Bippy，adapter 私有虚拟模块必须能在受支持 Vite 版本中解析和加载。拆分边界 (见 doc-id:02-architecture-stack)。
- 不把 parser 打入浏览器；Oxc 只运行在 Node 端。
- source code、manifest、Zod 服务端部分不进入浏览器 chunk。
- provider adapter、Git、文件工具和检查 runner 不进入浏览器 chunk；AI 关闭时 Node 开发路径也不初始化这些模块。

### Agent 资源预算

- 并发和累计调用必须被公共 Agent limits 硬终止，不依赖模型自觉停止。
- 取消动作应立即更新 UI，并在有界时间内终止 provider 流和检查子进程。
- 长日志、大文件、大 Diff 和 provider 超限响应不得造成浏览器卡死或 Node 无界内存增长。
- 首次真实 Job 不得额外消耗独立 capability probe 的两个 provider 往返；只读调用并发、目录/内容缓存和同版本 check 去重必须有行为测试，且任何写入后都不能返回旧结果。
- 性能报告分别记录 provider 等待、工具执行、检查和 Apply 时间，不把远程模型延迟计入元素选择性能指标。

数值上限只取公共配置 (见 doc-id:03-public-api-models)，不在本文件维护第二份默认值。

## 验收指标

### 功能验收

- 原生业务 JSX 精确定位率 ≥ 95%。
- 所有业务元素可定位到可修改业务文件的比例 ≥ 90%。
- 组件名人工核对准确率 ≥ 90%。
- AntD Portal 元素可选择率 = 100%。
- 一键在自动识别或显式配置的 Cursor/VS Code 中打开匹配项目工作区、文件标签和精确行列的成功率 ≥ 99%（排除用户未安装或 CLI 不可用）；多个编辑器窗口下不得强制落入最后活跃的无关工作区，即时启动失败不得计为成功。
- Prompt 复制成功有明确反馈，失败可手动选取文本。
- 在公共配置允许范围内，多目标的追加、去重、移除、逐目标不同说明、全部目标预览和活动目标打开编辑器均有确定结果；单个异步采集结果不得写入已删除或重选后的目标，任一说明缺失或总字符超限都不得创建 Job。
- fake provider 的 Responses、Chat Completions、工具循环、review Apply、受限 auto、取消和 Revert E2E 全部通过。
- Agent 产生变更时，UI 展示的文件、Diff 统计和 checks 与隔离 worktree 的实际结果一致。
- 工作区健康检查能准确区分 clean、需同意和不可执行；纳入本地修改后，Agent 的 Apply/Revert 不改变用户原有 index 状态，不撤销用户原有内容，也不因无关文件变化误报冲突。
- 任何 capability、工具、路径、limits、required check 或基线门禁失败，都不能修改业务工作区。

### 安全验收

安全验收指标不得在此复制，统一执行安全规范中的验收清单 (见 doc-id:09-local-protocol-security)。

### 性能验收

- hover 过程不读取文件或遍历全部 stylesheet。
- pointermove 处理不超过每帧一次。
- 普通页面点击后 300 ms 内得到完整上下文。
- Runtime 无持续增长的 Element/Fiber 引用。

这些指标与本文件“性能预算/Runtime”共用同一验收实现，不另设一套数值。

`@spotpatch/next@0.1.0` 公共预览尚未进入本文件的正式兼容矩阵。正式支持前必须完成独立规范中的阻断式 POC、公共内核零回归、Turbopack/webpack 双构建器、App/Pages Router、RSC、Sidecar 安全、生产零残留和 Registry 冷安装门禁 (见 doc-id:next-08-testing-delivery)。只有该门禁全部通过并更新产品支持矩阵后，相关 job 才能成为本仓库 required checks；不得用包已发布或单一 demo 成功代替矩阵证据。

## PR 检查清单

每个 PR 必须回答：

- 是否改变公共 API 或协议？
- 是否新增浏览器或 Node 权限？
- 是否可能进入生产构建？
- 是否读取了更多源码或用户数据？
- 是否向新的 provider、host 或上游发送数据，且 UI 是否取得知情同意？
- 是否改变模型 allowlist、工具权限、保护路径、Agent limits 或自动应用门禁？
- 是否可能泄漏 Key、Prompt、源码、Diff、命令输出或真实模型名？
- 是否增加 token/请求成本、重试、后台 Job 或无法取消的进程？
- 是否新增第三方依赖，且职责是否与现有依赖重复？
- 是否有 fail-open 或降级路径？
- 是否释放新增监听器、Observer、timer、AbortController？
- 是否增加对应单元测试/E2E？
- 是否更新兼容矩阵或已知限制？
- 是否验证 spotpatch-web 中至少一个真实场景？

合并前 required checks：

```text
format:check
lint
typecheck
test:unit
test:e2e:chromium
test:production-leakage
package:validate
```

真实 provider smoke test 只能作为人工、显式 opt-in 的发布前检查：从环境变量读取专用低权限 Key，使用最小 fixture 仓库，设置费用上限，运行后销毁 Key；它不是 required CI，失败也不能通过放宽 contract 测试掩盖。目标项目的最终 Agent smoke test 必须先满足干净工作区与备份/提交前置条件。

编码质量规则见编码规范 (见 doc-id:11-coding-standards)，真实项目场景见当前项目接入规范 (见 doc-id:13-project-integration)。
