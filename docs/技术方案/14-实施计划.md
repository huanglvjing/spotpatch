# 实施计划

Milestone 0–5 以 v1 核心范围为边界；Milestone 6–10 是默认关闭的 v1.1 AI 扩展；Milestone 11 把多目标交互、品牌视觉和双语能力提升到产品化质量，均不能削弱已经成立的 v1 降级路径 (见 doc-id:01-product-boundary)。工期是工程估算，不是完成承诺；每个阶段只有通过对应完成标准才进入下一阶段。

## Milestone 0：仓库与质量基线（0.5 天）

- 初始化 pnpm workspace。
- 建立四包结构和依赖方向检查。
- 配置 TypeScript strict、ESLint、Prettier、Vitest、Playwright。
- 建立最小 React 18 + Vite playground。

完成标准：空实现可以 build、lint、typecheck、test，公共包 exports 通过验证。

仓库结构见总体架构 (见 doc-id:02-architecture-stack)，编码要求见编码规范 (见 doc-id:11-coding-standards)。

## Milestone 1：精确源码标记（1–1.5 天）

- Source Registry。
- JSX/TSX 过滤。
- Oxc AST 遍历。
- MagicString 注入和 source map。
- transform 黄金测试。
- 生产零残留测试。

完成标准：所有 intrinsic fixture 精确通过；自定义组件不被错误注入。

实现规范见 Vite 插件文档 (见 doc-id:04-vite-plugin)，门禁见测试与验收文档 (见 doc-id:12-testing-acceptance)。

## Milestone 2：Picker 与打开源码（1–1.5 天）

- Runtime 注入和单例生命周期。
- Shadow DOM Trigger/Highlight。
- 捕获事件与选择状态机。
- source-context/open-editor API。
- 文件 root 安全和 session token。

完成标准：点原生元素能显示文件行列并打开 VS Code。

实现分别见 Runtime (见 doc-id:05-runtime-lifecycle)、UI (见 doc-id:10-ui-diagnostics) 和协议/安全规范 (见 doc-id:09-local-protocol-security)。

## Milestone 3：React 语义（1–2 天）

- React Adapter 接口。
- React 18 Bippy adapter。
- displayName、memo、forwardRef、组件栈。
- AntD Button/Modal 实测。
- 置信度与降级 UI。

完成标准：第三方 DOM 不伪装 exact；能合理回溯业务组件。

判定规则见源码解析与置信度 (见 doc-id:06-source-resolution)。

## Milestone 4：上下文与 Prompt（2–3 天）

- DOM collector 和 sanitizer。
- CSS rule/computed collector。
- 组件或附近代码读取。
- Annotation/Preview UI。
- Prompt Composer、预算和 Clipboard fallback。

完成标准：用户可以完成“点选 → 标注 → 预览 → 复制”的完整闭环。

实现分别见采集规范 (见 doc-id:07-dom-css-collection)、源码与 Prompt (见 doc-id:08-code-prompt)、安全规范 (见 doc-id:09-local-protocol-security) 和 UI 规范 (见 doc-id:10-ui-diagnostics)。

## Milestone 5：真实项目验收（1–2 天）

- 接入 spotpatch-web。
- 分层抽样 50–100 个元素。
- 记录 exact/probable/approximate/unknown。
- 修复高频失败类别。
- 做生产构建泄漏检查和隐私检查。

真实项目约束见接入规范 (见 doc-id:13-project-integration)，所有完成判据最终以测试与验收规范为准 (见 doc-id:12-testing-acceptance)。

## Milestone 6：AI 规范与配置基线（1 天）

- 固化 Provider、凭据、Agent、Git 与审阅 ADR。
- 扩展公共 AI 配置、limits、Job 模型和稳定错误码。
- 建立 provider/agent Node-only 包边界与依赖检查。
- 先写 config、Schema、状态转换和安全拒绝单测。

完成标准：AI 默认关闭；合法/非法 URL、env、profile、model、check 与 limits 都有确定解析结果；浏览器构建无法导入 Node-only 模块。

配置事实见公共 API (见 doc-id:03-public-api-models)，架构边界见总体架构 (见 doc-id:02-architecture-stack)。

## Milestone 7：Provider Adapter 与能力探测（2–3 天）

- 实现 Responses 与 Chat Completions adapter。
- 实现严格 JSON/SSE parser、归一化事件、取消、超时和有界重试。
- 实现环境变量 Secret Resolver 与全链路脱敏。
- 实现无源码 capability probe 和 fake provider contract suite。

完成标准：两种协议的成功与全部失败 fixture 通过；Key 泄漏扫描为 0；不支持结构化工具调用的模型不能进入 Agent 执行。

实现契约见模型提供商规范 (见 doc-id:17-model-provider-credentials)。

## Milestone 8：Agent Engine、工具与 Git 隔离（3–4 天）

- 实现 Job store、工具循环、预算、幂等和取消。
- 实现受控只读工具、patch 工具和 check registry。
- 实现 clean-worktree 门禁、临时 worktree、Diff、Apply/Revert 和清理。
- 完成路径攻击、保护文件、并发变化和原子失败测试。

完成标准：所有写入只发生在测试 worktree；未通过验证前业务工作区保持不变；恶意/重复/超限工具调用全部 fail-closed。

实现契约见 Agent 执行规范 (见 doc-id:16-ai-agent-execution) 与安全规范 (见 doc-id:09-local-protocol-security)。

## Milestone 9：本地协议、流式 UI 与审阅（2–3 天）

- 注册能力、Job、事件、结果、取消、Apply 和 Revert endpoint。
- 实现 provider/model 选择、远程传输同意、运行进度与取消。
- 实现完整 Diff、checks、review Apply、受限 auto 和 Revert UI。
- 完成键盘、焦点、屏幕阅读器、视口定位与 HMR E2E。

完成标准：fake provider 可以完成“选中 → 输入 → 运行 → 工具 → 检查 → 审阅 → Apply → HMR → Revert”闭环，任一门禁失败均有明确且不可绕过的 UI 状态。

协议与 UI 分别见本地安全规范 (见 doc-id:09-local-protocol-security) 和 UI 规范 (见 doc-id:10-ui-diagnostics)。

## Milestone 10：真实中转站与目标项目验收（2–3 天）

- 用专用低权限 Key 对用户中转站做显式 opt-in smoke test。
- 在干净的 spotpatch-web 工作区执行单文件、可撤销任务。
- 验证 lint/build、Apply 冲突、HMR、Revert、取消、限流和 Key 脱敏。
- 记录 provider 实际兼容范围、成本、延迟和已知限制。

完成标准：测试与验收规范的 v1.1 required 项全部通过；真实 smoke test 不取代 fake contract；用户确认 Diff 后才扩大使用范围 (见 doc-id:12-testing-acceptance)。目标项目专有前置条件见接入规范 (见 doc-id:13-project-integration)。

## Milestone 11：逐目标工作台与产品视觉（2–3 天）

- 把多目标数据契约升级为 schema v3：每项目标拥有独立说明，并增加单项/总量硬上限和全链路运行时校验。
- 实现活动目标卡片编辑、草稿隔离、完整字符预算反馈、不同说明 Prompt/Agent 原子执行和切换/追加/移除回归测试。
- 以 SpotPatch 标识建立集中视觉令牌，重构目标、Provider、Job 和底部操作层级；移除装饰性“AI 科技”噪声并完成桌面/窄屏响应式。
- 实现类型完备的中英文消息表、`auto`/显式初始语言与无刷新切换；固定错误码和 Prompt 标题随语言更新，业务数据不猜测翻译。
- 在 playground 与 spotpatch-web 分别完成截图、键盘、焦点、屏幕阅读器、HMR、Prompt、Agent 门禁和生产零残留验证。

完成标准：公共 schema、Runtime、Prompt、服务端授权与 Agent Engine 对逐目标语义完全一致；所有目标说明在语言切换和异步刷新后保持；任一空项或总量超限不能执行；中英文与响应式验收矩阵、全量 lint/typecheck/unit/E2E/build 均通过，且真实业务组件只会在用户审阅 Apply 后修改。规范事实分别见公共模型 (见 doc-id:03-public-api-models)、Runtime (见 doc-id:05-runtime-lifecycle)、Prompt (见 doc-id:08-code-prompt)、UI (见 doc-id:10-ui-diagnostics) 和验收 (见 doc-id:12-testing-acceptance)。
