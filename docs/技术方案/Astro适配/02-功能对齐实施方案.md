# Astro 与既有适配器功能对齐

本轮用户要求补齐全部既有能力，取代 00/01 中将 dataFlow、externalAgent、contextualAsk、trustedFastMode 永久排除的预览范围。旧验证记录仍是历史证据，不能当作本轮功能已经完成的证明。`@spotpatch/astro@0.1.0` 已于 2026-09-06 发布到 npm；发布不改变外部 Agent、真实 provider、SSR adapter 与第三方 UI 框架的既有证据边界。

## 对齐清单与顺序

1. 公共服务：提取框架无关 session 服务装配，复用同一工作区互斥协调器、AI Job、Ask executors、Inbox、主动 Agent 控制及关闭逻辑；桥接实现以窄 factory 注入，避免 dev-server -> bridge -> dev-server 开发依赖环。保留 Next 的 sidecar/注册/公开路由边界。
2. 浏览器扩展：按启用的功能装载 Data flow、Ask、外部 Agent 面板；保留共享模块实例、Astro 页面切换与 HMR 的清理。开关必须同时有服务和 UI，不以开启 schema 替代实现。
3. 源码定位：原生 `.astro` 保留现有编译器；JS/TS/JSX/TSX islands 使用公共 compiler，而不是依赖 vite/next 适配器。仅处理原始源码，不给已编译 Astro JS 伪造原始位置。
4. 数据链路：React islands 复用现有 AST instrumentation/静态分析；原生 Astro 需要原文坐标的语言投影，隔离 frontmatter 与 script 的变量作用域，保留相对 import、真实源码授权及版本 hash。原生 DOM 的归属不能伪报 React/Fiber；框架导航请求不能算业务接口；浏览器无法证明的服务端执行保持 declared-not-observed。
5. Trusted fast：复用原执行模式与显式同意；Astro 检查必须覆盖模板，不能把发现 tsc 解释为已能验证 Astro。保留用户配置的 required checks，并测试缺失检查时 fail-closed。
6. 接入/外部命令：从 npm 安装 Astro integration 并使用桥接公共 CLI；不复制协议、Agent connector 或代码生成实现。第三方镜像同步延迟必须显式提示回退官方 npm registry，不能通过放宽或直装内部依赖掩盖。
7. 验收：能力开关与禁用路径、源码读取、Ask/Inbox HTTP、浏览器 UI、AI Review/Apply/Revert、native/island 数据流、导航/HMR/重启、production、既有框架回归。大构建与进程时序测试串行运行。

## 不可放宽的约束

源码 registry/realpath/token/Origin、受限 Agent 工具、工作区写入互斥、只读 Ask 和冲突安全回滚继续生效。未知动态行为使用既有 unknown/partial 语义，不能为了“功能对齐”伪造 exact/proven/observed。React Fiber 语义只用于真实 React island；Astro 的前后端作用域以官方 [脚本处理](https://docs.astro.build/en/guides/client-side-scripts/)和 [Integration API](https://docs.astro.build/en/reference/integrations-reference/)为依据。

每项实现及验证完成后在本文增加证据；所有项目通过前不得声称全功能完成。

## 实现落点

- `packages/dev-server/src/development-session.ts` 统一服务生命周期；Vite、Next、Astro 注入各自 bridge 工厂并保留 HTTP/sidecar 边界。Ask、AI 变更共用工作区协调器，服务关闭逆序执行，部分启动失败也清理。
- `packages/astro/src/integration.ts` 只在 dev 装配；`transform.ts` 分流原生模板和 JSX/TSX；`runtime-plugin.ts` 按选项加载独立浏览器产物。Astro CLI 复用 `connect`/`bridge`，并由独立的 Astro 配置初始化器安全处理 ESM 静态对象、变量导出和单一对象返回的 `defineConfig`；它不依赖 Vite/Next 适配器，对动态 integrations、spread 覆盖、重复导入或多配置文件无写入失败。
- `source-projections.ts` 保留原文 UTF-16/换行和物理文件 hash，frontmatter 与模板表达式共享服务端绑定，浏览器 script 独立。相邻模板表达式分组，不能拼成原文不存在的函数调用。处理后的浏览器 script 使用共享 compiler 的模块/事件 instrumentation，具名事件回调保留 add/remove 身份。
- analyzer 为投影创建独立程序并合并证据，整个文件共享模块/调用/时间预算；超预算仍返回 partial。Runtime 合并接受静态报告证明的多个 script owner，但拒绝把服务端证据升级为浏览器已观测。页面导航排除使用实际 loader 的 URL 和 AbortSignal，非 URL 前缀猜测。
- Ask 通过 Astro AST 提取相对 imports/re-exports/脚本引用，继续使用只读 grant、真实路径与字节预算；不解析或执行前端构建产物作为原文。
- 原生 `.astro` AI Review/Apply/Revert 使用同一 Agent 执行链，测试 provider 为合成响应。外部 Agent 的平台/客户端成熟度没有因增加 Astro 而扩展。

## Astro 校验的安全边界

常规 `astro check` 会调用 sync，因此自动发现使用已安装的 `@astrojs/check/bin/astro-check.js`，固定 error 阈值、仓库相对 `--root` 和 `--tsconfig tsconfig.json`。要求宿主明确声明 Astro/checker/TypeScript、具有常规 tsconfig 和 Git 根；缺失时不安装、不退回 tsc。显式配置的 required checks 优先，命令本身仍由用户负责。

`@astrojs/check` 0.9.10 的 bin 与参数解析器重复去掉前两个参数；命令前置的显式默认 error 阈值兼容这一路径，同时保留 root/tsconfig。已用真实工具验证有效模板通过、类型错误退出 1，且不会执行抛错的 `astro.config.mjs`。依据：本地已安装官方包源码，以及 [Astro 类型检查](https://docs.astro.build/en/guides/typescript/#type-checking)和 [CLI](https://docs.astro.build/en/reference/cli-reference/#astro-check)。

`packages/agent/src/validation/trusted-check-dependencies.ts` 只允许固定直接 tsc/Astro diagnostic 命令在托管校验阶段临时使用宿主已安装依赖。Agent 编辑阶段不挂载，校验完成或失败后清理；参数变化、越界 root、无关 checker 不获取此权限。嵌套应用保留依赖查找链，自动发现命令在仓库根执行，自定义命令保留应用根语义。它不是 OS 级沙箱，已安装的检查工具/依赖是信任前提。

不在隔离快照自动同步 `.astro` 内容集合/生成类型；依赖这些产物的项目需要自己配置必需检查。检查失败阻止自动应用，不把检查器通过等同于完整业务、SSR 或视觉验收。
