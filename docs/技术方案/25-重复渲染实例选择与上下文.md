# 重复渲染实例选择与上下文

## 1. 问题与证据

本方案先于实现编写。基线为本地 `6a43747`；分析对象是当前源码，不推断 npm 已发布能力。

用户反馈：页面用同一个组件渲染 20 张卡片时，选择一张应保留具体实例的上下文，而不只是共享 JSX 文件。

已确认的问题：

1. Runtime `duplicateTarget()` 优先按 `fileId + line + column` 去重。两个不同 DOM、相同 source marker 的临时控制器复现，实际只产生一个目标。
2. 服务端 `annotation-authorizer.ts` 的 `targetIdentity()` 同样按源码位置拒绝重复目标。仅修浏览器会使提交被拒绝。
3. DOM selector 遇到 `id` / `data-testid` 即停止，未检查唯一性；重复测试 ID 会产生相同 selector，五层截断也可能丢失区分实例的祖先。
4. 复制 Prompt 只输出 DOM HTML，没有输出已有 selector；内置 Agent 的压缩兜底还可能退化为相同文件坐标。
5. 选中卡片内的同名按钮时，原采集器仅保留两层父 opening tag，容易丢失卡片标题、行记录等上下文。
6. DOM 采集异步发生，点击与采集之间节点被虚拟列表复用时，可能采到另一个记录。现有 MutationObserver 主要处理几何与卸载，不观察属性、文本变化。
7. 现有 mapped-list E2E 只检查 source marker、test ID 和单项源码置信度，没有验证同源实例多选、提交、Prompt、重排与节点复用。

修复前已有 66 项相关单测通过。这说明原测试覆盖不足，不能将通过率当作实例语义正确的证据。

## 2. 事实边界与官方依据

- 源码位置标识生成代码；同一处 JSX / Astro 模板生成多个 DOM 是正常行为。
- React `key` 仅要求在兄弟间唯一，也不会作为普通 prop 传给组件，不能作为跨框架全局实例身份：[Rendering Lists](https://react.dev/learn/rendering-lists)、[Special Props](https://react.dev/warnings/special-props)。
- DOM 对象引用能区分当前文档中的具体元素；`isConnected` 仅证明仍连到文档，不能证明业务记录未改变：[MDN isConnected](https://developer.mozilla.org/en-US/docs/Web/API/Node/isConnected)。
- selector 查询是某个时刻的 DOM 事实，重排后位置会变化：[MDN querySelectorAll](https://developer.mozilla.org/en-US/docs/Web/API/Element/querySelectorAll)。

本次保证：点击时绑定正确 DOM，独立保存同源实例及其要求；保留可核验的捕获时定位和邻近实例上下文；节点变化、移除、恢复时不静默指向新实例；这些证据贯穿所有执行路径。

不能保证：仅凭 DOM 自动知道未渲染的业务 ID、props 或服务端记录；任意框架内部实例身份；真实模型总能正确修改单条业务记录。选中实例也不自动代表只修改实例，作用范围仍由用户要求决定。相同外观且无公开身份的记录，应报告证据不足。

## 3. 身份分层

| 层次 | 身份与用途 | 不可用于 |
| --- | --- | --- |
| 源码 | 现有 SourceRef / marker，源码读取与授权 | 页面目标去重 |
| 活动 DOM | 当前文档中的 Element 对象引用 | reload/HMR 后自动重绑定、业务记录永久身份 |
| 捕获实例 | 文档随机命名空间 + 目标序号形成的不透明 ID | 文件授权、推断数据库主键 |
| 上下文证据 | 捕获时唯一 selector、局部容器 HTML、可选业务提示 | 作为可信指令或修改范围授权 |

保留现有目标 ID、注解版本和任务 envelope。给 `ElementContext` 增加可选 `instance`，避免给各框架另造 DTO。旧注解仍可解析；新 Runtime 必须提供该证据。旧服务端的 strict schema 不认识新字段，发布时须一起升级共享协议和框架交付包，不能混用新 Runtime 与旧服务端。

`instance` 包含捕获 ID、状态、selector 状态及有界邻近容器上下文。数据模型、预算与状态只在 shared 定义；协议使用严格 schema。selector 仍使用现有 `element.selector`，不重复存储。

## 4. 选择与定位算法

### 4.1 去重

- 只有仍活动、同一个 Element 才视为重复选择。
- 两个 Element 即使 marker、文本、组件名、测试 ID 相同，也必须分别建目标。
- 恢复的快照没有活动 DOM 引用，不依据源码、selector、序号、业务提示自动绑定。
- 已变化的目标释放活动引用；重新选择同一被复用节点，创建新捕获。

### 4.2 selector

- 优先尝试安全的 id / test ID / 结构路径，但必须用当前 document 实测唯一且结果就是选中 Element。
- 重复 ID / test ID 继续向上构造含 `nth-of-type` 的路径，不能把第一个命中当作成功。
- 长度、祖先深度设限；不可表示、脱敏后失真、非文档查询根等情况返回 unavailable，不能截断后仍标为唯一。
- selector 只承诺捕获时唯一，不作为恢复、重排或 HMR 后的自动选取器。

### 4.3 实例局部上下文

- 点击时同步采集 DOM 与实例证据，CSS 等较重工作保留异步。
- 在有界祖先链中优先取显式 `data-spotpatch-instance`、表格行、列表项、article、语义 row/listitem 或同源重复容器；找不到则保留邻近父容器。
- 容器是 DOM 上下文，不宣称它就是框架组件边界。容器 HTML 复用已有 DOM 清洗、深度和节点预算，并设独立字符上限。
- `data-spotpatch-instance` 是可选公开业务提示，只有开发者主动放到 DOM 才采集；仍脱敏，不增加通用任意 `data-*` 或整份 props 采集。
- 表格/列表可直接使用可见名称定位；隐藏业务身份只能由宿主显式提供。React key/Fiber props 不是本次依赖。

## 5. 生命周期与交互

| 状态 | 含义 | 行为 |
| --- | --- | --- |
| captured | 保留点击时快照；尚未观测到相关内容变化 | 用原 Element 高亮，重排仍跟随同一节点 |
| changed | 观察到局部内容/身份属性变化或移出原捕获容器 | 保留原证据和要求，释放活动引用，提示重新选择 |
| detached | 原节点已移除或应用后释放 | 保留快照，不重绑定 |
| restored | 从 Session 恢复的历史选择 | 保留快照，不依据 selector 查找新节点 |

观察 childList、characterData、attributes；SpotPatch 工作台位于 Shadow DOM，文档观察器不会跨入。纯 `style` 属性变更用于几何刷新，不认定为业务身份变化；CSS 仍是点击时快照。纯兄弟重排且原节点/容器内容未改变，不重新按位置选取。对有界容器内的内容变化保守降级；宁可要求重新确认，也不将虚拟列表复用后的节点视为原记录。提交/再次选择前处理待交付 mutation records，堵住观察器异步回调窗口。

历史快照仍可用于已有跨页 Ask / Change 工作流；UI 与 Prompt 必须标明状态，不能把它展示为当前页面实时绑定。历史证据不自动更新为新节点内容。非 style 动态属性或计数变化可能保守降级，这是明确取舍。若宿主只修改框架内部状态，或直接写入不会产生 MutationRecord 的 DOM property（例如 input.value），系统无法仅凭观察器证明业务记录改变；宿主需同步公开实例提示，或由用户重新选择，不能宣称覆盖所有虚拟列表实现。

目标标签展示脱敏的短文本或容器文字辅助区分，同一组件名不再是唯一可见标识。源码置信度继续独立展示，`exact` 不代表业务实例已识别。

## 6. 协议、授权与执行路径

- shared schema 限制 instance ID 字符集/长度、状态枚举和上下文字符数；浏览器持久化对新字段同样校验。
- 服务端新注解按捕获 ID 检查重复，允许同源不同实例；旧注解用页面、源码及 DOM 证据组合识别重复，不再只按源码坐标。
- 源码仍逐目标通过 registry 授权。实例字段属于不可信浏览器证据，不能影响可读写路径。
- 授权、冻结、Session、Ask 转 Change、外部交接全部保留 instance。
- 复制 Prompt、内置修改 Agent、配置 Key Ask 的正常与压缩路径均保留完整实例证据和定位。预算不足时明确拒绝构造，不静默丢失区分实例的信息。
- Managed Ask / 外部交接复用 envelope；逐条检查其序列化路径，不能仅以类型兼容推断实际保留。
- Agent 指令明确：同源目标可能是不同实例；只有源码读取可去重，目标要求不可合并；位置不是业务 ID；涉及单实例修改时检查共享组件影响范围，证据不足应说明。

## 7. 包边界与组织

| 所在包 | 改动职责 |
| --- | --- |
| shared | 实例模型、常量、严格 schema、共享提示规则 |
| runtime/collectors | 唯一 DOM locator；复用 DOM 采集的局部实例上下文 |
| runtime/state | 捕获与生命周期的独立小模块；不再增加控制器内重复算法 |
| runtime/controller | 组合选择、状态、UI 与现有工作流 |
| runtime/prompt、ui | 保留证据、预算失败语义与双语状态 |
| dev-server | 实例去重、源码授权后保留字段 |
| agent | 修改/问答 Prompt 的证据保留和范围规则 |
| vite / astro / next | 使用共享 Runtime，补实际 fixture/验收，不复制选择实现 |

不新增框架专用实例包，不读新增 Fiber 私有字段，不增加模型调用，不修改源码标记格式，不给宿主 DOM 注入人工实例属性，不重建 data-flow 的组件归属模型。

## 8. 验收计划

先建立能在基线上失败的回归，再实现：

1. 同源 20 张卡片，点第 7 张的同名按钮；Prompt 同时含正确路径、该卡片内容、独立捕获 ID。
2. 同时选第 3/7 张，各有要求；第三次点第 3 张只聚焦原目标；服务端接受两实例并拒绝重复捕获。
3. 重复 test ID、重复 DOM id、无 ID、深层嵌套、同祖先源码降级、未知框架 DOM、SVG，不能误报 locator 唯一。
4. 同一节点重排仍指向原节点；卸载/替换/HMR/虚拟列表文本或属性复用，不把原目标迁移到新记录。
5. 点击后立即变更、提交前尚未派发的 mutation，不能采到或提交成新记录。
6. reload/跨页恢复保留两个同源快照并标记 restored；新页面选择不与旧快照合并。
7. 脱敏、预算、schema、冻结、Prompt 普通/压缩、Ask/Change/外部 envelope 都保留实例区分。
8. 浏览器覆盖 React + Vite、原生 Astro 重复模板，Next 公共 Runtime 接入；验证包内联一致性与生产无残留。
9. 运行相关单测、类型检查、lint、构建和可用的真实浏览器测试。记录实际执行命令、结果、环境与未验证项，不宣称真实模型成功率。

## 9. 实施与验收记录

### 已实施的设计调整

- 服务端对实例文本脱敏后重新限制字段长度，防止短值替换成 `[redacted]` 后超过协议预算；授权回归同时验证清洗、不可变性与最终字段上限。

- 全套浏览器回归发现 Framer Motion 的 style 动画会令实例立即失效，甚至来不及完成 CSS 采集。调整为忽略纯 style 属性的身份失效判断，同时继续刷新高亮几何；业务提示、其他属性、文本、替换仍触发失效，并添加专项单测。

- 历史状态同时展示在目标列表和诊断摘要；不把失效绑定继续展示为 Ready。
- 点击同步采集实例证据，复制前重新构造 Prompt 并消费尚未派发的 mutation records，避免预览之后节点复用导致状态仍显示 captured。
- Next 验收使用公开 CLI + 正式完整接入配置，分别启动 Webpack / Turbopack；夹具依赖均链接仓库锁定的安装版本，不新增框架运行时实现。
- 新逻辑初次构建实测 Vite 核心 51,635 bytes gzip、Astro 核心 55,422 bytes gzip，超过原 50 / 54 KiB 门槛。为同步实例采集、验证 locator、生命周期和状态提示保留受控成本，将门槛调整为 52 / 56 KiB；与测试中既有 macOS Node 26 测量记录相比增加约 2.7 KiB。Ask / Agent / 动效仍为独立包，未引入 Node-only 依赖；最终体积见下方验收表。
- JSDOM 27.4.0 实测对重排后的 `nth-of-type` 查询存在缓存表现；单元测试断言真实 DOM 顺序和原始快照，真实 Chromium 则检查重排后的高亮几何位置，避免以模拟 DOM selector 行为作为唯一依据。

### 可复现演示

1. `pnpm build` 后运行 `pnpm --filter @spotpatch/playground dev`，在 “Repeated component instances” 区域查看 20 张同源卡片。
2. 选择 Product 3 的 Edit，填写只修改该记录的要求；追加 Product 7 的 Edit，填写另一要求；再次选择 Product 3 应仍只有两个目标。
3. 预览 Prompt，核对两个不同捕获 ID、各自 Product 内容和独立 selector。夹具故意重复使用 DOM ID / test ID，以检验不能把重复属性误当成唯一定位。
4. 返回编辑，点击 Reverse cards：高亮跟随原节点。点击 Recycle product 3：原目标显示内容已变化，原 Product 3 证据仍保留，不会被覆盖成 Product 103。
5. 原生 Astro 演示为 `pnpm --filter @spotpatch/compat-astro7 dev` 的 `/models/repeated/`。刷新后旧目标必须标记 restored，重新选择建立新捕获。
