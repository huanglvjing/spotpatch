# 上下文问答：实仓审计与能力矩阵

## 审计结论

当前失败不是模型“不会回答”，而是端到端领域契约只有 Change：输入必须是逐目标修改说明，Prompt 要求编辑，执行器必须创建可写隔离区，首次纯文本会被判定工具能力不足，结果 Schema 只有 Diff/files/checks。仅修改 system prompt 或放宽一个校验无法形成安全 Ask。

## 当前代码事实

| 位置 | 当前事实 | 对 Ask 的影响 |
| --- | --- | --- |
| `packages/shared/src/model/annotation.ts` | `SpotTargetContext.instruction` 必填；注释明确每个 target 拥有 requested change | 选择与修改意图耦合，问题没有合法载荷 |
| `packages/shared/src/protocol/requests.ts` | `agentJobCreateRequest` 只接受 `SpotAnnotation v3`、apply mode、Provider 和写流程同意 | 没有 Ask endpoint 或 task discriminator |
| `packages/agent/src/engine/agent-prompt.ts` | system prompt 明确要求 editing code，包含写工具和 checks 规则 | 问题会被重写为修改任务 |
| `packages/agent/src/engine/execute-agent-change.ts` | 开始即创建 isolated Git worktree；首个无工具响应抛 `MODEL_TOOL_CALL_UNSUPPORTED` | 纯答案必然失败且承担无意义 Git 成本 |
| `packages/agent/src/engine/execute-agent-change.ts` | 终态收集 change-set、required checks、Diff、hash 和 PreparedChange | 没有“答案成功”分支 |
| `packages/agent/src/managed/managed-execution.ts` | managed pipeline 审计变更；零 Diff/不合格变更按 validation failure 处理 | `managed-apply-v1` 不能承载只读问答 |

| `packages/shared/src/protocol/external-agent-control.ts` | 唯一 managed profile 是 `managed-apply-v1`，结果只有变更与检查 | 必须增加独立 ask profile/result，而非扩宽现有 profile |
| `packages/bridge/src/active/codex/executable.ts` | Schema Gate 只要求 `turn/started`、`turn/completed` | 当前未证明答案 item 事件可用 |

| `packages/runtime/src/state/selection-session.ts` | SessionStorage 保存 selection 和逐目标 instruction | 可复用跨页面选择，但首阶段不能误当问答历史 |
| `packages/runtime/src/ui/runtime-view.ts` | 一个持续 Shell 已承载选择、Agent、外部 Handoff 和数据链路扩展 | Ask 应增量注册 Scene/Panel，不能创建第二浮层 |

## 可复用资产

可以复用但必须保持窄接口：

- Source marker、Source Registry、React/DOM/CSS/code context 和跨页面 selection 采集；
- Provider profile、Secret Resolver、SSE/JSON parser、模型选择、远程数据同意和 Abort；
- `read_file`、`search_text`、`list_files` 的路径校验、保护文件、大小限制和输出清洗；
- dev-server Job manager 的事件、取消、TTL 和 loopback/cookie/Session 防护模式；
- Codex executable realpath、版本/Schema Gate、JSONL client、配置隔离、auth/model 诊断和 thread cleanup journal；
- Runtime extension、持续 Shell、Execution Island、双语消息、open-editor 和安全 DOM primitives。

不得复用为 Ask 语义的部分：

- `SpotAnnotation v3` 的必填 instruction；
- `executeAgentChange`、PreparedChange、Git worktree/change-set/check/apply/revert；
- `managed-apply-v1` grant、writable snapshot 和 managed result；
- 外部 Handoff 的“发送修改说明”产品文案；
- “turn completed = answer ready”的推断。

## 官方能力复核

本节最近复核于 2026-09-01。产品能力易变；官方文档只能证明协议存在，SpotPatch 支持声明仍必须绑定锁定版本、生成 Schema 和真实 E2E。

### Codex App Server

[Codex App Server 官方文档](https://developers.openai.com/codex/app-server/)确认：

- `item/agentMessage/delta` 可流式传递 assistant 文本；`item/completed` 中最终 `agentMessage { id, text, phase? }` 是权威 item，`phase` 可区分 `commentary` 与 `final_answer`；
- `turn/completed` 只给出 completed/interrupted/failed 终态，不能替代答案 item；
- `turn/start.outputSchema` 可对当前 turn 施加结构化输出约束；
- `sandboxPolicy.type = readOnly` 支持只读模式，当前官方文档还描述 restricted readable roots；
- thread 默认可持久化，`thread/delete` 才是删除持久记录的明确方法；ephemeral 行为仍须按锁定版本 Schema/POC 验证；
- `thread/shellCommand` 在 sandbox 外运行，必须永远不进入 Ask adapter 的可调用端口。

2026-09-01 的 Q1 POC 进一步确认：本机 `codex-cli 0.151.0` 生成 Schema 具有 `outputSchema`、final `agentMessage`、ephemeral thread、经典 `readOnly` 和命名 permission selector，但经典 `readOnly` union **没有**官方页面当前展示的 restricted-roots 字段。真实回合通过独立 `spotpatch-ask-readonly` permission profile 证明了 projection read、root read deny、write deny、空 hooks/MCP/instructions、结构化答案和 ephemeral 不持久化。因此协议可行，但生产 parser/adapter 仍未实现，且必须按锁定版本 feature-detect，不得发送 Schema 不存在的字段。

### Claude Code Channels

[Claude Channels](https://code.claude.com/docs/en/channels) 与 [Channels Reference](https://code.claude.com/docs/en/channels-reference)确认：Channel 当前是 Research Preview、只在会话打开时接收事件；两向 Channel 通过普通 MCP reply tool 把文本发回外部系统。SpotPatch 当前 Channel 已声明 tools，但只有 lifecycle result tool，新增有界 `spotpatch_submit_answer` 在官方模式上可行。

由于 Channel 没有通用 notification ACK、组织策略可阻断、reply tool 是否调用取决于宿主，本能力必须单独做 sender/cursor、重复/迟到结果、版本和真实会话 Gate。首阶段不启用 Claude answer return。

### Cursor

[Cursor CLI Output Format](https://docs.cursor.com/en/cli/reference/output-format)确认 `--print --output-format json|stream-json` 可返回聚合 `result`、assistant deltas、session/request ID；[Cursor CLI Parameters](https://docs.cursor.com/en/cli/reference/parameters)同时说明 print mode 拥有包括 write/bash 在内的工具。官方 MCP 文档只证明 Cursor 能消费 MCP，不能证明一个已打开 IDE 对话会主动调用 SpotPatch 回传工具。

因此 Cursor 后续有两条候选路径：Inbox + 显式 result tool，或受控 CLI read-only runner。两者都未完成权限 POC，首阶段保持不支持，不能仅靠 Prompt“不要写代码”声明安全。

## 目标能力矩阵

| 执行器 | 首阶段 | 答案回 SpotPatch | 写入隔离 | 历史 | 发布前证据 |
| --- | --- | --- | --- | --- | --- |
| Configured Key | required | 严格 submit-answer tool | 工具集合物理无写工具 | 当前 Job 内存 | fake provider + 两协议 + secret/越权/零写 E2E |
| Managed Codex | required | final `item/completed.agentMessage` + outputSchema | 独立只读源码投影 + readOnly sandbox | 新 thread，终态删除 | 锁定版本 Schema、负向权限、真实双 Job、清理故障注入 |
| Claude Channel | later | 两向 MCP answer tool | 依赖宿主，需独立只读策略 | 运行中会话 | Research Preview 版本/组织策略/迟到回传 E2E |
| Cursor Inbox | later | MCP result tool 或 CLI JSON | 当前未证明 | 当前 handoff | 官方入口 + read-only 权限 + IDE/CLI 真实合同 |
| Generic MCP | later/optional | 只能显式 tool 回传 | 宿主自有 | Inbox TTL | 不宣传主动推送，明确证据等级 |

## 根因修复判定

若实现仍满足任一条件，则根因没有被修复：

- Ask 请求仍构造 `SpotAnnotation` 并伪造 instruction；
- Ask 调用 `executeAgentChange`，只是在零 Diff 时放行；
- Managed Codex Ask 使用 `managed-apply-v1` 或 workspace-write；
- 浏览器从 Markdown/路径字符串猜测引用；
- Codex 只看 `turn/completed` 就显示“答案已返回”；
- Ask/Change 由关键字分类自动决定；
- Claude/Cursor 未有回传证据却出现在可用列表。
