# Next.js 安全与生产隔离

## 增量威胁模型

既有文件、会话、Provider、Agent、Git 和脱敏规则不因框架改变 (见 doc-id:09-local-protocol-security)、(见 doc-id:16-ai-agent-execution)、(见 doc-id:17-model-provider-credentials)。Next 适配新增以下攻击面：

| 攻击面 | 风险 | 强制处理 |
| --- | --- | --- |
| external rewrite | 公共前缀被业务路由/Proxy 劫持，header 或流被改变 | 保留前缀冲突检测、端到端协议测试、fail-fast |
| Sidecar 随机端口 | 恶意本地页面探测或 DNS rebinding | loopback、两类高熵凭据、Host/Origin/Fetch Metadata、无 CORS |
| Loader 内部注册 | 浏览器或业务代码注册任意绝对路径 | 非公开路径、独立 internal secret、real root 与文件授权 |
| Next 多 worker/cache | 凭据写入 Loader option、cache 或 map | secret 只在进程环境/内存，产物扫描禁止出现 |
| RSC/server compile | marker 意外进入生产 HTML/RSC | phase 层不注册 transform，生产扫描 HTML/RSC/chunk |
| instrumentation-client | hook/client import 进入生产 bundle | 生产 noop alias + tree shaking +产物字节扫描 |
| Next LAN dev | 页面从其他设备调用本机 Sidecar | Sidecar 永远 loopback；LAN 支持需独立 ADR，首版不继承 Vite allowLan |
| 配置多次求值 | 重复 Sidecar、重复 Loader、token 漂移 | CLI 单一 owner、包装幂等、握手 session 固定 |

## 开发期最小暴露

- Sidecar 不绑定 Next 的对外 host，不因为 `next dev -H 0.0.0.0` 自动允许 LAN。
- Next rewrite destination 只来自 CLI 受控握手，用户配置、浏览器、模型和环境文件不能提供任意代理 URL。
- 内部环境变量使用包私有前缀、运行后删除不必要副本，并禁止任何 `NEXT_PUBLIC_` 名称。
- 浏览器 bootstrap 只返回运行所需的非敏感字段；真实 provider URL/模型/Key/root/命令仍禁止。
- Source Registry 只接受 Loader 内部登记；公共浏览器接口不能提交相对或绝对路径绕过 fileId。
- Next app 的 Server Action、Route Handler、Proxy 和业务 API 与 SpotPatch 公共前缀完全隔离。

## 生产零残留

生产要求不是“功能关闭”，而是发布产物中不存在可识别能力：

- 不启动 Sidecar、Agent、Git、provider、编辑器或 source registry。
- 不执行 source Loader，不产生 marker。
- HTML、RSC payload、Flight data、JS/CSS chunk、source map、route manifest、server output、standalone output和静态导出不含 marker 属性、公共 API 前缀、SpotPatch Runtime UI、session/internal 环境名或 bootstrap 代码。
- `@spotpatch/next/client` 在生产解析为 `sideEffects: false` 的空实现并被消除；若构建器仍保留可识别 import/模块字符串，则零残留测试失败。
- `next start` 不注册公共 rewrite；保留前缀返回宿主原本的 404/路由结果，不能有 SpotPatch envelope。
- 生产构建不得读取 AI Key。测试使用 getter/哨兵保证任何读取都会失败，而不是只扫描最终 bundle。

仅在代码中写 `if (process.env.NODE_ENV !== "production")` 不足以证明零残留；phase 配置、noop alias、tree shaking 和最终产物扫描必须同时成立。

## Cache 与持久化

- `.next/cache`、Turbopack filesystem cache、webpack cache 不得保存 session token、internal secret、provider Key、绝对 worktree 路径或 Prompt。
- Source map 可以包含业务相对 source 与内容，但不能包含认证信息或 Sidecar 内部路径；其生产生成遵循宿主配置，SpotPatch 不额外开启。
- Sidecar Registry/Job/能力探测只在内存；CLI关闭后失效。
- 如果为性能必须写开发 cache，需单独 ADR、明确路径、文件权限、清理和泄漏测试；首版默认禁止。
- Service Worker/浏览器 Cache Storage 不得缓存 bootstrap/Job；所有公共响应 `no-store`。

## 配置与供应链

- `@spotpatch/next` peer dependency 约束 Next 范围，启动时读取实际安装版本并再次验证；不按 lockfile 文本猜测。
- 调用本地 Next binary，不执行 `npx next` 的自动下载路径。
- Loader/CLI/Client exports 明确，禁止消费者导入内部 secret/server模块。
- 新的 compiler/dev-server/next 包进入同一 publint、类型、provenance 和依赖闭包检查。
- 初始化器不修改 `.env`、lockfile之外的依赖版本、业务组件或 Git 状态；所有写入有预检、幂等和差异预览。

## Fail-open 与 Fail-closed

| 故障 | 策略 |
| --- | --- |
| AST parser、source map、普通模块 transform | fail-open：返回业务原代码，警告一次 |
| 路径/root/internal auth/公共 token/Origin/schema | fail-closed：拒绝请求，不产生伪 marker/结果 |
| Sidecar启动、自检或 rewrite 冲突 | fail-fast：不启动 Next 半成品接入 |
| React Adapter/Fiber | 降级：保留 marker、DOM/CSS、Prompt |
| bootstrap | Runtime 禁用且不影响页面；显示确定诊断 |
| provider/Agent | 核心选择与 Prompt 可用，AI 显示精确错误 |
| production 残留测试 | 阻断发布，不允许 warning 放行 |

## 安全验收增量

- 浏览器不能直接访问 internal registration。
- 错误 internal secret、session token、Origin、Host、方法和 body 全部拒绝。
- rewrite 不允许把保留前缀代理到用户给定地址。
- Sidecar只监听 loopback；Next LAN 地址无法从其他设备越过该边界。
- Loader cache、`.next`、日志、map、浏览器 bundle 与生产产物敏感信息泄漏为 0。
- App/Pages/RSC/webpack/Turbopack 都满足生产 marker/API/Runtime 残留为 0。
- 崩溃、Ctrl-C、HMR 和重复启动后无遗留 Sidecar端口、活动 worktree 或可用旧 token。
- 初始化器在 dirty/复杂/冲突配置下不会部分覆盖文件。
