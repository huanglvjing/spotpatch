# 组件数据链路领域模型、本地协议与配置

> 当前 Beta 契约已经进入 `@spotpatch/shared`、dev-server 和 Runtime，但尚未发布。本文解释已实现协议；TypeScript/Zod 的唯一可执行事实源仍是 `packages/shared/src/model/data-flow.ts` 与 `packages/shared/src/protocol/requests.ts`。完整目标与当前差异见 (见 doc-id:data-flow-13-beta-implementation)。

模型服务于包边界、归属、观测和数据来源 (见 doc-id:data-flow-03-architecture-packages)、(见 doc-id:data-flow-04-static-attribution)、(见 doc-id:data-flow-05-runtime-observation)、(见 doc-id:data-flow-06-data-provenance)；AI context 是独立 Schema (见 doc-id:data-flow-09-ai-assistance)，所有具体预算只在 (见 doc-id:data-flow-10-security-performance) 维护。

## 建模原则

- 执行状态、证明状态、关联类型和新鲜度相互独立，禁止塞进一个“confidence”字符串。
- report 是不可变、可序列化、已清洗 DTO；不含 DOM、Fiber、Function、Request、Response、Error、绝对路径或原始 stack。
- observation 是浏览器内存事实；静态 report 来自 Node。Runtime 用 ID 合并，不把 observation 原值发回 Node。
- 每个数组、字符串、递归深度和响应体都有 Zod 上限；TypeScript 类型不能替代运行时验证。
- Schema version 只在不兼容时递增；新增 optional 字段仍需兼容测试和 Changeset 判断。

## 正交状态

```ts
type ExecutionState =
  | "observed"
  | "declared-not-observed"
  | "not-applicable"
  | "unknown";

type ProofState = "proven" | "candidate" | "unavailable" | "conflict";

type AssociationKind =
  | "direct"
  | "transitive"
  | "upstream"
  | "possible"
  | "unassigned"
  | "unknown";

type FreshnessState = "current" | "stale-source" | "stale-route" | "expired";
```

只有 `proof=proven` 且 association 为 direct/transitive/upstream 才计入“已确认相关接口”。`observed` 只证明执行，不自动证明组件归属。

## Evidence

```ts
interface EvidenceRef {
  readonly id: string;
  readonly kind:
    | "source-anchor"
    | "import-resolution"
    | "symbol-edge"
    | "trigger-edge"
    | "call-edge"
    | "data-binding"
    | "adapter-rule"
    | "runtime-observation"
    | "runtime-reference"
    | "diagnostic";
  readonly source?: EvidenceSourceRef;
  readonly adapter?: { readonly id: string; readonly version: string };
  readonly summaryKey: DataFlowMessageKey;
}

interface EvidenceSourceRef {
  readonly fileId: string;
  readonly displayPath: string;
  readonly line: number;
  readonly column: number;
  readonly sourceVersion: string;
}
```

`displayPath` 是服务端授权后的相对展示文本；所有读取/打开操作只接受 fileId + line/column。

## 报告模型

```ts
interface ComponentDataFlowReport {
  readonly schemaVersion: 1;
  readonly reportId: string;
  readonly baseline: AnalysisBaseline;
  readonly capability: DataFlowCapability;
  readonly component: ComponentIdentity;
  readonly dependencies: readonly DataDependency[];
  readonly evidence: readonly EvidenceRef[];
  readonly diagnostics: readonly DataFlowDiagnostic[];
  readonly completeness: ReportCompleteness;
}

interface PageDataFlowReport {
  readonly schemaVersion: 1;
  readonly reportId: string;
  readonly baseline: AnalysisBaseline;
  readonly capability: DataFlowCapability;
  readonly dependencies: readonly DataDependency[];
  readonly evidence: readonly EvidenceRef[];
  readonly diagnostics: readonly DataFlowDiagnostic[];
  readonly completeness: ReportCompleteness;
}

interface AnalysisBaseline {
  readonly registryEpoch: string;
  readonly analyzerVersion: string;
  readonly adapterSetHash: string;
  readonly analyzedSourceVersions: readonly string[];
}

interface ReportCompleteness {
  readonly complete: boolean;
  readonly visitedModules: number;
  readonly visitedCallsites: number;
  readonly frontierCount: number;
  readonly truncatedBy?: "depth" | "modules" | "callsites" | "bytes" | "timeout";
}
```

Node endpoint 返回的 `ComponentDataFlowReport`/`PageDataFlowReport` 是静态基线：dependency 的 execution 只能是 `declared-not-observed`/`unknown`，`observationIds` 为空。Runtime merger 不修改输入对象，而是用同 sourceVersion 的内存 observation 派生一个新的同型不可变 report；只有浏览器派生结果可以出现 `observed` 和 observation IDs。这样 Node 不需要接收原始运行时数据，UI 也不会把静态声明误称为真实执行。

## Dependency 与参数

```ts
interface DataDependency {
  readonly id: string;
  readonly kind: "http" | "graphql" | "rpc" | "server-action" | "unknown";
  readonly direction: "read" | "write" | "read-write" | "unknown";
  readonly execution: ExecutionState;
  readonly proof: ProofState;
  readonly association: AssociationKind;
  readonly method?: string;
  readonly operation?: string;
  readonly url?: DataUrlDescriptor;
  readonly parameters: readonly DataParameter[];
  readonly response: DataResponseDescriptor;
  readonly origin?: RequestOrigin;
  readonly suppliedBindings: readonly SuppliedBinding[];
  readonly locationIds: readonly string[];
  readonly evidenceIds: readonly string[];
  readonly observationIds: readonly string[];
}

interface DataParameter {
  readonly path: string;
  readonly position: "path" | "query" | "body" | "header" | "cookie" | "variable" | "form" | "unknown";
  readonly type?: string;
  readonly source?: ParameterSource;
  readonly condition?: string;
  readonly sensitive: boolean;
  readonly valueState: "not-collected";
  readonly evidenceIds: readonly string[];
}
```

模型故意没有 `value?: unknown`，当前也没有不可达的 `DataShape`/`shape-only` 占位契约。首发不允许通过类型漏洞把原始值或未实现的响应 shape 塞进 DTO；参数类型来自静态代码，响应只表达源码消费字段。

## Observation DTO

```ts
interface NetworkObservation {
  readonly schemaVersion: 1;
  readonly id: string;
  readonly pageEpoch: string;
  readonly routeEpoch: string;
  readonly requestCallsiteId?: string;
  readonly invocationId?: string;
  readonly componentSourceId?: string;
  readonly sourceVersion?: string;
  readonly transport: "fetch" | "xhr";
  readonly method: string;
  readonly url: SanitizedObservedUrl;
  readonly outcome: "dispatched";
  readonly freshness: FreshnessState;
  readonly diagnosticIds: readonly string[];
}
```

浏览器 store 可以保存该 DTO；不得附加 raw URL、body、headers、stack 或对象引用。Axios 最终通过浏览器 XHR/fetch transport 被观测，不伪造独立 `axios` runtime transport。WeakMap provenance 是私有临时结构，不属于 DTO。

## Capability

```ts
interface DataFlowCapability {
  readonly enabled: boolean;
  readonly staticAnalysis: "available" | "partial" | "unavailable";
  readonly runtimeObservation: "dispatch-only";
  readonly responseShape: "consumed-fields-only";
  readonly aiAssistance: "disabled";
  readonly reasons: readonly DataFlowCapabilityReason[];
}
```

当前 capability 只允许实际交付值，不为 safe JSON、settle 观测或 AI 预留看似可用的联合类型。未来能力通过 Gate 后再扩展 Schema；不能只添加枚举值和 UI 文案。

## 当前 endpoint

所有 endpoint 从既有 `SPOTPATCH_API_BASE` 常量派生，使用相同 Origin、session token、loopback、JSON、`POST`、`no-store` 和统一 envelope：

```ts
const DATA_FLOW_COMPONENT_REPORT_ENDPOINT = `${SPOTPATCH_API_BASE}/data-flow/component-report`;
const DATA_FLOW_PAGE_REPORT_ENDPOINT = `${SPOTPATCH_API_BASE}/data-flow/page-report`;
```

### component-report request

接受 exact identity：

```ts
{
  schemaVersion: 1;
  componentSourceId: string;
  sourceVersion: string;
}
```

或已授权源码坐标：

```ts
{
  schemaVersion: 1;
  fileId: string;
  line: number;
  column: number;
  sourceVersion?: string;
}
```

### page-report request

只接受 `schemaVersion` 与有界 `targets` 数组，每个 target 使用上述 exact identity 或源码坐标结构。服务端从当前可信 options 决定 root、预算和 resolver，不接受浏览器提供 root、path、glob、include、depth、module list 或 adapter ID。

runtime observation 不需要上传给静态 endpoint；merger 在浏览器对 opaque ID 操作。若未来服务端 AI 需要 observation 摘要，必须使用 (见 doc-id:data-flow-09-ai-assistance) 的独立已清洗 context Schema。

## 协议限制

- request body、数组、ID 和字符串分别执行 data-flow 集中硬上限。
- 单组件和多目标聚合 report 都经过共享 collection limiter；超过集中上限时返回合法 truncated report，不返回半截 JSON 或 Schema 越界数组。
- 未启用统一返回 capability-disabled envelope，不泄露依赖和路径。
- source stale 返回稳定冲突码并要求重新分析，不猜新位置。
- adapter exception 转换为 bounded diagnostic；错误 cause/stack 不进入响应。
- analyzer 支持 AbortSignal；客户端关闭/切目标时取消无用分析。

具体数值只由 limits 常量维护一次，候选预算见 (见 doc-id:data-flow-10-security-performance)。

## 当前公共配置

保持一个入口，不暴露十几个低层 flag：

```ts
interface SpotPatchOptions {
  readonly dataFlow?:
    | false
    | {
        readonly runtime?: "dispatch";
      };
}
```

- 当前默认 `false`，避免未经选择增加 transform/runtime 成本。
- `dataFlow: {}` 解析为唯一已实现的 `dispatch`；当前不读取 Response，不暴露 `safe-json-shape` 假能力。
- data-flow AI 尚未完成准确上下文与证据回验，因此不公开无行为的 `aiAssistance` 开关，capability 固定为 disabled。
- 不提供 `raw-values`、`includeSecrets` 或扩大硬上限的开关。
- `.js/.jsx/.ts/.tsx` 是集中维护的 data-flow 支持扩展集合；不会改变现有 intrinsic marker include，也不会扩大 sourceRoots。

如果需要项目专用 client 支持，应优先从 `axios.create`/import binding 自动解析。未来公开 binding descriptor 前必须先有跨项目需求和安全 Schema，不能为 `shengsuanyun-web` 硬编码路径、变量名或域名。

## 默认值与硬编码治理

- 用户默认值只在 `resolveOptions` 的 data-flow 子 resolver 装配一次并 deep-freeze。
- 浏览器安全配置由 serializer 白名单投影；Node-only sourceRoots/adapter details 不序列化。
- hard limits 使用命名常量和表驱动测试，不在 recorder、handler、UI 各写数字。
- endpoint、message key、diagnostic code、adapter ID 使用 `as const` 集合 + Zod enum/type 派生。
- 目标项目 URL、文件路径、Store 名称、字段名只存在 fixture/manifest，不能进入产品代码。

## 错误与诊断码族

诊断前缀：

- `DATA_FLOW_CAPABILITY_*`
- `DATA_FLOW_SOURCE_*`
- `DATA_FLOW_ANALYSIS_*`
- `DATA_FLOW_OBSERVATION_*`
- `DATA_FLOW_REDACTION_*`
- `DATA_FLOW_AI_*`

每个 code 映射一个类型化双语 message key、是否可重试、用户动作和内部诊断类别。错误消息不拼接绝对路径、URL value、body、stack 或 secret。

## 版本与迁移

- 当前 report 与 observation 都显式携带 `schemaVersion: 1` 并由 shared 严格校验；未来 AI context 使用独立 Schema，不能复用 report DTO 偷渡字段。
- Runtime 对未知 major/version fail closed：保留现有 SpotPatch 功能，禁用 Inspector 数据投影。
- HMR sourceVersion 不兼容不是 Schema 版本变化；通过 freshness 表达。
- 公共选项/API 变更遵循 Changeset；内部 adapter fixture 更新不自动构成公共 breaking change。
