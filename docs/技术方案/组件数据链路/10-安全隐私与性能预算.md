# 组件数据链路安全、隐私与性能预算

本页约束 runtime、数据来源、协议与 AI (见 doc-id:data-flow-05-runtime-observation)、(见 doc-id:data-flow-06-data-provenance)、(见 doc-id:data-flow-07-model-protocol-config)、(见 doc-id:data-flow-09-ai-assistance)，并增量复用现有本地安全和全仓验收 (见 doc-id:09-local-protocol-security)、(见 doc-id:12-testing-acceptance)。

## 安全目标

该功能会接触接口元数据、字段名和运行时请求事实，敏感度明显高于 DOM/CSS 采集。设计采用：**源头不采集、最小结构、内存短驻留、显式远程发送、生产零残留**。

既有 session token、Origin、loopback、Content-Type、统一错误 envelope、realpath/sourceRoots、保护文件和 AI provider 信任规则继续生效。本页只定义 data-flow 增量要求，不削弱 (见 doc-id:09-local-protocol-security)。

## 威胁模型

| 威胁 | 风险 | 控制 |
| --- | --- | --- |
| 请求含 token/password/PII | UI、日志、AI 泄漏 | 在 observation store 前清洗；多数值根本不读取 |
| URL 含签名或用户数据 | path/query 泄漏 | 结构化 URL sanitizer、敏感 segment/query value 删除 |
| Response/props 是 Proxy/getter | 读取会执行业务代码或抛错 | 当前不读对象/结果；未来 result tap 必须另过 Gate |
| recorder 改变 fetch/XHR | 宿主故障、时序变化 | 保持 identity/返回/事件；差分测试；异常 fail-open |
| 恶意页面伪造全局 metadata | 错误报告或读取接口 | opaque ID 仍由 Registry 验证；浏览器不能扩权 |
| 浏览器提交任意文件/root | 任意源码读取 | endpoint 只接受已登记 fileId/opaque IDs |
| 项目源码 prompt injection | AI 越权 | 源码/字段均视为不可信；只读 allowlist、Schema 输出 |
| AI 猜测被当事实 | 错误归属 | AI 输出与系统 report 隔离；证据引用校验 |
| HMR/SPA 复用旧数据 | 错误上下文 | page/route/session/source epoch 与 stale 状态 |
| 内存记录无界增长 | 页面卡顿/敏感数据久留 | 条数、字节、TTL、clear/dispose 硬上限 |
| 生产误带探针 | 性能/隐私风险 | build-time noop + 产物字符串/模块扫描 |

## 信任边界

- 浏览器页面、项目源码、request/response、DOM/Fiber 和模型输出都是不可信输入。
- Vite Node/Sidecar 只有在 session、Origin 和本地绑定规则通过后才是受控服务边界。
- Registry 的 fileId/opaque source ID 是授权句柄，不是浏览器可自由构造的路径。
- invocation/callsite ID 用于一致性和归属，不是密码学身份；恶意业务代码可以破坏自身观测。首发保证受支持、非对抗性开发代码的准确性，不声称抵御蓄意篡改的应用。
- 外部 AI provider 是独立信任域，只有用户显式同意后接收已清洗内容。

## 数据分类

| 等级 | 示例 | 本地 UI | Node 协议 | AI |
| --- | --- | --- | --- | --- |
| D0 低敏元数据 | method、清洗 path、opaque ID、dispatch 状态 | 是 | 有界 | 显式同意后 |
| D1 项目结构 | 相对路径、组件/字段/Store/key 名、URL template | 是 | 已授权 | 显式同意后 |
| D2 源码摘要 | call path、source expression、受限片段 | 是 | 按 fileId 读取 | Assist Find 明确授权 |
| D3 禁止数据 | secret、密码、token、Cookie 值、完整 body/response、storage 值、绝对路径、连接串 | 否 | 否 | 否 |

D1/D2 仍可能包含商业敏感信息，所以不自动远程发送。header/storage 的 key 名可用于本地解释；若 key 本身呈现高熵 secret 模式，则替换为 redacted key descriptor。

## 永不采集或返回

- Authorization、Proxy-Authorization、Cookie、Set-Cookie 的值。
- API key、token、secret、password、credential、session、captcha 常见变体的值。
- 原始 request body、GraphQL variables、response body、runtime props/state/store/cache/storage 内容。
- File、Blob、ArrayBuffer、stream 内容。
- `.env*`、密钥文件、连接字符串、数据库 host/用户名/密码。
- 原始 Error stack、Fiber、DOM、Request/Response/XHR 对象。
- 绝对路径和 provider 凭据/真实 transport 配置。

不允许提供 `debugRaw`、`includeSecrets`、`showValues` 等逃生开关。

## 采集点清洗

### URL

URL 解析失败时不保留原字符串，只记录 invalid-url diagnostic 和长度 bucket。成功时：

- protocol/method 校验后保留。
- authority 中 userinfo 永久删除。
- query 仅保留安全 key 和 presence/type，value 删除。
- fragment 删除。
- path 以静态 template 为首选；observed 动态 segment 经 allowlist/type classification，不满足则用 `:dynamic`。
- signed URL、JWT/base64/高熵/超长 segment 和配置命中的敏感名称整体替换。

### 参数与响应

- 参数来自 AST key/source；runtime body 不做通用深遍历。
- 当前 ring buffer 不生成 JSON shape，不接触 body/Response/props/state/store/storage 对象。
- key 命中敏感词时只保留 key 与 `sensitive=true`，始终不读取 value。
- 静态类型与 consumed field 来自源码语义分析，不从运行时值反射。

### 日志与错误

新增命名空间沿用 `[spotpatch:transform]`、`[spotpatch:server]`、`[spotpatch:runtime]`；adapter 可在结构化字段写 `subsystem=data-flow`，不创建无治理日志体系。debug 只记录计数、耗时、opaque ID、状态码和 diagnostic code，不记录 endpoint query/path 动态值、字段 value、源码、AI context 或绝对路径。

## 本地协议与源码

- 只接受 `POST application/json`、session token、允许 Origin；响应 `Cache-Control: no-store`。
- fileId/source IDs 必须属于当前 registry/session/sourceRoots；过期 ID 返回 stale。
- 浏览器不能控制 resolver、adapter、深度、超时、root、glob 或文件列表。
- analyzer 不执行项目代码、配置、package script、数据库 client 或网络请求。
- symlink/realpath、保护文件、大小、普通文件和 root 边界复用现有单一安全 helper，不复制一套 data-flow 文件读取器。
- 分析缓存不包含源码全文和 runtime observation，session 结束释放。

## 页面注入风险

- prelude 只在明确 development + enabled 构建存在；不能依赖运行时 `NODE_ENV` 隐藏生产代码。
- 全局桥按职责使用版本化 symbol：recorder Runtime 与 UI 扩展契约各一个最小入口；业务页面仍可能在同一 realm 观察它们，因此桥里没有 secret 和原始 payload。
- wrapper 只替换自有、可写的 data property；卸载通过当前函数 identity 检查，只恢复仍由 SpotPatch 持有的原 descriptor，不覆盖后来安装的第三方 wrapper。
- recorder 只在原 `fetch`/XHR 调用未同步抛错后记录 dispatch；URL getter、序列化、预算或采集异常被隔离，不阻止、不重试业务请求。当前 Beta 不伪造“采集失败 diagnostic”，因此异常条目可能缺席而不能被解释为“没有请求”。
- cross-origin iframe 首版不注入、不穿透；同源子文档只有经过独立 prelude/epoch 支持后才纳入，不能从父页面直接读取其请求对象。

## AI 安全增量

- context preview 与实际 normalized payload 同源构建；确认后任何 source/context 变化使同意失效。
- 远程同意与本地修改同意分离；data-flow explain/find 不获得写权限。
- Assist Find 只读 tool allowlist 在服务端固定，模型不能请求启用 write/run/network。
- 模型输出严格 Schema + evidence existence 验证，以安全文本 DOM 渲染。
- 任何模型提供的路径/URL/命令都只是文本，不能直接成为本地工具参数。
- provider error/cause/body/SSE 原文不回显，以稳定 code 呈现。

## 数据生命周期

| 数据 | 存储 | 清理 |
| --- | --- | --- |
| static AST/graph cache | Node 会话内存，content hash key | HMR 依赖失效、session stop |
| static report DTO | Node/Runtime 会话缓存 | source/session 变化、显式刷新/clear |
| observation DTO | document 内存 ring buffer | TTL、淘汰、unload、Start over、dispose |
| WeakMap provenance | Runtime 私有 WeakMap | GC、dispose |
| AI context/result | 当前会话内存 | Start over、session end；默认不落盘 |
| selection session | 沿用现有已清洗目标 | 不加入 data-flow observation/AI result |

## 唯一预算表

以下数值已进入 `DEFAULT_DATA_FLOW_LIMITS`，是当前 Beta 唯一默认值。实现只能从该常量/已解析 options 读取，禁止在 recorder、handler、UI、AI 和测试中复制魔法数字。后续可以收紧；放宽必须有基准、安全评审和 ADR。

| 常量字段 | 当前值 | 作用 |
| --- | ---: | --- |
| `observationMaxEntries` | 100 | ring buffer 条数 |
| `observationMaxBytes` | 256 KiB | DTO 估算总字节 |
| `observationTtlMs` | 300,000 | 最长内存驻留 5 分钟 |
| `protocolRequestMaxBytes` | 32 KiB | data-flow request body |
| `reportMaxBytes` | 128 KiB | 完整成功 envelope 序列化上限；超限返回确定性 partial 前缀 |
| `reportMaxEvidence` | 200 | 单报告 evidence/引用数组上限 |
| `reportMaxDiagnostics` | 256 | 单报告 diagnostic 上限 |
| `capabilityMaxReasons` | 64 | capability reason 上限 |
| `graphMaxDepth` | 5 | 确定调用/数据图深度 |
| `graphMaxModules` | 50 | 单报告模块数 |
| `graphMaxCallsites` | 100 | 单报告 callsite 数 |
| `analysisTimeoutMs` | 2,000 | 单次分析硬终止 |
| `reportMaxFields` | 100 | query key、参数或消费字段等报告字段数组上限 |

未实现的“观测下一次操作”、safe response shape 与 data-flow AI 不在当前默认对象中预留无行为字段；对应能力进入实现 Gate 后再以实际消费方和测试加入预算。Node 内部使用完整 `DataFlowLimits`，浏览器只接收 recorder 与报告读取所需的四个 runtime limit，图分析和协议请求预算不会无意义地下发到页面。

测试从导出常量生成边界样本；文档 lint 应检测数字漂移。UI 使用服务端返回的 resolved limits，不自己写倒计时或数量上限。

## 性能目标

| 路径 | 目标 |
| --- | --- |
| prelude 同步初始化 | Chromium p95 `< 2 ms` |
| 每次 fetch/XHR 同步采集 | p95 `< 1 ms`，不含业务请求 |
| 首次静态分析 | 锁定常规 fixture p95 `< 300 ms` |
| 内容未变缓存命中 | p95 `< 50 ms` |
| UI 打开已有报告 | p95 `< 100 ms` |
| observation 内存 | 始终不超过条数/字节双上限 |
| 核心 Runtime gzip | `< 42 KiB`；不包含 Inspector 卡片实现，并覆盖 Linux/macOS Node zlib 的实测差异 |
| data-flow prelude gzip | `< 8 KiB`，不包含 UI、Zod 或 Node-only 依赖 |
| data-flow panel gzip | `< 10 KiB`，与核心 Runtime、prelude 分开记账 |

基准分别报告 cold/warm、模块数、callsite 数和机器环境，不把缓存命中当 cold 数据，也不把 API 网络耗时计入 recorder 开销。

## 性能实现纪律

- 不在启动时扫描整个 Monorepo；从已授权目标/page entries 惰性扩图。
- compiler transform 单遍收集现有 marker 与 data-flow anchor，避免对同一 AST 重复 parse。
- prelude 不引入 Zod/TypeScript/UI；完整 validator 留在 Node，面板位于独立 opt-in 浏览器入口。
- ring buffer 只保存 plain DTO，不持有 Request/Response/Element/Fiber/业务对象。
- WeakMap 不配套强引用 key 的数组。
- route/HMR/close/dispose 清除 listeners、timer、AbortController 和无用 cache。
- 页面接口最多 100 observation，不需要无界虚拟列表；仍对字段树和详情递归做上限。
- analyzer 支持取消和增量 invalidation；目标切换取消旧请求，不让结果写回新目标。

## 生产零残留

production 或 `dataFlow:false` 的产物必须同时满足：

- 无 prelude、fetch/XHR wrapper、data-flow virtual module、endpoint、lazy UI chunk。
- 无 source/component/trigger/request 额外 ID 或 marker。
- 无 adapter registry、AI context、diagnostic/message 文本。
- 无 Node analyzer 初始化、watcher、cache 或 endpoint handler。
- 既有 SpotPatch production leakage 门禁不被提高预算或放宽扫描替代。

## 安全与性能验收

- secret corpus 在 browser heap DTO snapshot、DOM、日志、协议、fake provider 和错误中命中数为 0。
- instrumented 与 uninstrumented fixture 的 fetch/XHR/Promise/event/abort/stream 可观察行为一致。
- 超限、超时和 adapter exception 均返回 bounded diagnostic，不影响宿主。
- 连续 HMR、SPA navigation、打开/关闭 100 次后 listener/wrapper/Element/Fiber/业务对象无持续增长。
- cold/warm 基准和 bundle 报告作为 PR artifact；超过预算不能以提高常量直接修复。
