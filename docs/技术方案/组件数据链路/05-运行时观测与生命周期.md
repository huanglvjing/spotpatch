# 组件数据链路运行时观测与生命周期

组件关联只消费静态归属契约 (见 doc-id:data-flow-04-static-attribution)，shape/数据来源语义 (见 doc-id:data-flow-06-data-provenance)，安全与预算 (见 doc-id:data-flow-10-security-performance)；宿主注入与现有 Runtime 状态仍以 (见 doc-id:04-vite-plugin)、(见 doc-id:05-runtime-lifecycle) 为准。

## 观测目标与边界

运行时层用于证明“请求当次确实派发过”，记录 method、清洗后的 URL、transport 和已有 callsite/invocation provenance。它不是浏览器代理，不观测 settle/status，不读取 Response，不观测 Worker/server 请求，也不替代静态分析。

严格区分三种数据源：

| 数据源 | 能提供 | 不能单独提供 |
| --- | --- | --- |
| fetch/XHR recorder | 请求真实派发、transport、当次 method/URL | React 组件、静态未执行分支、结果状态 |
| compiler provenance frame | request callsite、invocation、component/source version | 未 instrument 的第三方请求、结果对象 |
| PerformanceResourceTiming（未接入） | 资源时序和 `initiatorType` | 业务组件或精确 callsite |

Performance API 的 `initiatorType` 只表明 `fetch`、`xmlhttprequest`、`img` 等发起机制，不能用来证明 React 组件归属。

## 安装时机

Vite Beta 通过 `transformIndexHtml` 的 `head-prepend` 注入独立最小 prelude，并已在兼容性与 E2E 宿主中验证其先于普通 client 模块。prelude 只做：

1. 建立版本化全局 owner symbol 和单例状态。
2. 安装 invocation context、fetch/XHR transport hook。
3. 建立有界内存 ring buffer。
4. 暴露窄虚拟模块桥，等待完整 Runtime 接管。

不能把完整 Inspector UI、Schema validator 或 analyzer client 塞进同步 prelude。若宿主 CSP 阻止所选 inline/classic 方案，capability 必须显示 `prelude-blocked`；在完成 CSP-compatible fixture 前不得声称从页面加载起完整捕获。

Vite 官方支持 HTML 注入顺序与 `head-prepend`，但“在目标宿主一定早于所有业务代码”仍必须由真实 HTML、模块和 CSP fixture 验证，而不是只根据 API 名称推断。[Vite Plugin API](https://vite.dev/guide/api-plugin.html#transformindexhtml)

## Recorder 核心

### fetch transport

- 只在 `window.fetch` 是可写 data property 时保存原 descriptor 并安装 wrapper；不可安全替换时保持宿主原状。
- wrapper 使用原 receiver/参数调用一次；只有原调用未同步抛错后才在同一 request frame 内存储已清洗 dispatch observation。
- 返回原始 Promise 对象，不包装成新的业务返回值。
- 默认 recorder 不主动 `clone()`/读取 Response body，也不消费 stream。
- URL getter、序列化、预算或 observation 写入失败全部隔离，不改变已取得的宿主 Promise。
- 若要观察 settle，不得通过额外 rejection handler 改变宿主 `unhandledrejection` 行为；当前因此保持 dispatch-only。

这里存在真实技术取舍：给 Promise 附加 `.then` 即使返回原 Promise，也可能改变未处理拒绝诊断；返回 chained Promise 又会改变 identity。因而当前全局 fetch/XHR recorder 只定义为**派发事实**，不宣称 success/status/duration 或运行时响应 shape。源码 consumed fields 独立来自静态分析；未来若有跨浏览器无可观察副作用的结果 tap，再通过独立 ADR 升级。

### XHR transport

- 不替换 `XMLHttpRequest` constructor；只有 prototype 自有的 `open`/`send` 都是可写 data property 时才分别安全 patch。
- 原 `open` 成功后才保存 method/URL；原 `send` 成功返回后才记录 `dispatched`。同步 `InvalidStateError` 等异常原样传播且不生成 observation。
- 不安装 `loadend`，不读取 status、responseURL、responseType、responseText、ArrayBuffer、Blob 或对象值。
- 某一个方法不可安全 patch 时，该路径可能缺少 observation；当前不会伪造 success/error/abort/timeout 状态。

### wrapper 共存

- 安装时记录上游函数；卸载时只有当前 property 仍是自己的 wrapper 才恢复上游，避免覆盖后来安装的 Sentry/MSW/其他工具。
- 当前函数 identity 是唯一恢复依据，不保留从未读取的 owner metadata，也不伪装成原始函数。
- 前装/后装 MSW、Axios interceptor 和 Sentry 风格 wrapper 均需组合 fixture。
- 多份 Runtime/HMR 通过版本化全局 Runtime symbol 复用同一实例，不叠加 patch。

## Request frame

request callsite helper 在调用实际 fetch/XHR/Axios 表达式的同步区间设置只读 frame：

```ts
interface RequestFrame {
  readonly requestCallsiteId: string;
  readonly invocationToken?: InvocationToken;
  readonly sourceVersion: string;
  readonly transportHint?: "fetch" | "xhr" | "axios";
}
```

transport wrapper 在真实 API 被调用时读取并立即复制 opaque IDs。若第三方库延迟到同步区间之外才发请求，frame 缺失；除非 adapter/编译变换显式传播，否则 observation 为 unassigned，不能按 endpoint 反补。

## 结果与 response shape tap

当前 Beta **没有 result tap**。DTO 不包含运行时 request/response shape、status、duration 或 responseType 字段；UI 只显示静态分析证明的 consumed fields。`await` 插桩用于传播 invocation/request provenance，不读取结果对象。

未来若实现 tap，必须先满足：表达式执行一次、原返回引用不变、异常原样传播、微任务/abort/stream 行为无差异、DTO 与预算真实落地。通过独立 ADR 和差分测试前，不得先加入 `safe-json` 枚举、shape 类型或无行为配置。

## Observation 模型

一次 observation 当前只记录：

- opaque observation ID、`pageEpoch`、`routeEpoch`。
- `fetch | xhr` transport、method、仅含 origin/path/query key 的 sanitized URL。
- 可选 requestCallsiteId、invocationId、triggerCallsiteId、componentSourceId、sourceVersion。
- 固定 `outcome: "dispatched"`、freshness 与 diagnostic IDs。

它不记录时间、status、duration 或结果 shape，因此这些字段既不参与归属，也不出现在公共 Schema。

当前 merger 要求 current freshness、requestCallsiteId、request sourceVersion、method 与 pathname 一致；静态 origin 已知时也必须一致。transitive 依赖还要求 componentSourceId 与 triggerCallsiteId 同时一致，导入 JSX handler 由 compiler 在每次真实调用时创建新的 trigger token。静态 origin 缺失时只接受唯一观测 origin；多个 origin 冲突则不补值。

## 页面与路由生命周期

- `pageEpoch`：document prelude 创建时生成，整页导航后变化。
- `routeEpoch`：初始 route 和每次受支持 SPA navigation 变化；旧 observation 仍可查看但默认折叠。
- `invocationId`：每次 trigger 产生；StrictMode/effect 重跑不会按 URL 自动去重。
- `sourceVersion`：HMR 变更后变化；旧记录标 stale。
- `sessionEpoch`：开发服务器/Registry 重启后变化；浏览器清空不可重新授权映射。

页面接口视图默认显示当前 route epoch，可切换“本次页面”；组件视图只自动合并 sourceVersion 可验证的记录。

## “观测下一次操作”流程

选择器现有语义会阻止宿主事件，必须保留这一安全行为。用户点击“观测下一次操作”后：

1. 保存当前目标的 opaque identity，不保存 runtime 值。
2. 暂停 inspecting overlay，按服务端下发的 resolved timeout 显示可取消倒计时。
3. 用户亲自再次执行真实操作；SpotPatch 不合成 click/submit。
4. compiler trigger instrumentation 创建 invocation token。
5. recorder 按 token 收集该 invocation 的主请求；其他并发请求留在页面接口。
6. 首个 trigger 完成或窗口超时后恢复面板，展示结果和 follow-up 分组。

窗口只改善用户体验和列表聚焦，不作为归属证据。危险动作由用户实际执行，SpotPatch 不绕过宿主确认。

## 主请求与 follow-up

同一 invocation 中可有多个请求，系统不强迫选择唯一接口：

- `primary`：触发路径上第一个或 adapter 明确的业务 operation。
- `parallel`：同一 handler 内并列请求。
- `follow-up`：成功 callback、navigation 或后续 effect 触发，保持自己的 trigger edge。
- `background`：polling/refresh；归于 mount/timer，不归于最近 click。

该分类必须来自事件/调用边或新的 invocation token；仅时间先后不足以确定 `follow-up`。

## 内存与清理

- observation 只存在当前 document 内存的有界 ring buffer，默认不进入 selection session、local/sessionStorage、IndexedDB、日志或 Prompt。
- 页面 unload、Start over、session epoch 变化、显式 clear 或 dispose 时释放。
- HMR 不重复安装；source 映射失效但原 observation 可作为 stale 页面事实短暂保留。
- 达到条数、字节或时间上限时按 oldest-first 淘汰，并保留 dropped count；预算唯一值见 (见 doc-id:data-flow-10-security-performance)。

## 运行时能力降级

prelude 未安装、CSP 阻止、wrapper 被不可配置属性占用、版本冲突或浏览器能力不足时，Runtime 仍允许静态分析和选择功能。UI 必须准确显示“运行时观测不可用”，不能把“未观测”解释为“未请求”。
