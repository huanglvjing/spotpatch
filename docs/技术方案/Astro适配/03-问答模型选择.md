# 问答模型选择

本轮范围：共享 Contextual Ask 的 Managed Codex 模型选择，不扩展修改任务的执行权限，不改全局 Codex 配置。

## 设计依据与实现

依据 [OpenAI App Server 模型发现协议](https://learn.chatgpt.com/docs/app-server#list-models-modellist)：使用 `model/list`、`includeHidden: false` 获取分页目录，以 `model` 作为提交值、`isDefault` 作为初始默认选择。不得从静态模型名单推断账户权限。

- 原先只读执行器选择仅展示默认模型，没有独立模型选择；保留执行器契约，新增可选 `models` 能力字段及可选 `model` 提交字段。
- 执行器和模型共用 `ask-picker.ts`，使用 combobox/listbox、活动选项、方向键、Home/End、Enter/Space、Escape、Tab、焦点移出及外部点击收起。菜单留在正常布局流中，限制高度并滚动，长名称可换行；忙碌时禁止变更。
- 旧执行器不返回 `models` 时不显示额外模型栏；配置 Key 继续由服务端模型档案构造执行器，不接受浏览器任意覆盖模型。
- 管理器以模型参与幂等指纹，并在分配任务前校验模型属于执行器能力目录。任务快照记录所选模型。
- Codex 执行前重新读取模型目录，显式传递 `thread/start.model`。不存在的选择失败，不回退；已有模型重路由事件继续更新结果中的有效模型。
- 分页去重、页数及模型数量/长度有界，循环游标或超限目录失败。能力缓存沿用成功 5 分钟、失败 30 秒；执行前的独立复核防止缓存内已失效模型被使用。
- Vite、Next.js、Astro 共用运行时、协议、管理器及 Codex 执行器，无框架专用模型列表。

## 验证边界

协议测试覆盖分页目录、选择透传、非法模型拒绝和循环分页；管理器测试覆盖白名单、执行参数、任务快照及幂等冲突。面板测试覆盖选择保留、旧能力兼容与忙碌锁定；浏览器测试覆盖窄屏键盘选择和实际请求字段。

真实模型目录读取不等于所有模型均已完成真实推理请求。自动测试使用受控执行器，不替用户消耗额度，也不修改业务源码。
