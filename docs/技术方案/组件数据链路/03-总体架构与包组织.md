# 组件数据链路总体架构与包组织

架构服务于需求 (见 doc-id:data-flow-01-requirements)，归属、观测和契约细节分别由 (见 doc-id:data-flow-04-static-attribution)、(见 doc-id:data-flow-05-runtime-observation)、(见 doc-id:data-flow-07-model-protocol-config) 维护；既有总体架构、编码规范和 Next 平级适配器边界继续以 (见 doc-id:02-architecture-stack)、(见 doc-id:11-coding-standards)、(见 doc-id:next-02-package-architecture) 为准。

## 设计原则

1. **确定性内核先于 AI**：编译、静态图和 runtime observation 先产出证据；AI 只解释。
2. **一个事实、一处实现**：ID、Schema、清洗、shape、recorder 和默认值各自只有一个 owner。
3. **Node 与浏览器硬隔离**：源码/文件系统/TypeScript 图只在 Node；Runtime 只持有 opaque ID 和已清洗 DTO。
4. **宿主适配器是叶子**：Vite/Next 只翻译生命周期，不复制分析器、协议和 UI。
5. **按功能付费**：小型 prelude 早装；只有显式启用 `dataFlow` 才加载 analyzer endpoint、插桩和独立 Inspector 面板包。
6. **失败开放于宿主、关闭于结论**：分析故障不影响业务页面，但不得输出无证据关联。

## 总体数据流

```text
Source modules
  → @spotpatch/compiler
      source/component/trigger/request callsite registration
      instrumentation metadata
  → framework adapter resolver/registry
  → @spotpatch/analyzer (Node-only, lazy)
      module graph + symbol graph + event graph + def-use graph
  → @spotpatch/dev-server
      authenticated read-only report endpoints + cache

HTML head-prepend prelude
  → @spotpatch/runtime/network recorder core
      fetch transport + XHR transport + invocation provenance
  → bounded in-memory observation store

selected element / current page epoch
  → static report + observations + evidence merger
  → opt-in separate Inspector UI bundle
  → optional redacted AI context builder
```

静态报告回答“源码声明和数据关系”，observation 回答“当前页面真实发生过什么”。Merger 只能按 opaque callsite/invocation/evidence ID 合并，禁止按 URL + 时间窗口直接建立确定关联。

## 包级归属

| 包 | 新增职责 | 明确不得承担 |
| --- | --- | --- |
| `@spotpatch/shared` | 数据链路 DTO、Schema、枚举、错误/警告码、纯 shape/redaction policy 类型 | DOM、Node fs、框架类型、默认值解析 |
| `@spotpatch/compiler` | `.js/.jsx/.ts/.tsx` AST 识别、source anchor、请求/触发/调用边 instrumentation | 模块 IO、Vite/Next 生命周期、运行时 recorder |
| `@spotpatch/analyzer` | Node-only TypeScript Program、符号解析、def-use、缓存和报告构建 | HTTP server、浏览器对象、provider、执行项目源码 |
| `@spotpatch/dev-server` | analyzer 生命周期、可信配置、source authorization、cache、只读 endpoint | 重写 analyzer 算法、框架私有 resolver |
| `@spotpatch/runtime` | prelude、recorder、observation store、merger、独立 UI 子入口 | fs、AST、绝对路径、凭据、模型网络调用 |
| `@spotpatch/react-adapter` | 组件语义和受限 runtime 形状增强 | 核心归属、网络 hook、原始 Fiber 序列化 |
| `@spotpatch/vite` | `head-prepend` 注入、Vite resolver/transform/serve/build 接桥 | 复制公共 analyzer/recorder/Schema |
| `@spotpatch/next` | `instrumentation-client`/Loader/Sidecar 接桥、Next 请求观测策略 | 复制公共 analyzer/recorder/Schema/panel；把 Client Component 证据扩大为服务端 dispatch 证据 |
| `@spotpatch/agent` | 复用既有 provider-independent tool loop 解释证据 | 第二套 data-flow AI 客户端或自动升级事实 |

`@spotpatch/analyzer` 已作为独立 workspace 包实现，因为 Node-only 依赖、缓存和图算法不应进入 compiler 的纯 transform，也不应塞进 dev-server handler。dev-server 只持有其窄接口，不得再保留第二份分析实现。

若采用独立包，它是和 compiler/dev-server 相同的“公共内部依赖”：必须发布以闭合 npm 依赖图，但用户仍只安装 `@spotpatch/vite` 或 `@spotpatch/next`。`A → B` 表示 A 可以导入 B：

```text
compiler ──────→ shared
analyzer ──────→ compiler + shared
dev-server ────→ analyzer + compiler + shared + agent
runtime ───────→ shared + react-adapter
react-adapter ─→ shared
vite/next ─────→ compiler + dev-server + runtime + shared
```

反向导入均禁止；特别是 shared/compiler/analyzer 不得为了 AI 解释依赖 agent/provider，runtime 不得导入 analyzer/dev-server。

## 当前 Beta 源码组织

```text
packages/
├── shared/src/
│   ├── model/data-flow.ts
│   └── data-flow-runtime.ts          # prelude 轻量子入口
├── compiler/src/
│   ├── data-flow-id.ts
│   └── data-flow-instrumentation.ts
├── analyzer/src/
│   ├── static-analyzer.ts
│   ├── request-extractor.ts
│   └── typescript-utils.ts
├── dev-server/src/server/data-flow-http.ts
├── runtime/src/
│   ├── data-flow/data-flow-runtime.ts
│   ├── data-flow/report-merger.ts
│   ├── data-flow-entry.ts             # recorder/merger 子入口
│   ├── data-flow-panel-entry.ts       # Inspector 子入口
│   └── ui/data-flow-panel.ts
├── vite/src/
│   ├── runtime-data-flow-prelude.ts
│   └── runtime-data-flow-panel.ts
└── next/src/
    ├── data-flow-runtime.ts       # pre-hydration 共享 recorder 安装
    ├── internal/data-flow-policy.ts
    └── loader.ts                  # source + data-flow 原子转换/登记
```

当前 Vite 构建把核心 Runtime、React Adapter、data-flow prelude 和 data-flow panel 产成独立浏览器入口。Next 公共预览从 `@spotpatch/runtime/data-flow-panel` 安装同一面板，从 `@spotpatch/shared/data-flow-runtime` 安装同一 recorder；只有 Loader、启动时序和 Sidecar 承载保留在框架包内。两端 `dataFlow:false` 都不激活插桩或面板，生产构建都必须通过零可执行残留扫描。Vite `dataFlow:true` 在 Runtime bootstrap 时加载面板入口，Next 在已认证 bootstrap 确认功能开启后安装共享面板；两者当前都不是点击页签后才网络加载。若未来改成交互时动态 import，必须重新验证首屏、CSP、错误状态和 E2E，不能只修改文档措辞。

以上是已落盘结构，不是预先批准未来继续拆文件。新增 adapter 或算法只有在职责确实独立时才拆分；实现必须继续控制文件规模、保持最小 export map，并用依赖测试阻止浏览器包导入 Node-only 模块。

## 窄接口

```ts
interface DataFlowCompilerHost {
  readonly registryEpoch: string;
  registerAnchors(input: RegisterAnchorInput): readonly SourceAnchorId[];
  resolveModule(specifier: string, importerFileId: string): Promise<ResolvedModule | null>;
}

interface DataFlowAnalyzer {
  analyzeTarget(input: AnalyzeTargetInput, signal: AbortSignal): Promise<ComponentDataFlowReport>;
  analyzePage(input: AnalyzePageInput, signal: AbortSignal): Promise<PageDataFlowReport>;
  invalidate(change: SourceChange): void;
  dispose(): Promise<void>;
}

interface NetworkRecorder {
  start(config: RuntimeRecorderConfig): RecorderHandle;
}

interface RecorderHandle {
  snapshot(query: ObservationQuery): readonly NetworkObservation[];
  clear(reason: ObservationClearReason): void;
  dispose(): void;
}
```

接口只接受已经授权的 fileId/source ID 和有界 query；浏览器不得提交任意绝对路径、root、glob、分析深度或 adapter 名称。

## Adapter 设计

适配器是纯识别/提取器，由中央 registry 按已解析 import symbol 匹配，不允许各模块散落字符串判断：

```ts
interface DataFlowAdapter {
  readonly id: DataFlowAdapterId;
  readonly apiVersion: 1;
  supports(context: AdapterProbeContext): boolean;
  contribute(context: AdapterAnalysisContext): AdapterContribution;
}
```

- `supports` 不执行用户代码，只检查解析后的 package/symbol/version。
- 每个 adapter 必须有 package version range、正例、同名负例、边界与 golden report。
- adapter 只能贡献标准 graph nodes/edges/evidence，不能直接构造 UI 文案。
- adapter 顺序由 registry 明确定义；冲突必须产生 diagnostic，不以最后写入覆盖。
- 项目专用 Axios wrapper 通过配置化 binding descriptor 或项目 adapter fixture 支持，不在通用 analyzer 中硬编码 `@/utils/http`。

## 解析与缓存

- Vite 首发复用宿主 `resolve` 结果处理 alias、extension、package exports；analyzer 不重新实现一套 resolver。
- sourceRoots、realpath 和保护文件继续由 dev-server 的可信配置控制。
- 首次打开目标时，从 component file 向外惰性扩图；不在 dev 启动时创建全仓 TypeScript Program。
- cache key 至少包含 `registryEpoch + fileId + contentHash + analyzerVersion + adapterSetHash + resolvedOptionsHash`。
- HMR 只失效反向依赖闭包；session/registry epoch 变化全部失效。
- cache 只存 AST 摘要和已清洗报告，不存请求/响应实际值。

## 复用与去冗余硬规则

1. fetch/XHR transport 只负责采集，统一进入一个 recorder core；页面总览和组件视图读取同一 store。
2. 参数与响应 shape 使用同一个 side-effect-free extractor；协议、UI、AI 不各写一套清洗。
3. 状态、badge 和错误码来自 shared schema；中英文文案由面板内单一 typed dictionary 维护，不进入 shared，也不散落到关联算法。
4. 所有预算和默认值由一个 Node options resolver 装配；浏览器只接收最终安全配置。
5. compiler/analyzer 共享 SourceAnchor 契约，不复制 hash/位置算法。
6. Adapter 通过 registry 扩展；禁止在核心遍布 `if (library === "zustand")`。
7. 每次迁移删除旧活动实现、旧 export、旧测试 helper 和 feature flag；不得保留“以后可能用”的死代码。

## 禁止依赖

- `runtime/shared/compiler → analyzer/dev-server/fs/typescript/vite/next`：禁止。
- `analyzer → vite/next/runtime UI/agent/provider`：禁止。
- `vite ↔ next`：双向禁止。
- 任一包导入另一包未声明的 `src/**`：禁止。
- UI 直接读取 recorder 私有对象或 Node report cache：禁止。
- AI context builder 直接遍历 Fiber、Request、Response 或任意 storage：禁止。

## Feature 生命周期

功能由一个公共高层选项启用，内部 capability 由版本/宿主/POC 结果决定。`disabled` 必须在构建阶段剪除 analyzer endpoint、instrumentation、prelude 和 lazy chunk；不能只在运行时 `if` 后保留生产字符串。实验 flag 必须有 owner、创建日期、退出条件和最晚删除 Gate，完成后要么变正式配置，要么删除。

## 结构验收

- dependency-cruiser/ESLint 或等价测试证明禁止依赖为零。
- export surface snapshot 证明无意外公共 API。
- `rg` 结构扫描证明旧 recorder、旧 schema、旧常量和临时 POC 路径不存在。
- bundle 门禁证明 Node-only 包不进入浏览器，Inspector UI 不进入核心 Runtime 文件；关闭能力时客户端不导入 Inspector/prelude 虚拟模块。
- disabled 与 production fixture 证明相关模块和可识别字符串均为零残留。
