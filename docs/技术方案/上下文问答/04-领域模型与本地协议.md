# 上下文问答：领域模型与本地协议

本页是 Contextual Ask 公共模型、浏览器协议、限制和错误码的唯一事实来源。示例类型已在 Q2 由同一 Zod Schema 推导运行时校验和公开类型，禁止手写两套漂移定义。Q2 只提供协议代码，不注册 endpoint、不接受用户配置，也不启用 UI；这些属于 Q3 以后 Gate。

Q2 的活动事实位置：

- `packages/shared/src/model/context-schema.ts`：新旧任务共用的选择上下文事实 Schema；
- `packages/shared/src/model/contextual-ask.ts`：Selection、Task、Draft、Answer、Capability；
- `packages/shared/src/protocol/contextual-ask.ts`：create/snapshot/event/result 请求响应；
- `packages/shared/src/contextual-ask-browser.ts`：无 Zod/Node 运行时依赖的 Browser DTO/常量入口；
- `packages/shared/src/contextual-ask-node.ts`：Schema 与有删除里程碑的 Change-only `SpotAnnotation v3` adapter。

## 目标公共配置

首阶段只新增一个显式、默认关闭的入口，不复制 Provider/Codex 配置：

```ts
type ContextualAskExecutorPreference =
  | Readonly<{
      kind: "configured-key";
      providerProfileId: string;
      modelProfileId: string;
    }>
  | Readonly<{ kind: "managed-codex" }>;

type ContextualAskOptions =
  | boolean
  | Readonly<{ defaultExecutor?: ContextualAskExecutorPreference }>;

interface SpotPatchOptions {
  readonly contextualAsk?: ContextualAskOptions;
}
```

默认 `false`；`true` 或对象显式启用。Configured Key 只从既有 `ai` 配置生成，Managed Codex 由 Bridge 独立探测，不要求同时开启 change-oriented `externalAgent`。对象中的默认执行器只能引用可信配置里已登记的 Provider/model 或固定 Managed Codex kind；无效引用 fail-fast。未配置默认且只有一个 ready executor 时可以预选；有多个 ready executor 时要求用户明确选择，并只在当前页面内存记住，不能把厂商选择写入长期 Storage。

Browser 不能设置自定义命令、路径、URL、Key、模型名、sandbox、permission 或本页集中限制。Q3 已把 `contextualAsk` 字段、默认 `false`、Configured Key 引用复验和 Next IPC 精确 transport 接入 `SpotPatchOptions`；Q4 已在该内部 flag 开启时装配 Configured Key executors；Q5 已条件装配 Runtime UI 和严格 Browser transport。Managed Codex 仍属于 Q6，Q7 发布矩阵也未完成，因此内部可交互不代表产品已经发布 Ask。

## 选择与任务分离

```ts
interface SpotSelectionTarget {
  readonly targetId: string;
  readonly page: Readonly<PageContext>;
  readonly source: SourceRef;
  readonly react: ReactContext;
  readonly element: ElementContext;
  readonly styles: StyleContext;
  readonly code?: CodeContext;
  readonly warnings: readonly string[];
}

interface SpotSelectionContext {
  readonly schemaVersion: 1;
  readonly selectionId: string;
  readonly locale: SpotPatchLocale;
  readonly targets: readonly SpotSelectionTarget[];
  readonly createdAt: string;
}

type SpotTask =
  | Readonly<{ kind: "ask"; question: string }>
  | Readonly<{
      kind: "change";
      instructions: readonly Readonly<{ targetId: string; instruction: string }>[];
      origin?: AskDraftOrigin;
    }>;

interface SpotTaskEnvelope {
  readonly schemaVersion: 1;
  readonly taskId: string;
  readonly selection: SpotSelectionContext;
  readonly task: SpotTask;
  readonly createdAt: string;
}
```

`SpotSelectionTarget` 没有 instruction；跨页面事实只以每个 target 的 `page` 为准。`SpotAnnotation v3.page` 和 target instruction 在迁移期由 Change adapter 生成，不能用于 Ask。Change 的 `instructions` 必须与 selection target 一一引用、ID 唯一、至少一个非空；Ask 只有一个 question。

## Ask 创建请求

```ts
interface AskJobCreateRequest {
  readonly schemaVersion: 1;
  readonly requestId: string;
  readonly envelope: SpotTaskEnvelope & Readonly<{ task: { kind: "ask"; question: string } }>;
  readonly executorId: string;
  readonly providerDataConsent: true;
}
```

`executorId` 是 capability API 返回的 opaque ID。Configured Key 的 Provider/model 选择可以编码在服务端签发的 executor option 中，Browser 仍只提交已枚举 ID；不得提交 Base URL、Key、环境变量、Codex path、cwd、permissions 或 sandbox。

同 `requestId` + 同 normalized fingerprint 返回原 Job；同 ID + 不同内容返回 `ASK_IDEMPOTENCY_CONFLICT`。fingerprint 不包含 Key，但包含 selection/context hash、question、executor 和 dev Session。

## Answer 结果

执行器先返回仅在 Node 内流转的不可信草稿。它使用 Job source handle 加行范围，不能直接构造 Browser 引用：

```ts
interface AskDraftCitation {
  readonly handleId: string;
  readonly startLine: number;
  readonly endLine: number;
}

type AskAnswerDraftBlock =
  | Readonly<{ kind: "paragraph"; text: string; citations: readonly AskDraftCitation[] }>
  | Readonly<{
      kind: "list";
      items: readonly Readonly<{
        text: string;
        citations: readonly AskDraftCitation[];
      }>[];
    }>
  | Readonly<{
      kind: "code";
      code: string;
      language?: string;
      citations: readonly AskDraftCitation[];
    }>;

interface AskAnswerDraft {
  readonly blocks: readonly AskAnswerDraftBlock[];
  readonly warnings: readonly AskAnswerWarning[];
}
```

Manager 校验 handle、hash 和行界，把每个不同的 `handleId + startLine + endLine` 规范化为一个 result source ID，并把 block citations 投影为下述 `sourceIds`。相同范围稳定去重，不同范围保持不同引用。

Warning 也有明确的事实所有权：executor draft 只能声明 `insufficient-evidence` 与 `partial-context`；`source-truncated` 与 `source-stale` 只能由 Manager 根据 Source Grant 和落盘内容计算后附加，Provider 不能自行声明这两类服务端事实。

```ts
type AskAnswerBlock =
  | Readonly<{
      kind: "paragraph";
      text: string;
      sourceIds: readonly string[];
    }>
  | Readonly<{
      kind: "list";
      items: readonly Readonly<{ text: string; sourceIds: readonly string[] }>[];
    }>
  | Readonly<{
      kind: "code";
      code: string;
      language?: string;
      sourceIds: readonly string[];
    }>;

interface AskSourceReference {
  readonly sourceId: string;
  readonly label: string;
  readonly relativePath: string;
  readonly fileId: string;
  readonly startLine: number;
  readonly endLine: number;
  readonly confidence: "exact" | "probable" | "approximate";
  readonly targetIds: readonly string[];
  readonly sourceVersion?: string;
  readonly contentHash: string;
}

interface AskAnswerResult {
  readonly schemaVersion: 1;
  readonly jobId: string;
  readonly selectionId: string;
  readonly contextHash: string;
  readonly executor: Readonly<{
    executorId: string;
    kind: "configured-key" | "managed-codex";
    label: string;
    modelLabel: string;
  }>;
  readonly blocks: readonly AskAnswerBlock[];
  readonly sources: readonly AskSourceReference[];
  readonly warnings: readonly AskAnswerWarning[];
  readonly createdAt: string;
  readonly expiresAt: string;
}
```

`blocks` 是一个答案的结构，不是聊天消息。UI 按 union 渲染，不能解析 Markdown HTML。所有 `sourceIds` 必须存在于 `sources`，关键事实块原则上至少有一个引用；没有证据的推断必须带本地化 warning 或明确使用“推测/未知”。

模型草稿不得直接指定 `fileId`、绝对路径或 open-editor 坐标。它只能提交本次 source handle 和该 handle 内的最小支持行范围；Manager 根据 grant 解析为 `AskSourceReference`。引用打开时仍走既有 endpoint，并重新验证 Session、fileId、行号和当前 Registry；hash 变化时先显示 stale，不静默打开错误位置。

## 转修改来源

```ts
interface AskDraftOrigin {
  readonly kind: "contextual-ask";
  readonly askJobId: string;
  readonly question: string;
  readonly answerDigest: string;
  readonly sourceIds: readonly string[];
}
```

`AskDraftOrigin` 是只读 provenance，不是全局修改 instruction。`answerDigest` 由本地确定性裁剪从 Answer blocks 生成，不调用模型；Change Prompt 把它放在“参考上下文”不可信边界内。每个目标仍需要自己的 instruction，服务端不能从 origin 猜修改意图。

## Job 状态与事件

```ts
type AskJobStatus =
  | "queued"
  | "authorizing"
  | "running"
  | "cancelling"
  | "answered"
  | "cancelled"
  | "failed";

type AskJobEvent =
  | SnapshotEvent
  | PhaseEvent
  | ReadActivityEvent
  | AnswerReadyEvent
  | ErrorEvent;
```

状态单调：

```text
queued → authorizing → running → answered
                         ├──────→ failed
                         └→ cancelling → cancelled|failed
```

`ReadActivityEvent` 只含 `sourceId`、安全相对路径或文件数量 bucket、状态和序号；不含源码正文、查询字符串、绝对路径或 reasoning。`answered` 必须在完整 Answer 通过校验并写入内存结果后发生。Provider final text、Codex `turn/completed` 或 tool call 写入成功都不能单独产生 answered。

每行 NDJSON 都有 `schemaVersion`、严格递增 `sequence`、jobId、status 和 timestamp。Runtime 对重复 sequence 幂等，遇到跳号/倒退/未知必需字段 fail closed 并重新取 snapshot；未知可选 event type 只能在协议版本允许时忽略。

## Endpoint

```text
GET  /__spotpatch/v1/ask/capability
POST /__spotpatch/v1/ask/jobs
GET  /__spotpatch/v1/ask/jobs/:jobId/events
GET  /__spotpatch/v1/ask/jobs/:jobId/result
POST /__spotpatch/v1/ask/jobs/:jobId/cancel
```

- capability 返回 `enabled`、执行器列表、ready/degraded/unavailable、requested/effective model label、是否需同意和安全限制摘要；不返回 secret 或厂商原始错误。
- create 返回 Job snapshot，不等待模型。
- events 使用既有有界 NDJSON 连接模式；断线后从 `afterSequence` 恢复。
- result 只在 answered 返回 Answer；非终态返回 snapshot；到期返回 `ASK_RESULT_EXPIRED`。
- cancel 幂等；answered/cancelled/failed 后重复取消返回当前终态，不改变结果。

所有 endpoint 继承 (见 doc-id:09-local-protocol-security) 的 development-only、loopback、cookie/Session、Origin、method、content-type、body 上限和生产 404 规则。

## 集中限制

下表只在本页定义；代码必须集中为 `CONTEXTUAL_ASK_LIMITS` 并由 Schema、Manager、executor 和测试引用，不得在 UI/adapter 重复数字。

| 常量 | 首阶段值 | 目的 |
| --- | ---: | --- |
| `maximumTargets` | 20 | 与核心协议硬上限一致 |
| `maximumQuestionCharacters` | 4,000 | 单问题边界 |
| `maximumAnswerCharacters` | 40,000 | 所有块文本累计 |
| `maximumAnswerBlocks` | 40 | DOM/Schema 有界 |
| `maximumSources` | 64 | 引用和打开入口有界 |
| `maximumReadFiles` | 32 | 避免全仓扫描 |
| `maximumReadBytesPerFile` | 64 KiB | 单文件读取上限 |
| `maximumReadBytesTotal` | 512 KiB | 单 Job 源码总量 |
| `maximumToolCalls` | 48 | Key 工具循环上限 |
| `maximumModelTurns` | 12 | 内部往返上限，不等于产品追问 |
| `jobTimeoutMs` | 300,000 | 端到端有界执行；覆盖托管模型偶发长尾，超时返回独立 `ASK_TIMEOUT`，不误报执行器不可用 |
| `capabilityTimeoutMs` | 30,000 | 单次冷启动探测有界；单个执行器失败只降级自身，不拖垮其余执行器 |
| `resultTtlMs` | 900,000 | 仅支持当前结果/转草稿，不是历史 |
| `maximumActiveJobsPerSession` | 1 | 单飞 |
| `maximumRetainedResultsPerSession` | 1 | 无聊天历史 |

协议结构自身还使用下列集中技术边界；它们同样只由 `CONTEXTUAL_ASK_LIMITS` 提供：

| 常量 | 首阶段值 | 目的 |
| --- | ---: | --- |
| `maximumIdCharacters` | 128 | opaque Job/Selection/Source ID 有界 |
| `maximumProfileIdCharacters` | 64 | 复用现有 Provider/model profile ID 上限 |
| `maximumLabelCharacters` | 256 | 执行器与引用展示标签有界 |
| `maximumRelativePathCharacters` | 1,024 | 仅项目相对 POSIX 路径且拒绝遍历/绝对路径 |
| `maximumLanguageCharacters` | 64 | code block language 标签有界 |
| `maximumPhaseMessageCharacters` | 1,024 | UI 阶段信息有界且不承载 reasoning |
| `maximumExecutors` | 32 | capability 列表有界 |
| `contentHashHexCharacters` | 64 | SHA-256 小写十六进制内容哈希 |

上线前若真实 benchmark 证明某值不合理，必须在本页与 ADR 同步修改并重跑性能/安全 Gate；不得在厂商 adapter 内单独放宽。

## 稳定错误码

| 错误码 | 含义/恢复 |
| --- | --- |
| `ASK_DISABLED` | 功能未显式启用；修改配置 |
| `ASK_SELECTION_REQUIRED` | 没有目标；返回选择流程 |
| `ASK_SELECTION_STALE` | Session/Registry/sourceVersion 已变化；重新采集 |
| `ASK_QUESTION_INVALID` | 空、超限或 Schema 非法；编辑问题 |
| `ASK_EXECUTOR_UNAVAILABLE` | 执行器未 ready；诊断/改选 |
| `ASK_CONSENT_REQUIRED` | Provider 数据同意缺失；显式确认 |
| `ASK_BUSY` | 当前 Session 已有活动 Ask；等待或取消 |
| `ASK_IDEMPOTENCY_CONFLICT` | requestId 重用且内容不同；生成新 ID |
| `ASK_SOURCE_SCOPE_DENIED` | 读取/引用越权；终止本 Job |
| `ASK_LIMIT_EXCEEDED` | 时间、文件、字节、轮次或输出超限；缩小问题/重试 |
| `ASK_ANSWER_INVALID` | Answer Schema、引用或终态不合格；不猜测修复 |
| `ASK_WRITE_ATTEMPTED` | 执行器产生写/权限升级证据；立即终止并降级 capability |
| `ASK_CANCELLED` | 用户取消；不接收迟到结果 |
| `ASK_RESULT_EXPIRED` | 当前结果 TTL 到期；重新提问 |
| `ASK_PROTOCOL_INCOMPATIBLE` | Provider/Codex 版本合同不满足；诊断/改选 |

错误响应不包含 Provider body、Codex message、绝对路径、源码、Key、Prompt 或堆栈。厂商错误先归一化，再交给 Browser 本地化。
