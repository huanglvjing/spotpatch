# 上下文问答：测试、验收与实施计划

## 交付原则

每个阶段只在代码、自动化、负向安全、真实宿主和文档证据全部满足后完成。后续阶段不得以 feature flag 留下不可达半实现；Gate 未过的 executor 不注册、不出现在 UI，也不形成支持声明。

## Gate Q0：文档与 ADR

- 本专题 00–10 评审通过，当前事实和目标设计没有混写；
- 接受 ADR-040～ADR-044；
- 与 `SpotAnnotation v3`、ADR-014、内建 Change、managed apply、数据链路 Explain 和持续 Shell 的所有权无冲突；
- 首阶段/后续范围、协议限制、错误、状态和删除条件唯一；
- 更新总索引与一手依据。

Q0 完成只表示可实施，不能宣传功能可用。

## Gate Q1：阻断式 POC

### Q1-A Configured Key

用 fake Responses/Chat Completions 证明：只读 source tools、跨轮 tool result、严格 submit-answer、引用验证、取消和无 free-text 降级。确认现有 Provider session 能以独立 system/tools 复用而不 import Change engine。

### Q1-B Managed Codex

按 (见 doc-id:context-qa-06-managed-codex) 完成锁定版本 Schema、answer item/outputSchema、restricted read-only、config isolation、thread/runtime cleanup 和写入攻击。POC 必须在一次性 fixture 中运行，不能以官方页面或 mock 代替真实 CLI。

### Q1-C UI/包体基线

制作最小 extension POC，测量核心 Runtime 是否零增长、Ask chunk gzip、mount、模式切换、40k answer/64 sources DOM 和 320px/200% zoom。把实测写回安全/测试文档和 ADR 后再开始完整 UI。

任一 POC 失败时更新方案并停止对应实现；Key 和 Codex 可独立通过，首阶段“同时支持两者”的发布 Gate 仍要求二者都通过。

### Q1 实测结论（2026-09-01）

Q1 本机可行性 Gate 已通过，稳定结论与复现命令见 `experiments/contextual-ask-q1/CONCLUSION.md`：

- Configured Key：Responses/Chat Completions 共 6 个确定性正向/负向测试，覆盖四工具白名单、跨轮结果、真实引用、free-text/写工具/伪引用拒绝和取消传递；
- Managed Codex：`codex-cli 0.151.0` 生成 Schema + 一次认证真回合，命名只读 profile 真实拒绝 root 外读与 projection 写，结构化答案、权威 final item、空扩展和 ephemeral 不持久化通过；
- UI：独立 IIFE 6,905 B raw / 2,762 B gzip，39,640 字符、40 blocks、64 sources 的 jsdom mount median 2.47 ms / P95 6.23 ms，265 DOM nodes，模式切换 P95 0.011 ms；
- 真实 Chromium：320 px 与 200% root font 均无 document-level 横向溢出；POC 在独立 experiment bundle，Runtime 入口未引入它。

这些是 Q2 的入场证据，不是产品 beta/released 证据；双 Job、中断/崩溃/清理故障注入、跨平台和完整 Runtime 仍按 Q5–Q7 执行。

## Gate Q2：公共模型与协议

- `SpotSelectionContext`、`SpotTaskEnvelope`、Ask create/snapshot/event/result/capability Schema 和错误码；
- 严格 union、unknown field、边界、总字符和关联 superRefine 测试；
- endpoint builder 与 Browser/Node 子入口；
- legacy `SpotAnnotation v3` Change adapter 与迁移测试；
- 不把 Node、Zod parser 之外的厂商类型带入 browser export。

完成 Q2 后发布的只是内部协议代码，不启用 UI endpoint。

### Q2 实测结论（2026-09-01）

Q2 Gate 已完成，且没有提前启用产品功能：

- `@spotpatch/shared` 已落地 Selection/Ask/Change/Draft/Answer/Capability/Job/Event 的严格 Schema、集中限制与 15 个稳定 Ask 错误码；
- Answer 强制引用闭包；无引用时必须显式 `insufficient-evidence`，相对路径拒绝 POSIX/Windows 绝对路径、遍历、反斜杠与控制字符；
- `getAskJobEndpoint` 只允许 `events/result/cancel`，恢复游标只允许用于 events 且必须是非负安全整数；
- Browser/Node 子入口和 package exports/typesVersions 已建立；Browser-only 单入口 bundle 实测 3,751 B raw / 1,575 B gzip，产物不包含 Zod、Node 或厂商实现；核心 Runtime ESM 仍为 Q1 基线 275,652 B raw；
- Change-only adapter 按 selection 顺序保留逐 target page/instruction；Ask 在类型层不可传入，运行时伪造也由严格 parser 拒绝；
- shared 全量 55 tests passed、1 skipped，其中 Q2 新增 9 组契约测试与 2 组 endpoint 测试；`eslint packages/shared/src`、shared typecheck/build 全绿。

这些证据只关闭 Q2；没有 Source grant、Manager、HTTP middleware、正式 executor 或 UI，因此产品状态仍为 unavailable。

## Gate Q3：Source grant 与 Manager

- Registry/Session/realpath/保护文件/普通文件/size/sourceVersion 授权；
- target-first candidate graph 与最大文件/字节/截断；
- immutable read snapshot、source handles、hash/stale；
- Job 单飞、idempotency、sequence、NDJSON 恢复、取消、TTL、最新结果替换和 dispose；
- executor port fake 的 success/failure/late-result/cleanup；
- Vite/Next 使用同一 middleware 和 option。

必须证明无目标/过期/伪造 source 时远程调用数为零。

### Q3 实测结论（2026-09-01）

Q3 Gate 已完成，正式模型执行与 UI 仍未开始：

- `@spotpatch/agent` 新增 Node-only `ContextualAskExecutor`/grant/snapshot 端口，不 import Change engine，也未注册任何真实 Provider/Codex 实现；
- dev-server 以 Registry 为授权根，复验 Data-flow `sourceVersion`，按所有目标优先、已登记关联样式、确定性本地相对 import 的顺序构造候选；固定上限为 32 files、64 KiB/file、512 KiB total，问题文本不参与路径解析；
- 安全打开覆盖 root realpath、全路径 symlink、hardlink、普通文件、受保护目录/文件、NUL、fatal UTF-8、打开前后 inode/size/mtime 和内容 hash；执行器只收到 opaque handle、相对路径与冻结内存字节，终态/取消立即 dispose；
- `ContextualAskManager` 负责每 Session 单飞、request fingerprint 幂等、单调 sequence、有界 replay/subscriber、取消与迟到结果丢弃、120 s timeout、15 min TTL、仅一个 retained result、引用投影和最终 Schema；Ask 与既有 Change 共用 workspace activity coordinator；
- `/ask/capability`、create/events/result/cancel 已进入统一 middleware；events 使用 NDJSON 和 `afterSequence`，订阅先于同步 replay 建立以关闭交接竞态；Vite/Next 共用同一 option transport、Manager 和 middleware；
- Q3 直接新增 16 个 source/manager/HTTP 测试，并增加真实 Change coordinator、option 与 Next transport 回归；无目标、stale sourceVersion、stale code excerpt、伪造 fileId 的 executor 调用均为零，硬链接与伪 handle fail closed，取消后迟到答案不进入 result；
- 全仓 unit 795 passed / 2 skipped，lint、typecheck、build 通过；Runtime 核心 ESM 仍为 Q1/Q2 基线 275,652 B raw，Q3 没有引入 Runtime UI 或 Ask browser chunk 自动加载。

这些证据只关闭 Q3；Configured Key 正式只读工具循环和 Runtime UI 后续已分别在 Q4、Q5 完成。Managed Codex 正式执行器仍属于 Q6，当前产品状态仍为 unavailable。

## Gate Q4：Configured Key executor

- Responses 和 Chat Completions 正常、多次读、零额外读、并发读；
- direct final text、写工具、重复 ID/submit、invalid args/source/line、limit、timeout、stream interruption；
- Provider/model/capability snapshot、secret redaction 和同意；
- root/Git 零变化断言；
- fake provider 收到的上下文与 UI normalized preview 一致。

Q4 完成后可在内部 flag 下测试 Key，不先对外标首阶段完成。

### Q4 实测结论（2026-09-01）

Q4 Gate 已完成，Key 只读执行器可在默认关闭的内部 flag 下进入 Manager，但产品仍不可用：

- Responses 与 Chat Completions 均通过正式四工具、跨轮 tool result、同轮批量读取、初始 excerpt 零额外读取和严格 submit-answer；Provider 请求的 user prompt 与导出的 normalized preview 为同一字符串；
- Ask 专属 capability fixture 真实验证 read、continuation、严格结构化 submit，并按 Provider/model/protocol/Base URL/auth/model/Ask version 摘要隔离稳定 opaque executor；成功/失败缓存及并发 probe 合并已覆盖；
- direct final text、写/未知工具、混合或重复 submit、Chat/Responses 重复 call ID、无效 arguments/source/citation/line、tool/turn/time limit、取消、终态后迟到 event 和中断 stream 全部 fail closed；无效但可恢复的行范围只返回有界 retryable tool error；
- Prompt 和只读工具输出双重脱敏，Key 仅存在 opaque credential WeakMap 与 HTTP auth header；capability/result/error 不含 Base URL、env、绝对路径或 Provider 原始正文；缺失数据同意稳定返回 `ASK_CONSENT_REQUIRED`；
- Vite/Next 通过 dev-server 同一 factory 注册 Configured Key executors，显式 Ask 默认项优先，模型总数超过 capability 上限会在配置解析期拒绝；默认 `contextualAsk: false` 与 Runtime 零 UI 注入保持不变；
- Q4 新增 29 个测试，临时真实 Git repository 的 Manager E2E 证明 capability + answer 前后 root 内容和 status 零变化；复审覆盖 executor/server warning 事实所有权、并发 capability waiter 独立取消，以及 stale 投影期间取消后丢弃迟到答案；全仓 unit 824 passed / 2 skipped，format、lint、typecheck、build、publint、attw、production leakage/budget 全绿，核心 Runtime ESM 仍为 275,652 B raw。

这些证据只关闭 Q4；Q5 Runtime/UI 已在下一节于 2026-09-02 独立验收。Q6 Managed Codex 正式执行器和 Q7 跨框架/平台发布矩阵仍未完成，不能宣传 Contextual Ask 已发布或首阶段已完成。

## Gate Q5：Runtime 与 UI

- Ask/Change 显式模式、双草稿、至少一目标、字符/快捷键/IME；
- executor/consent/capability、submit/cancel/retry；
- Answer blocks、code、sources、copy、open-editor、stale；
- 转 Change draft 不创建 Job/写请求，并保持逐目标 instruction；
- current-only result、page unload/Start over cleanup；
- Shell 状态映射无“修改中”误文案，reduced motion 无信息损失；
- 中英文所有状态、键盘/焦点/live region、320px、200% zoom。

需要 jsdom 单元、Playwright 行为、真实 Chromium 截图和 axe/等价无障碍检查；截图不能替代交互断言。

### Q5 实测结论（2026-09-02）

Q5 Gate 已完成，Configured Key 已可在默认关闭的内部 flag 下完成 Runtime 端到端问答；首阶段产品仍未发布：

- Vite 与 Next 都只在 `contextualAsk.enabled` 时加载同一个 `@spotpatch/runtime/contextual-ask-panel` extension；未启用时不请求 Ask bundle，production 不注入 Runtime 或 Ask endpoint，核心 Runtime 没有吸收 Ask transport、答案渲染和本地化正文；
- 同一持续 Planner 具备显式 Ask/Change tabs 和相互独立的 question/逐目标 instruction；无选择、capability 未 ready、未选择 executor 或未完成本次 Provider consent 时提交均禁用，选择和 Job 生命周期由现有 Controller 与 immutable selection snapshot 驱动；
- 独立 Browser API 严格校验 capability/create/NDJSON events/result/cancel，限制响应/行/流体积并拒绝乱序 sequence、身份漂移和无效结果；Session token 只进 header，不进入草稿、DOM 或 storage；
- queued/authorizing/running/read activity 投影到既有 Execution Island，文案不出现修改/应用语义；关闭 Planner 不取消，取消、重新开始和 unload/dispose 均终止当前请求，revision/current-only 规则丢弃迟到结果；
- Answer 只用安全 DOM node 渲染 paragraph/list/code/source，支持 copy、服务端 `fileId + line` 打开源码、stale 提示；“转成修改请求”只生成本地 `AskDraftOrigin`，保留所有既有逐目标 instruction，不创建 Ask/Change Job，也不发写请求；
- jsdom 覆盖双草稿、状态/负向文案、恶意内容 inert、完整工作流与 40,000 字答案（本机断言 <250 ms）；真实 Chromium 覆盖完整单轮、源码跳转、转草稿、320 px、200% page scale 和可访问角色/名称，并保留 `tests/e2e/contextual-ask.spec.ts-snapshots/contextual-ask-answer-chromium-darwin.png`；
- 全仓 unit 831 passed / 2 skipped，Chromium E2E 20 passed；format、lint、typecheck、build、publint、attw 和 production leakage/budget 全绿。核心 `runtime-client.js` 为 48,894 B gzip，仍低于既有 48 KiB 门禁；独立 Ask bundle 为 12,783 B gzip，低于 14 KiB 门禁。

这些证据只关闭 Q5。Q6 Managed Codex 正式执行器和 Q7 跨框架/平台/安全发布矩阵仍未完成，不能宣传 Contextual Ask 已发布或首阶段已完成。

### Q6 实测结论（2026-09-02）

Q6 正式执行器与本机 authenticated gate 已完成，Managed Codex 已进入与 Configured Key 并列的内部 executor 列表；跨平台 beta 发布矩阵仍未关闭：

- `@spotpatch/bridge` 新增独立 `managed-ask-v1` adapter、Answer event collector 和 Job 私有只读 projection；Vite/Next 通过同一个 executor composition 注册 Managed Codex，即使没有 Key 配置也能探测本地 Codex；显式 `defaultExecutor: { kind: "managed-codex" }` 只改变顺序，不改变安全配置；
- 产品锁定 `codex-cli 0.151.0` 并在每次连接验证 realpath、版本和 generated Schema required surface；命名 profile 为 root deny、minimal read、workspace read、network disabled，且复验 ephemeral、effective roots、instruction sources、hooks 与 MCP；
- Structured Outputs wire block 避免不受支持的 `oneOf`，但在服务端强制 paragraph/list/code 的字段互斥后才转为公共 `AskAnswerDraft`；最终答案必须同时具备 correlated completed final item 与 completed turn，delta/command/reasoning 不进入 UI；
- mock 故障注入覆盖非空/迟到 diff、fileChange/collab/dynamic/MCP/web activity、permission reverse request、重复/缺失 final、turn failed、hook/MCP 残留、取消 interrupt、进程崩溃、删除失败和 ephemeral not-persisted 清理；projection 另有 hash、敏感路径、readonly mode、mutation 和 dispose 断言；
- 真实登录态 macOS 使用正式 executor 完成 capability、两个单文件 Ask 与一个六文件 App Ask；2026-09-02 最新复验 115.2 秒，三个结果均含源码引用，未 resume/fork/steer，runtime home 最终为空；答案正文和凭据未写入测试 artifact；
- 全仓 unit、真实 Q6 live gate、format、lint、typecheck、build、production leakage/bundle budget、publint 与类型导出检查均通过。Managed Ask 的 server-only 代码没有进入 Runtime browser bundle，仍沿用 Q5 的独立 UI chunk。

因此 Q6 的产品代码和单机证据可以进入 Q7；Ubuntu、Windows、Node 20/22、npm 安装 fixture 以及完整 Vite/Next 场景未完成前，状态仍是内部可用，不标 beta、不做跨平台宣传。

## 实施顺序

```text
M-Q0 文档/ADR
→ M-Q1 Key + Codex + UI POC
→ M-Q2 shared 协议
→ M-Q3 source grant/read snapshot/manager
→ M-Q4 Key executor
→ M-Q5 Runtime Ask UI + Key 内部验收
→ M-Q6 Managed Codex executor
→ M-Q7 双执行器跨框架/平台/安全/性能收口
```
