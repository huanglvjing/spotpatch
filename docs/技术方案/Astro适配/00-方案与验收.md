# Astro 适配设计与验收

> 历史阶段方案：本文保留首轮源码预览的设计与范围。本轮用户要求的全功能对齐以 [02-功能对齐实施方案](./02-功能对齐实施方案.md) 为当前规范；下文“不开放”条目不再代表当前代码状态。

## 依据与现状

本方案在代码变更前制定。用户已授权调研、确定方案、实现与文档更新；发布 npm 和部署不属于本次执行。验收结果记录在本目录的实施记录中，不以设计代替通过证据。

- SpotPatch 的 02/04/06/08/09/11 号活动规范：AST 定位与 React 语义分离；Runtime 无 React 可降级；适配器平级；Node 服务和浏览器包隔离；源码读取必须经会话 registry、realpath、大小限制；失败不能伪造 exact。
- 本地宿主 `shengsuanyun-newmodel`：Astro 7.2.8、Vite 8.2.2、Node >=22.12、`.astro` 页面、lit-html/原生脚本交互、无 React；自有 `astro.dev()` 启动器；开发工具栏关闭；自定义 BFF、鉴权与生产扫描。
- [Astro Integration API](https://docs.astro.build/en/reference/integrations-reference/)：`astro:config:setup` 提供 command/updateConfig/injectScript；`page` 阶段是 Vite 处理的浏览器 module；`astro:server:setup` 提供开发服务；集成 default factory + `astro-integration` keyword 可使用官方 `astro add`。
- [Astro Compiler](https://github.com/withastro/compiler)：旧 @astrojs/compiler 4.0.0 的临时探针暴露 void tag、属性表达式与位置偏差，不用于最终实现。
- 本地 Astro 7 编译源码：Astro 自己的 transform 为 enforce:pre；适配转换还需 hook order:pre，不能只依赖插件数组顺序。Astro 7 使用 compiler-rs；SpotPatch 的独立 AST 仅用于源文本标记，不替代宿主编译器。

## 架构决策

### 调研修订：采用官方 Rust parser（2026-09-05）

真实 fixture 显示旧 @astrojs/compiler 4.0.0 在 `<meta>` 与正则表达式属性上存在错误坐标；不采用该实现。[compiler-rs 官方 API](https://github.com/withastro/compiler-rs) 的 parse 返回 ESTree-compatible AST，0.4.0 实测 start/end 为 JS UTF-16 offset，正确处理中文、emoji、void tags 和正则表达式。采用锁定的 `@astrojs/compiler-rs@0.4.0`；它要求 Node >=22.12，因此 Astro 适配包统一声明该 Node 下限，原 Vite/Next Node 支持不变。对其未严格声明的 AST 以 unknown 开始逐字段校验；不信任 any。

Astro 的 spreadAttributes 会输出 HTML 属性，重复属性由浏览器优先保留第一个。因此原生 Astro marker 放在 tag name 后、所有用户属性之前；JSX 仍保持尾部插入。真实 spread 冲突用例验证此差别。实现直接消费受校验的 AST name.end/start，不保留旧 opening-tag scanner 或 UTF-8 转换代码。

新增平级 `@spotpatch/astro` 用户入口，使用 Astro Integration，不依赖 `@spotpatch/vite` 或 `@spotpatch/next`。复用 `shared` 协议、`compiler` JSX 工具（仅明确需要时）、`dev-server` registry/配置/鉴权/Agent、`runtime` 选择/采集/工作台与 React 兼容层。Astro 专有 AST 依赖留在 Astro 包内，不增加其他框架的编译依赖。

首个可交付范围：原生 `.astro` DOM 精确定位、编辑器跳转、DOM/CSS、双语多目标 Prompt、Configured Key Review/Apply/Revert。无 React 宿主无需安装 React。首版暂不开放组件数据流和外部 Agent/Ask：这些能力涉及 frontmatter、浏览器脚本与 island 的不同执行上下文，必须独立证明归属、源码授权和会话发现后才能开放；公共类型及运行时明确拒绝尚未支持的开关，不显示可用假象。

这属于新增 Astro 0.x 适配器，不修改现有 Vite/Next 的正式支持声明。候选矩阵为 Astro 5/6/7；实际承诺只覆盖版本化 fixture 的真实通过项。Astro 7/Vite 8 为必验主宿主；Node 按 Astro 自身 engine 要求运行。安装范围不等于已完成全部版本/OS 测试。

## 包与职责

```text
packages/astro/
  src/index.ts                  公共导出
  src/integration.ts            command 门禁、配置与 Astro 生命周期
  src/options.ts                Astro 专属支持边界；复用通用选项解析
  src/transform.ts              Vite hook、过滤、registry、诊断
  src/astro-source-markers.ts   Astro AST 与局部源码编辑
  src/runtime-plugin.ts         浏览器 module 供应、受控 config、HMR
  src/client.ts                 复用 Runtime，Astro page swap 生命周期
  tsup.config.ts                Node 入口与浏览器产物独立构建
  README.md                     安装、选项、局限和验证命令
playgrounds/compat-astro*/      版本化真实 Astro fixture（5/6 复用 7 的模板）
```

只有实现有实际消费方的模块/选项；不建设自有 CLI 配置修改器，使用官方 astro add 和手动配置。框架标识使用 `astro`，不能伪报 Vite。新增 `astro-host` origin 和 `astro` CodeContext language；旧 marker 三段格式保持不变，Astro marker 追加 `:astro`，同一共享 parser/formatter 处理；旧 JSX 与 React 语义不变。

## 源码转换

1. 只在 command=dev 安装插件和脚本；build/preview/sync/enabled:false 为无副作用空集成。
2. 默认处理 root 内 `**/*.astro`，支持相对 root 的 include/exclude；这也覆盖自定义 srcDir 及导入的模板，避免将用户磁盘路径嵌入 glob。必须 realpath root 内，排除依赖、生成目录、虚拟模块以及所有 query 子请求。
3. 在 Astro 编译前解析原文，用 AST 识别 intrinsic/custom-element；不修改组件调用、Fragment、slot、script、style。script/style 子树不处理，以保持 hoisting、作用域 CSS 与原始字符串语义。
4. 校验原文 `[node.start, name.end)` 恰等于 `<tagName`，只在名称后插入 source marker。保留所有用户属性原文，不扫描表达式、不重写 AST、不覆盖已有显式 marker。
5. 使用 Rust AST 的 UTF-16 offset，从原始字符串计算行/列；覆盖中文、emoji、CRLF。MagicString 输出高精度 map，相对路径，无绝对路径 marker。
6. 已有 marker 不覆盖并诊断；parser/位置异常整文件 fail-open，无部分输出；warning 按文件去重。动态 HTML/lit-html/第三方 island 内部没有可证明的模板标记时为 ancestor/unknown，不能称 exact。

## 读取、AI 与安全

通用源码读取新增 `.astro` 允许类型，仍仅限已登记文件与原有 realpath/大小/会话门禁。`.astro` 片段使用已有附近行预算裁剪，明确 `boundary:nearby-lines`，不把 frontmatter 当 JSX 解析或泄露整文件。

AI 复用通用配置、凭据解析与 Agent manager，默认 Review。在 Vite configResolved 后读取最终 mode/envDir，因此 CLI 自定义 mode 不会误用 development 凭据；只向浏览器传递脱敏配置。首版不提供 trustedFastMode 自动发现：单独 tsc 不能验证 Astro 模板。用户显式配置检查（如项目的 `pnpm check`），文档不得声称自动验证了 Astro。用户项目 `.env.local` 有专门凭据约束，试验仅用 fixture，不向真实宿主写 Key。

同一开发 origin 挂载已有本地 middleware；无独立端口，无代理重写，默认 loopback，禁止自行降低 Origin/token 检查。关闭时释放 middleware/Agent/registry。Runtime 仅用已脱敏配置，不携带 provider Key；Astro base 不改变内部协议根路径，必须在真实 base fixture 验证。

## 生命周期

`injectScript('page', ...)` 导入虚拟浏览器模块，不用 Vite transformIndexHtml 假设。复用 Runtime 单例 bootstrap；Astro `astro:before-swap` 释放旧 DOM 监听，`astro:page-load` 重新挂载；沿用现有 session draft storage。HMR disposal 清理事件和实例，普通页面刷新自然销毁。生产不注入上述任何代码。

## 验收与推进顺序

1. 完成 AST/顺序/注入的可运行探针后落定本方案，再实现。
2. 单测：AST 属性、spread、表达式、script/style、slot、Unicode、CRLF、已有标记、失败、query/root/filter、map；协议兼容与源码读取拒绝路径。
3. 真实 Astro 5/6/7 fixture：dev HTML/source marker/API、无 React、base、组件/slot、script 运行、CSS、ClientRouter、HMR/重启、build/preview 零残留。
4. 浏览器：选择 -> `.astro` 正确行列 -> Prompt；导航与 HMR 后单个工具实例。Agent 引擎集成测试通过有界 Git fixture 验证 Review -> diff -> Apply -> Revert；不调用真实收费 provider。完整浏览器 AI 操作链作为独立后续门禁，不用引擎单测冒充端到端通过。
5. 运行现有 TypeScript/lint/单测/包验证及相关 Vite/Next 回归。任何失败记录根因，修复后再扩大声明。
6. 中英文 README、包 README、架构/协议/兼容矩阵、安装命令、Changeset 同步；区分本地可安装包与尚未发布 npm 的包。不为支持工具迁移业务项目的框架。

本方案取代核心文档中“所有 source context 仅 jsx/tsx”的限定，但不扩大任何路径授权；其他核心安全与执行规范继续适用。后续发现冲突先更新本方案再实现。
