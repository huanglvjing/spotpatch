# 上下文问答：UI 状态机与交互规范

## 信息架构

Ask 进入现有唯一 Planner，不新增聊天抽屉或全屏页：

```text
Floating Surface / Planner
├── Header（品牌、当前选择、关闭/语言）
├── Mode switch: Ask | Change
├── Selection summary（1–20 个目标）
├── Ask scene
│   ├── 一个 question textarea
│   ├── suggested questions
│   ├── executor selector + capability
│   ├── data preview / consent
│   ├── submit / cancel
│   └── current answer card + sources
└── Change scene（现有逐目标 instructions/Agent/Handoff/Prompt）
```

模式切换是原生 button/tab 语义，具备 `aria-selected`、键盘左右切换和可见 focus。不得使用文本输入内容自动移动选中状态。

## Draft 所有权

Runtime 内存同时保留两个互不覆盖的草稿：

- Ask draft：一个 question、executor selection、当前 result；
- Change draft：每个 target 的 instruction、apply/provider selection 和可选 Ask origin。

切换模式不会丢失用户尚未提交的内容。selection 增删时：

- Ask 问题保留，但现有 Answer 标 stale；
- Change 只删除被移除 target 的 instruction，其他保持；
- 新 target 的 Change instruction 为空；
- 活动 Job 期间 selection 操作禁用或要求先取消，不让上下文悄悄变化。

首阶段 Ask draft/result 不写 `sessionStorage`，避免跨页面形成半实现会话；既有 selection draft 可继续跨页面。刷新/导航后用户需要重新提问。

## 空态与建议问题

至少一个目标后 Ask 显示 3–4 个本地静态建议，内容由目标事实决定，不调用模型：

- “这是什么组件，源码在哪里？”
- “这个元素的状态和文案从哪里来？”
- “为什么它现在不可见/不可点击？”（只有相关 DOM/CSS facts 时）
- 多目标：“这些元素之间是什么关系？”

建议点击只填入 textarea，不自动发送。建议字符串由本地化资源和集中模板生成，不能散落硬编码到 DOM 创建逻辑。

未选择目标时不展示可提交的 Ask composer；Pill/Planner 指引“先选择至少一个元素”。不提供“仍然询问整个项目”的旁路。

## 输入与提交

- 一个多行 textarea，显示真实字符计数和协议上限；
- `Enter` 换行，`Cmd/Ctrl+Enter` 提交；输入法 composing 时不提交；
- 空白、超限、无 executor、未同意、busy 时按钮 disabled，并有可读原因；
- submit 后 question 保持可见但只读，直到终态/取消；
- 不做自动重试收费请求；失败后用户点击 Retry 生成新 requestId；
- 关闭 Planner 不取消运行，Execution Island 保留；Start over 明确取消并清除。

## 执行器选择与同意

Selector 只显示 capability API 枚举的安全 label，例如：

```text
Configured Key · GPT …
Managed Codex · GPT …
```

不可用项默认不混入正常选择；“查看不可用原因”在诊断区域展示稳定错误和操作。不得显示 Base URL、Key env、Codex path、绝对 workspace 或原始厂商错误。

首次对某 executor 发送项目数据前显示：选中目标数、候选源码文件数量、是否包含当前未提交内容、DOM/CSS/code 类别、截断状态、executor/model label 和第三方数据政策提示。Key/Codex 同意按当前 dev Session 和 executor profile 记录；context 改变不静默扩大授权文件范围。用户可展开本地 normalized preview，但 secret 已在源头排除。

## 状态与文案

| Job 状态 | Planner | Execution Island | 主操作 |
| --- | --- | --- | --- |
| editing | question/executor | 无 | Ask |
| queued/authorizing | 正在准备上下文 | PREPARING ANSWER | Cancel |
| running，无读取 | 正在理解所选元素 | ANSWERING | Cancel |
| running，有读取 | 最近真实 source activity | READING SOURCE | Cancel |
| cancelling | 正在取消 | CANCELLING | disabled |
| answered | Answer card | ANSWER READY | New question / 转修改 |
| cancelled | 保留问题与取消说明 | 返回 Planner | Retry |
| failed | 稳定错误、诊断和恢复 | ANSWER FAILED | Retry/改选 |

禁止使用“正在修改”“已应用”“检查通过”描述 Ask。没有可证明进度百分比；不展示模型 reasoning、Codex plan、虚构文件读取或 token 估算。

Ask 使用现有持续 Shell：Planner → answering island → answer ready → Planner。Motion 只消费真实 Job 状态；answer ready 不自动清空 selection。`prefers-reduced-motion` 直接切 Scene，所有状态信息仍完整。

## Answer card

Answer card 包含：

1. executor/model 安全 label 和回答时间；
2. 结构化 paragraph/list/code blocks；
3. 每块末尾的小型来源 chips（如 `Button.tsx:42–58`）；
4. 合并后的“源码来源”列表，显示 target 关联和置信度；
5. stale/截断/证据不足 warning；
6. Copy、New question、根据回答创建修改。

渲染规则：

- 普通文本使用 `textContent`；换行由 CSS 处理；
- code 使用 `<pre><code>` 纯文本，不做 HTML syntax renderer；
- link 只有服务端已解析 source ref 的内部 open-editor button；模型 URL 不自动成为可点击链接；
- source chip 是原生 button，标题/accessible name 包含文件和行范围；
- 引用点击先请求服务端打开；stale 时弹出明确警告/重新采集动作；
- Copy 输出纯文本答案，并附相对路径/行范围；不复制隐藏 prompt、hash、绝对路径或 provider 信息。

没有引用的答案不能以“已确认”视觉展示。允许回答“当前证据不足”，并把已知选择 facts 作为来源；完全无合格 source 时 Job 应失败或返回明确 unknown warning，不能伪造 `Source 1`。

## 转为修改草稿

按钮文案必须是“根据回答创建修改”，不能是“立即修复”。点击后：

- 本地构造 `AskDraftOrigin`，切换 Change；
- 在 Change 顶部显示可折叠“问答来源”，而不是把完整答案复制进每个 textarea；
- 保留/恢复逐目标 instruction；没有 instruction 时焦点进入第一个目标输入；
- Run/Send 仍 disabled，直到 Change 自身必填、能力和同意全部满足；
- 写任务开始前 Node 重新授权 selection/source，Ask source handle 不授予写权限；
- stale/expired Ask 仍可作为可见参考，但必须标记，且 Change 不依赖服务端旧正文才能编辑。

这样满足一步进入修改流程，同时保留 ADR-014 的逐目标 instruction 所有权。

## 焦点、响应式与无障碍

- Planner 打开 Ask 时焦点进入 question；Answer 返回不抢走当前焦点，live region 简短宣布“答案已返回”；
- Cancel/failed 后焦点回 submit/retry；切 Change 后进入首个未完成 instruction；
- Tab 顺序：模式 → selection → question → suggestions → executor → preview/consent → submit → answer actions/sources；
- 320 CSS px 宽度与 200% zoom 下不横向溢出；source path 可中间省略但 accessible name 保持完整；
- 色彩不是唯一状态信号；所有 icon 有文本/aria-label；
- code/source list 有界滚动，页面主内容不被锁死；
- Escape 遵循既有 Shell 规则，只收起表面，不把运行 Job 当作已取消。

## 视觉质量验收

必须用真实 Chromium 截图审阅：无目标、单/多目标、consent、Key/Codex running、长中文/英文答案、代码块、64 引用上限、stale、失败、320px、200% zoom、dark/light 宿主页和 reduced motion。UI 完成不能只靠 jsdom DOM 断言。
