# 组件数据链路实仓审计与支持矩阵

本页只维护实证；需求解释 (见 doc-id:data-flow-01-requirements)，归属和数据来源规则分别见 (见 doc-id:data-flow-04-static-attribution)、(见 doc-id:data-flow-06-data-provenance)。现有 marker、Runtime 选择和源码置信度基线分别以 (见 doc-id:04-vite-plugin)、(见 doc-id:05-runtime-lifecycle)、(见 doc-id:06-source-resolution) 为准。

## 审计口径

本页只记录可复核的仓库事实，不用产品愿景替代实现。请求统计范围为目标项目 `src/**/*.{js,jsx,ts,tsx}` 中创建业务 HTTP 请求的调用点；不把图片、视频、iframe、脚本和样式等资源加载计入 147。

计数采用 TypeScript AST 对 import binding 与 call expression 分类，再人工复核登录、表格、动态 URL、stream、Blob 和 Store 样本。未来必须把同一逻辑固化为版本化 manifest 生成器和人工 oracle；只有生成器、冻结 commit 与 oracle 同时记录，数字才可用于发布门禁。

审计时目标工作树只有 `package.json`、`vite.config.ts` 两个既有修改，`src/**` 没有本地修改，因此本页源码调用点对应 `de590c3`；依赖声明按当时工作树读取为 React `^18.3.1`、AntD `^5.25.2`、Zustand `^5.0.5`、Axios `^1.9.0`、Vite `^6.3.5`、`@spotpatch/vite ^1.7.0`。由于 `package.json` 本身是 dirty，这组依赖是“审计时工作树事实”，不能伪装成该 commit 的干净 manifest；正式 fixture 必须另存 lock hash。

## SpotPatch 当前能力

基线 `main@396e20a` 的实际结论：

| 当前路径 | 已有事实 | 对本需求的缺口 |
| --- | --- | --- |
| `packages/compiler/src/inject-source-markers.ts` | 只给 intrinsic JSX 注入 marker | AntD 等复合组件 callsite 无精确 marker |
| `packages/react-adapter/src/bippy-adapter.ts` | 提供组件名、组件栈、React 18 probable source | 不导出 fileId、props、state、Context 或请求链 |
| `packages/runtime/src/source/source-resolver.ts` | marker → React source → ancestor marker → unknown | 复合按钮可能只落到祖先根节点 |
| `packages/dev-server/src/server/extract-code-context.ts` | 可找包围组件或附近代码 | 不能跨 `.ts` Store/API 建调用图 |
| `packages/runtime/src/controller/runtime-controller.ts` | 采集 DOM/CSS/source；选择 click 阻止宿主事件 | 没有 recorder；选择按钮不会提交 |
| `packages/shared/src/model/annotation.ts` | 目标上下文只有 page/source/react/element/styles/code/warnings | 没有 dependency/observation/provenance 模型 |
| Vite Runtime 注入 | 当前以 `head` module script 注入 | 不是已证明早于首个业务请求的同步 prelude |
| source filter/registry | `.jsx/.tsx` | 漏掉常见 `.ts/.js` API、Store、route |
| selection session | 清洗后上下文写入 sessionStorage | 新 observation 和 response shape 不得自动加入 |

因此当前发布版不能在选中组件后准确显示其接口。此需求是新子系统，不是给现有 summary 增加几个字段。

## 目标项目请求清单

| 指标 | 结果 | 设计影响 |
| --- | ---: | --- |
| 业务请求调用点 | 147 | 锁定实仓回归分母 |
| 包含请求的源文件 | 67 | `.ts/.tsx` 必须进入模块索引 |
| 自定义 Axios `http` | 141 | 首个项目级 adapter |
| 直接 `axios.get` | 2 | 识别官方 method binding |
| 原生 `fetch` | 4 | 1 流、2 签名 URL 上传、1 Blob 下载 |
| WebSocket/EventSource/Beacon/手写 XHR | 0 | 当前快照无样本，不代表通用不需要 |
| page/component/layout 内调用 | 110（74.8%） | 多数可从组件边界直接开始 |
| Store/API/util 共享层调用 | 37（25.2%） | 必须反向调用图或 invocation provenance |

### URL 可解析性

| 写法 | 数量 | 静态结论 |
| --- | ---: | --- |
| 字符串字面量 | 122 | 精确 path |
| 可常量折叠的 `API_BASE` template | 13 | 精确 path |
| build-mode 条件 | 2 | 列出分支；结合当前 mode 后唯一 |
| 含运行时 path/query 片段的 template | 6 | 精确 template；执行后给安全 URL 表示 |
| 标识符 URL | 4 | 只在执行后给安全 URL 表示 |

因此 137/147（93.2%）可静态得到精确 path 或全部显式构建分支，143/147（97.3%）可得到可审计 URL template。后 4 个不得静态伪造 URL；执行经过 recorder 后才生成 observed 安全表示，其中非敏感 origin/path 可精确显示，签名、query 和敏感动态片段按策略隐藏。

### 参数与响应

- 56 个 POST 在调用点直接传 object literal body。
- 30 个 POST 传 `params`、`values`、`submitData` 等标识符 body，需要局部 def-use 或 runtime shape。
- 12 个 GET 有 config object，可解析 `params`；35 个 GET 没有第二参数。
- 至少 94 个 `http` 结果显式标为 `any`，TypeScript 无法给出可靠响应字段全集。
- 原生 fetch 同时覆盖 stream、签名上传和 Blob，UI 必须按传输类型显示，不能统一调用 `response.json()`。

## 登录按钮证据

### 默认短信登录

```text
src/pages/login/index.tsx:111-114
  setData("loginType", "sms")
  → src/pages/login/components/sms-login.tsx:187-230
    Form.onFinish + Button htmlType="submit"
  → sms-login.tsx:38-65
    smsLogin(loginParams, handleSuccess)
  → src/stores/modules/user.ts:216-220
    POST /v2/auth/login
```

body 的可证 key 为 `phone`、`code`、`inviteCode`、`from`；特定条件增加 `captchaId`、`captcha`、`callback_url`、`state`。`/v2/auth/sms` 是“获取验证码”操作，`/base/captcha` 是图形验证码操作，均不是提交按钮的主登录接口。

### 密码登录

```text
src/pages/login/components/account-login.tsx:93-117
  Form.onFinish + Button htmlType="submit"
  → account-login.tsx:26-55
    login(loginParams, handleSuccess)
  → src/stores/modules/user.ts:72-76
    isEN ? POST /auth/email/login : POST /base/login
```

body 的可证 key 为 `name_or_phone`、`password`、`inviteCode`、`from`；条件字段同上。`showCaptcha` 为真时还可能请求 `/base/captcha`，必须作为并行/辅助请求，而不是把按钮显示成只有一个永恒 endpoint。

### 登录后 follow-up

`src/pages/login/index.tsx:81-92` 表明普通成功路径会请求 `GET /user/firstRechargeEligible`；授权续流在 `:32-79` 改为 `GET /auth`。这些请求属于 login-success callback，不是登录提交的主认证请求。页面 `:116+` 还会在已有有效登录标记时检查用户信息；无标记时不执行。

## 微信查询接口证据

`src/pages/login/components/wechat-login.tsx` 的真实链路为：

```text
useEffect(:95-102)
  → GET /wechat/login (:19-27)
  → scene_id
  → setInterval 每 2000ms (:38-45, :93)
  → POST /wechat/query (:60-65)
```

- 参数：`scene_id`；条件性 `callback_url`、`state`（`:45-57`）。
- 实际读取：`code`、`data.open_id`、`data.token`、`data.expires_in`、`data.user`、`data.redirectUrl`（`:65-81`）。
- 生产 `VITE_APP_API_URL` 下可形成 `POST https://api.shengsuanyun.com/wechat/query`；其他 mode 的 base URL 不同。
- 触发归属是 `WechatLogin` mount/timer，不是短信或密码登录按钮。

这正是“相同页面出现一个接口”不能推出“选中按钮调用该接口”的反例。

## 表格数据来源证据

目标项目有 17 个渲染 AntD `<Table>` 的源码文件，至少 15 处 `dataSource` 是局部变量、props 或 Store 值。锁定三类 oracle：

| 类型 | 证据链 | 期望关联 |
| --- | --- | --- |
| 直接请求 | `model-mesh/log/index.tsx:93` GET `/modelmash/usage/...` → `:96` `setData(result.data.list)` → `:169` `dataSource={data}` | origin=current；fed-by=current response |
| Store 间接 | `serverless/rule/components/billing -rule.tsx:7-10` `getHardware()` → `stores/modules/serverless.ts:27-29` GET `/hardware/gpus` → Table `:54` `hardwareData` | origin=component via Zustand；fed-by=Store field |
| 父传子 | `model-mesh/list/info.tsx:23-25` GET `/modelmash/${params.id}` → `:84` `modelInfo.channels` → `channels.tsx:74` `tableData` | origin=parent；selected child=upstream |

若只按“选中组件函数体内有没有 fetch”判断，后两类都会出错。

## 客户端存储事实

- `src/stores/modules/user.ts:389-396` 的 Zustand persist 名为 `user`；`loading`、`showCaptcha`、`token` 被排除，其余 state 由默认 storage 持久化。
- `src/utils/http.ts:41-57` 的 Axios instance 使用 `VITE_APP_API_URL`、`withCredentials`、`X-Auth-Token`，开发环境可增加 `x-token`。
- `src/utils/auth.ts` 中生产登录态依赖后端 HttpOnly Cookie；开发联调会使用 `ssy_token`、`ssy_token_expires`，另有 `ssy_login` 标记。
- UI 只可显示 storage/header key、用途、读写方向与环境条件，不显示实际 token/cookie/header 值。
- 当前前端仓库没有登录后端 handler 或数据库 schema，所以服务端持久化只能是 unknown。

## 基线支持判断

| 能力 | 当前 SpotPatch | 目标 Beta | 结论 |
| --- | --- | --- | --- |
| DOM → intrinsic JSX | 已支持 | 保持 | 可复用 |
| DOM → AntD Button callsite | probable/ancestor | stable component/trigger ID | 必须补齐 |
| `.ts/.js` 模块索引 | 不支持 | 授权 root 内支持 | 必须补齐 |
| Axios/fetch 声明分析 | 不支持 | 147/147 callsite ID | 必须新建 |
| fetch/XHR 实际观测 | 不支持 | 页面加载起捕获 | 必须新建 |
| 组件精确归属 | 不支持 | 有证据 100% precision | POC 阻断 |
| Table data-fed-by | 不支持 | 17 文件 oracle 100% | POC/适配器阻断 |
| 数据库表 | 无后端证据 | unknown | 不得猜测 |
| AI 辅助 | 现有 Agent 可复用 | 显式、已清洗解释层 | 不新建 AI 客户端 |

## 基线漂移规则

以下任一变化都会使计数和百分比失效：目标 commit 变化、依赖版本变化、请求 wrapper 变化、sourceRoots 变化、AST 分类器版本变化。CI 报告必须同时输出 `repositoryCommit`、`manifestSchemaVersion`、`analyzerVersion`、`dependencySnapshotHash` 和人工 oracle 版本；无法重现时不能声称通过实仓验收。
