# 外部 Agent 连接：交互、性能与可观测性

## 交互入口

外部交接是现有工作台的第三条执行路径：

1. 复制 Prompt；
2. 使用 SpotPatch 内建 AI Agent；
3. 发送到已连接的主动 Agent；没有主动 adapter 时降级为外部 Agent Inbox。

三者复用同一个目标集和逐目标说明，不复制编辑器，不互相强制启用。外部能力关闭时第三个入口完全不渲染，也不请求 capability。

## 发送流程

### 初始状态

面板显示“连接外部 Agent”入口和本地能力摘要。只有服务端配置启用且 Broker ready 时交接入口可用：

- 当前 dev Session 有一个 SpotPatch 管理的主动 adapter 且 `ready`：主按钮为“发送给 Agent”，并显示实际 kind 与实验/稳定级别；这不表示其他 Generic MCP 宿主不能读取 Inbox；
- 主动 adapter `busy`：按钮禁用，展示当前 revision 的有证据 phase；
- 无主动 adapter：按钮语义降级为“发布到 Agent 收件箱”，提示需要在 Agent 中读取；
- MCP 是否已被某个产品配置无法仅凭文件推断；没有 Broker 观测时只能显示“尚未观察到连接器”，不能显示“未安装”。

### 首次披露

当前开发 Session 第一次发送前显示：

- 将发布目标数量和相对文件；
- 包含说明、组件、页面、DOM/CSS 和有界源码上下文；
- 本项目中任何连接的 SpotPatch Agent Connector 都可能在 TTL 内读取；
- Agent host 可能把内容发送给其云端 Provider；
- 外部修改不具备 SpotPatch 内建 worktree/Apply/Revert 保证。

用户确认只在内存保存到当前 dev-server Session 结束。后续每次仍必须点击明确的发送按钮；披露确认不能变成后台自动发送授权。

### 发布前校验

- 至少一个目标；
- 每项目标 instruction trim 后非空；
- 没有仍在采集中的目标；
- revision/source identity 当前；
- 总体积和目标数量未超既有公共上限；
- 用户可以展开预览每项目标文件、说明和数据类别。

校验失败聚焦对应目标，不创建部分 revision。

### 发布反馈

Inbox 按钮状态：`idle -> validating -> publishing -> published | failed`。主动模式状态为：

```text
ready → validating → publishing → queued → dispatching
      → dispatched → working → completed | failed | delivery-unknown
      → ready（仅 completed/failed 后）
```

网络/授权成功后显示：

- “已发布 revision N，15 分钟内可读取”；
- 当前等待 Connector 数量（只在 >0 时显示）；
- “连接器已取走 X 次”及最近时间，文案不使用“Agent 已修改”；
- “复制 Agent 提示”与“查看连接设置”。

主动模式另外显示 adapter kind 和 dispatch phase。Runtime 通过严格 `ExternalHandoffStatusResult` 轮询当前 cursor 的精确 dispatch，不从 pickupCount 或旧 capability 猜测。`dispatched` 的提示必须按宿主区分：Claude 为“事件已写入 Channel，等待 Agent 确认”，Codex 可在 `turn/started` 后显示“正在执行”。`completed` 文案必须补充“该轮已结束，不代表改动正确或测试通过”。

发布与 active dispatch 非终态期间按钮禁用，服务端也拒绝第二次请求。首版无任务队列、latest-wins、自动合并或 steer；完成/明确失败回到 ready 后，下一次点击创建新 revision 并立即触发同一常驻 Connector。

## 连接状态语义

| UI 状态 | 可验证事实 | 推荐动作 |
| --- | --- | --- |
| `disabled` | 可信配置未启用 | 提供文档，不显示发送 |
| `unavailable` | 配置启用但 Broker 初始化失败 | 查看本地诊断，仍可复制 Prompt |
| `ready-unobserved` | Broker ready，未观察到 wait/get | 设置 MCP 或在 Agent 中读取 |
| `waiting` | 至少一个 Connector 正在有界 wait | 发送后可快速唤醒；多个时提示都可能收到 |
| `published` | 当前 snapshot 可读取 | 在 Agent 中读取当前交接 |
| `picked-up` | 至少一个 Connector 已取走 | 在对应 Agent 查看后续，不推断执行 |
| `adapter-ready` | 一个主动 adapter lease 有效且无 active dispatch | 点击后会走该 adapter；不代表宿主永远在线 |
| `queued/dispatching` | Broker 已为本 Session 的受管 adapter 预留 / Connector 正在调用厂商边界 | 等待 adapter 特定证据；按钮禁用 |
| `dispatched` | Claude Channel transport write 已完成，或 Codex `turn/start` 成功响应已匹配 | Claude 仍等待 exact-cursor 取件；两者都不等于任务成功 |
| `working` | Codex turn 已 started，或 Claude 已通过 exact-cursor tool 确认；不证明已读文件、正在编辑或已产生 diff | 在对应 Agent 查看；按钮禁用 |
| `completed` | Codex turn completed 或 Claude 显式上报完成 | 核对 diff/checks；随后 adapter ready |
| `failed` | 已证明任务未成功交付或宿主明确失败 | 修复原因后重新点击 |
| `delivery-unknown` | 可能已经交付，但确认丢失/连接中断；受管 writer 已停止 | 先核对工作区，点击“已核对工作区，允许新任务”只解除 hazard；需要时重新连接 adapter，SpotPatch 不重试旧任务 |
| `expired` | TTL 到期，正文不可读 | 重新核对并发送 |
| `superseded` | UI 查看的是旧 revision | 切换到最新 revision |

Connector 进程启动但从未调用 Broker 时，SpotPatch 没有可靠在线证据；UI 不能通过扫描进程名、端口或厂商配置猜测在线。

## “点击即收到”的分级体验

| 档位 | 用户动作 | 保证 |
| --- | --- | --- |
| 零配置降级 | 复制 Prompt | 手工粘贴，最通用 |
| MCP 当前读取 | 先发送，再在 Agent 请求读取 | 当前 revision 在 TTL 内可取 |
| MCP 等待态 | Agent 先等待，页面随后发送 | tool call 存续期间低延迟唤醒 |
| Claude 主动 Channel（实验） | 运行中会话已显式启用后页面发送 | 立即写 Channel transport；Channel 无 completion ACK，working/terminal 依赖取件/结果 tool |
| Codex 主动 App Server（实验） | 常驻 Connector ready 后页面发送 | 立即 `turn/start`；结构化 turn 状态 |

标准 MCP 基线不允许 UI 使用“已推送到对话”。“等待态”也只有在 Agent 已发起工具调用且调用未超时期间成立。主动文案只在目标 dev Session 的 active lease 存在时启用，并严格受 (见 doc-id:external-agent-09-active-dispatch-adapters) 的宿主限制约束；不得把该内存 lease 表述为所有编辑器/进程的全局单 writer。

## 多目标与更新交互

- Handoff revision 固定目标顺序和逐项目标说明。
- 发布后继续编辑说明不会改变已发布 snapshot；UI 显示“有未发送更改”。
- Inbox 模式再次发送创建新 revision；旧 Agent 可能仍按旧 revision 工作，SpotPatch 不自动打断。
- 主动模式在当前 dispatch 非终态时禁止再次发送；不存在“旧任务工作时创建新主动 revision”的隐式分支。
- 若 current 已 picked-up 且用户再发，显示“将发布新版本；已取走的旧任务不会被撤回”。
- 目标选择因 HMR/source stale 失效时，发送入口禁用并要求重新采集。

## 设置体验

当前 Runtime 实现是一个紧凑的 `details` 命令列表，尚不是带 required/observed/unsupported 卡片、配置文件预览或“测试连接”的完整设置页。列表只按 Vite/Next 框架发布一组静态、不含 secret 的本地启动示例：

- Claude active setup dry-run，以及对宿主进程设置 legacy env 的 `MCP_PROTOCOL_NEGOTIATION=legacy claude --dangerously-load-development-channels server:spotpatch`；
- Codex 主动模式只显示一条零配置 `connect codex --allow-workspace-write`；可选 Inbox setup 不作为主动连接前置；
- Cursor Inbox setup dry-run，Cursor 和其他普通 MCP 宿主仍是 Inbox-only。

Runtime 中的 `node ./node_modules/@spotpatch/<framework>/dist/cli.js ...` 只是当前项目锁定入口的可复制命令，不是 Node 返回的动态能力卡片，也不包含 JSON/TOML 配置模板。`setup` 默认只 dry-run；用户必须明确加 `--write` 才会落盘。Codex 主动 connect 不走 setup，也不写项目 Codex 配置；同根有多个 dev Session 时，主动命令仍要使用 `sessions --json` 列出的 opaque `--session <id>`，当前简表不猜测该短期 ID。

持久 Inbox 的 JSON/TOML 路径与 thread 级 SpotPatch MCP command/args 都由同一个锁定版本生成器维护；Codex 的两种入口还共用同一固定运行目录 `env_vars` 名称白名单，Runtime 不保留第二份配置模板。主动功能当前为 `local-validation`：Claude 真实连续双次 E2E 仍为 `not-tested`；Codex 已在记录的 macOS/Next.js/Codex 0.149.0 环境人工完成连续两 revision，跨平台和可重复真实宿主自动化仍未完成。

## 可访问性与本地化

- 所有状态使用文本 + 图标，不只依赖颜色；发布/失败使用 `aria-live="polite"`，安全错误使用可聚焦 alert。
- 首次披露为可键盘操作的模态边界，焦点进入、循环和返回遵循现有 Shadow DOM 规范。
- 按钮有稳定 accessible name；loading 不移除原按钮，使用 `aria-busy`。
- cursor/revision、相对路径和时间可复制，但 token/端口不可见。
- 中英文固定文案进入现有类型完备消息表；项目内容不翻译。
- 快捷键仅在工作台打开且焦点不在可编辑控件时生效，并与按钮走同一校验/披露流程。

## 集中限制（当前实现值）

以下是外部 Handoff 专用值的唯一文档来源。代码集中在 `EXTERNAL_HANDOFF_LIMITS`，由 Schema、Store、Broker 和测试引用；发布前只能调低，调高需 ADR：

| 限制 | 目标值 | 理由 |
| --- | --- | --- |
| 完整 snapshot 最大序列化字节 | 256 KiB | 与现有 Agent 创建请求量级一致，控制 MCP 结果与内存 |
| Browser publish body 最大字节 | 256 KiB | 在 JSON 解析前阻断；不为 Handoff 放大既有例外 |
| Broker 非正文请求最大字节 | 8 KiB | 参数只有 cursor/session/timeout/instance ID |
| 单个发现描述符最大字节 | 8 KiB | 描述符只含连接元数据，不得承载正文 |
| current 正文数量 | 1 / Session | 避免多份源码常驻 |
| 旧 Summary 数量 | 8 / Session | 支持 UI 回执，不保留旧正文 |
| 单 revision 取件实例数 | 64 | 对 connector instance 去重并限制内存增长 |
| Handoff TTL | 15 分钟 | 足够晚启动 Agent，同时限制暴露窗口 |
| wait 默认 / 最大时长 | 20 秒 / 25 秒 | 低于常见 30 秒 tool timeout，真实值由客户端 POC 取最小兼容值 |
| 同 Session 并发 waiter | 8 | 覆盖多个 IDE/对话，阻断资源耗尽 |
| 一次扫描发现描述符 | 32 | 多项目开发足够，避免无界目录扫描 |
| cwd 向上发现层级 | 64 | 支持 monorepo 子目录，同时阻断异常无界遍历 |
| Broker header 总量 | 8 KiB | 无自定义 header 需求 |
| Broker 同时 socket | 32 | 包含 wait 和短请求；超限快速拒绝 |
| 单描述符探测超时 | 750 ms | 快速排除陈旧或不可达本地会话 |
| Broker 短请求绝对超时 | 2 秒 | status 之外的 current/ack 快速失败，不继承长 wait 超时 |
| wait 传输宽限 | 2 秒 | 在请求的有界 wait 之后留出本地序列化与传输时间 |
| 设置读取最大字节 | 1 MiB | 在解析已有 Agent 配置前阻断异常大文件 |
| requestId 幂等记录 | 16 / Session | 覆盖响应丢失与并发重复，不形成长期任务历史 |
| active adapter 心跳 / lease | 3 秒 / 10 秒 | 快速识别断线，同时允许短暂事件循环抖动 |
| active dispatch 最大存续 | 30 分钟 | 防止未上报的 Claude 任务永久占用；超时只判 unknown，不重试 |
| 单条 App Server JSONL | 1 MiB | 在解析前限制厂商输出；不收集流式正文 |
| App Server stderr 有界尾部 | 64 KiB | 只用于本地脱敏故障分类，不无限积累 |

annotation 的目标数、说明字符、DOM/CSS/code 字段和 URL 清洗上限继续引用现有公共模型，不在本页复制数值。

## 延迟与资源预算

在 required 性能 fixture、温热 Source Registry、现有公共最大目标数和 256 KiB 上限内：

| 指标 | 目标 |
| --- | --- |
| 页面点击发送到 Node 返回 published p95 | `<= 100 ms` |
| 已存在 wait 到 MCP tool 获得 snapshot p95 | `<= 250 ms` |
| 已 ready 主动 adapter 从 publish 完成到开始宿主 dispatch p95 | `<= 250 ms` |
| 已运行 Codex App Server 的 `turn/start` 接受 p95 | `<= 500 ms`，不含模型推理与首次进程启动 |
| Browser 主动状态可见新鲜度 | `<= 2 s`，使用有界 polling；不为本机状态额外引入 WebSocket 服务 |
| Connector 冷发现 + get p95 | `<= 300 ms`，不含 Agent host 启动 |
| Broker 空闲 CPU | 无忙轮询；5 分钟平均 `< 0.2%` 单核 |
| Manager + 单 current 增量 heap | `< 2 MiB + snapshot 字节` |
| Connector 空闲 heap | POC 建立基线；不得因历史 revision 线性增长 |
| dev-server dispose | `<= 1 s` 关闭 wait/socket/描述符 |
| 无人连接时对组件选择 p95 回归 | 测量噪声内，且不得新增每次 hover/click 文件 I/O |

延迟从同一 monotonic clock 记录阶段时间，不把 Agent 模型思考、文件修改和测试耗时算作 handoff 延迟。

## Runtime 包体策略

现有核心 Runtime 已有严格 gzip 门禁，不能把 MCP SDK、Broker client、设置模板或客户端矩阵打入浏览器。当前实现：

- MCP SDK 只在 Node Connector；
- Runtime 只包含小型 UI/controller 和 Browser API Schema；
- 完整设置模板只存在于 Node setup 生成器；Runtime 仅展示不含 secret 的短命令；
- 外部交接 UI 是启用时才加载的 dev-only chunk，并有独立包体门禁；核心 Runtime 只保留小型扩展契约；
- 任何提高现有核心预算的方案都要单独 ADR，不能以“功能新增”为由静默放宽。

## 可观测性

### 本地阶段指标

仅在 debug 模式写脱敏事件：

- manager init/dispose；
- Broker bind/close（端口只允许 debug 本地显示，不进入浏览器）；
- publish accepted/rejected、targetCount、serializedBytes、duration；
- waiter opened/resolved/timeout/cancelled、当前计数；
- get/ack outcome、revision、duration；
- descriptor create/remove/stale cleanup outcome；
- active adapter claim/heartbeat-expiry/release、dispatch phase、adapter kind、duration；
- App Server spawn/initialize/thread/turn 的结构化 outcome（不记录 thread/turn ID）；
- 错误码和阶段。

Codex Connector 的默认人类终端输出不需要打开 debug，但只是上述结构化状态的有界投影：

```text
Codex connected and ready for SpotPatch requests.
SpotPatch is preparing revision N for Codex.
Codex accepted revision N.
Codex started revision N.
Codex turn ended for revision N; review the workspace. Ready for the next request.
Revision N failed before a verified Codex turn completed; review the connector output and workspace. Ready for the next request.
Codex delivery for revision N is unknown; the connector will stop.
```

其中 `ready` 在 active claim 成功后输出；`preparing` 只表示 Broker 已进入 `dispatching`；`accepted` 来自匹配的 `turn/start` response；`started` 来自匹配的 Codex `turn/started`；terminal 来自 Broker 已接受的匹配协议终态。缺少源码位置等厂商写入前拒绝路径只会出现 `preparing → failed`，不能误报 Codex 已收到。输出观察器异常被隔离，不能改变派发成败或 lease 状态。

禁止日志：annotation 正文、instruction、DOM/CSS/code、页面 query value、相对/绝对文件路径、token/lease、完整 cursor、账号/模型、厂商 thread/turn ID、MCP 对话、App Server 流式文本或命令输出。adapter kind 属于有限诊断枚举，可以记录；不得从进程名猜测其他 Agent 产品。

### 诊断快照

本地 UI/CLI `doctor` 后续可以返回：

- enabled/brokerReady/protocol versions；
- Session 数量、current revision 是否存在、等待者/取走计数；
- active adapter kind、ready/busy、最近 dispatch phase（不含实例/会话 ID）；
- 发现目录是否满足权限（只返回 pass/error code）；
- required client 配置是否能解析（不回显完整配置）；
- 最近有界错误码和阶段。

诊断不能读取或回显 HandoffSnapshot。用户若需要内容核对，应在现有预览 UI 或显式 MCP get 中查看。

### 遥测

首版为零产品遥测：不向 SpotPatch、Claude、Cursor、OpenAI 或第三方发送连接事件。外部 Agent host 的自身遥测不在 SpotPatch 控制范围，首次披露需说明。未来增加 opt-in telemetry 必须另立隐私设计与 ADR。

## 性能失败策略

- snapshot 超限：发布整体失败，告诉用户减少目标/上下文；禁止截掉某个目标后继续。
- Broker 过载：新 wait 返回稳定 busy/retry-after，current get 优先；不杀已有请求。
- Source 重读超时：返回 source stale/unavailable，不发布浏览器旧片段。
- Connector result 超过客户端实测上限：在发布 Gate 中调低集中 snapshot 上限；不能在某个客户端静默裁剪。
- 包体超限：拆为启用时加载的私有 chunk或优化；不得删除安全披露/Schema 以“过指标”。
