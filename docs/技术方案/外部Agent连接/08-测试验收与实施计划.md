# 外部 Agent 连接：测试、验收与实施计划

## 执行原则

实施遵循“官方/本机阻断式可行性核验 → 公共契约 → Node 核心 → Event Pump/adapter → Runtime → 完整客户端/平台矩阵 → 发布”的顺序。Generic MCP Inbox 与主动 adapter 分别设 Gate：某个实验 adapter 可以被整层禁用，但不能用它的失败破坏 Inbox；同样也不能用 Inbox 通过来宣称“一次点击已主动执行”。

## Gate EA-0：文档评审

进入任何代码变更前必须确认：

- 产品接受“单击只选择、明确发送才发布”；
- 产品接受“标准 MCP 是 get/wait，不保证通用主动消息”；
- 产品接受 Generic Connector 对项目内容只读、Claude attached 不承诺 SpotPatch worktree/Apply/Revert；Codex managed 只有通过 ADR-037 独立快照/checks/apply Gate 才可声明 SpotPatch 审计；每 dev Session 仍是单受管 writer、单飞行，Generic Inbox 消费者和相同 root 的其他 dev Session 不受该内存 lease 排他；
- 项目 Inbox 可能被同项目多个 Connector 读取；
- 主动模式不广播，busy 时拒绝，不 queue/latest-wins/steer，投递未知不重试；
- 首版 local-only，不覆盖 ChatGPT 网页版、远程容器和跨机器；
- ADR-035 从 Proposed 更新为 Accepted；
- ADR-036 接受“Broker 事实源 + Bridge Event Pump + 宿主能力 adapter”，并记录 Claude Research Preview/Codex 专用 runtime 边界；
- ADR-037 接受 Codex managed 的 Supervisor、固定 grant、独立快照、显式 checks、四状态轴和固定降级，并只取代 ADR-036 的 Codex 直接写目标；
- 本专题文档链接、术语、状态和唯一事实源检查通过。

EA-0 未通过时不得创建 package、Schema、endpoint 或依赖。

## Gate EA-1A：编码前阻断式可行性 POC

POC 必须放在后续约定的实验目录或独立临时分支，不进入公共 exports，不发布包。必须产生可重复记录，而不是本机截图。

### POC-1：协议与本机客户端可行性

使用最小只读 stdio server，通过官方 SDK client/Inspector 完成协议调用闭环，并对本机已安装的 Claude Code、Cursor、Codex 做配置解析和可执行性记录：

- tools/list 和四个目标 tool 的发现/调用；
- structured content、text 和 256 KiB 边界附近结果的协议完整性；
- 20/25 秒 wait、超时和 client 取消；
- 多次/并发调用、stderr 显示和 server 重启；
- 本机可观察到的 MCP roots、启动 cwd、项目级配置和审批默认值；
- resources/prompts 只做 observed 记录，不计 required 成功。

阻断：官方协议 client 无法稳定调用 get/wait、结果在协议层被截断、取消无法释放请求，或任一本机已安装 required 客户端明确证明 stdio 基线不成立。未安装或不能无交互验证的客户端必须记为 `not-tested`，不得伪造通过；它们由 EA-1B 和 EA-6 继续阻断 beta/released。

### POC-2：本地 Broker 与发现

先在当前开发 OS 验证以下实现可行性；macOS、Ubuntu、Windows 完整矩阵移交 EA-1B/EA-6：

- 绑定实际 `127.0.0.1:0`、获取端口、token handshake；
- 用户私有发现目录、POSIX owner/mode、Windows ACL；
- 原子 descriptor、崩溃遗留、PID 复用、端口被新进程占用；
- cwd/MCP root 的 projectKey 计算、symlink root、大小写和 Windows volume；
- get/wait/ack 延迟、取消、并发上限和 dispose；
- LAN、DNS rebinding、proxy env、redirect 和伪造 descriptor 全部失败。

阻断：当前 OS 无法建立用户私有发现边界、跨项目可串读、Broker 可被 LAN 访问或快照必须落盘才能工作。Windows ACL 未验证时 Windows 支持必须保持 `not-tested`，不能阻断在其他平台编写共享实现，但会阻断跨平台发布声明。

### POC-3：Vite / Next 装配可行性

- Vite loopback/LAN 两种宿主 bind 下，Broker 始终只在 loopback；
- Vite HMR 不重建 Manager，dev-server 重启会轮换 Session；
- Next Sidecar browser rewrite 与独立 Broker 并存，CLI/Sidecar 整组退出无残留；
- `vite build`、`next build/start` 不启动 Broker、不写 descriptor、无协议字符串残留；
- disabled 时不创建 listener/Store/Runtime chunk。

### POC-4：包入口与设置可行性

编码前确定单入口方案并用最小 pnpm fixture 验证；npm、monorepo 和完整设置写入矩阵由 EA-1B/EA-6 完成：

- 用户只安装 `@spotpatch/vite` 或 `@spotpatch/next` 时，项目级 MCP command 能解析锁定的 Connector bin；
- 不依赖全局 PATH、全局 Node 包或 `npx latest`；
- Claude/Cursor/Codex 配置 dry-run、幂等写入、冲突与回滚；
- monorepo 子目录和工作区根启动行为。

EA-1A 完成后必须在本页记录版本、OS、命令、fixture、结论和未决项。本次 POC 后采用独立 `@spotpatch/bridge` 包，由框架入口依赖并转发 CLI；临时实验形成正式实现后必须删除，避免遗留死代码。

### EA-1A 主动入口补充证据（2026-08-24）

| 对象 | 锁定版本/入口 | 已核验事实 | 当前结论 |
| --- | --- | --- | --- |
| Claude Code Channels | Claude Code 2.1.235；官方 Channels/reference/CLI 文档；工作区假宿主合同测试 | `experimental["claude/channel"]`、`notifications/claude/channel`、无 notification/completion ACK、运行中会话、裸 server 开发参数、legacy host env、exact-cursor 取件与结果 tool 映射 | adapter 为 `local-validation`；真实双次点击 E2E `not-tested`，只能 experimental |
| Codex App Server | Codex CLI 0.149.0；`codex app-server`；该版本生成的 TS/JSON Schema；真实握手、无 turn preflight、首轮失败记录与修复后人工双 revision；工作区假 App Server | 真实 `initialize/initialized`、带 `emittedAtMs` 通知、inline `mcp_servers.spotpatch`、`thread/start`、Session-list-only status、exact-session tool-call、`turn/start`、匹配 `turn/started`/terminal、终态后再次派发、workspace root 归一化与配置分层；假宿主覆盖完整 turn 终态、known reverse-request Schema、POSIX 进程组清理 | 指定 macOS/Next.js/Codex 0.149.0 环境人工连续两 revision 通过；Windows 进程树清理与可重复真实宿主自动化 `not-tested`，整体仍为 `local-validation` |
| Cursor 主动入口 | Cursor 官方 MCP/CLI 文档 | 未找到与 Channel/turn-start 等价且已验证的稳定入站事件接口 | 主动模式 unsupported；保留 Inbox-compatible |

真实 Codex 握手 POC 没有启动模型 turn：在无项目 `.codex/config.toml` 的临时 root 中，thread 级 inline SpotPatch MCP 达到 `ready` 并列出 `spotpatch_get_current_handoff`；在已信任项目中把项目层同名 entry 指向无害失败进程后，inline 同名 entry 仍达到 `ready`，证明当前 0.149.0 的 thread 层覆盖生效。另一个无关项目 MCP 仍按 Codex 配置分层启动并失败，证明 Connector 不能声称隔离用户的其他 MCP。测试后临时进程与文件均已清理，目标项目配置恢复原文和 `0600` 权限。

2026-08-24 的第一次真实主动 turn 尝试进一步完成了 initialize/initialized、thread/start、MCP ready、turn/start response 和匹配的 `turn/started`，因此 UI 当时的 `working` 有结构化协议证据。模型请求前段多次发生 Responses WebSocket timeout，随后回退 HTTP 并继续。Agent 调用了 `spotpatch_get_current_handoff`，工具返回约 225 KiB 的有效结构化结果；之后代码模式把完整结果整体序列化，输出被裁剪/无法有效消费，Agent 未稳定提取用户 instruction，转而检查 SpotPatch 自身。目标文件保持未修改，记录截止时没有匹配的 `turn/completed`；该首轮未通过，第二个 revision 未开始。

更早的主动 readiness 尝试曾因 App Server 启动的 stdio MCP 没有显式转发 macOS 运行目录变量而与 Broker discovery 根目录分叉并返回 `SESSION_NOT_FOUND`；固定四变量 `env_vars` 用于关闭这一跨进程不确定性。后续已经到达 working 的首个模型 turn 是另一条故障：其 MCP 子进程已继承正确 `TMPDIR`，显式继承环境的手工调用也成功，所以该次未编辑不能再归因为运行目录；已确认的直接问题是整体序列化大型 tool result 及其输出裁剪。

修复后又在真实 0.149.0 完成不启动模型 turn 的独立预检：inline 四变量、`enabled_tools`、`required`、exact `--session`、`mcpServerStatus/list` 与 `mcpServer/tool/call` 均生效，SpotPatch 实际只暴露 Session-list 并只返回选定 Session。状态查询也会枚举用户其他已启用 MCP，本机响应约 73 KiB、耗时约 8.6–9 秒，因此默认 JSON-RPC 请求超时提高为有界 30 秒，终端继续披露其他 MCP 可能启动。

在有界任务投影、exact-session 预检和连接环境修正后，操作方于 2026-08-24 在同一 macOS/Next.js/Codex 0.149.0 环境完成连续两 revision 的人工复测，并确认两次目标修改完成、Connector 在首个 terminal 后回到可接收状态且第二次派发成功。该证据将真实 Codex happy path 从 `not-reached` 更新为“指定环境人工通过”，但没有形成可重复自动化日志夹具，不能外推为其他 Codex 版本、Claude、Cursor、Ubuntu、Windows 或稳定支持。

因此 EA-1A 只允许保留当前公共实现和继续本地验证，**不满足 EA-1B/EA-6**。Claude Code、Cursor、Codex 的支持声明以及 Ubuntu、Windows、npm 均继续阻断 beta/released；Cursor Agent CLI 不得写成已测试。

## Gate EA-1B：beta 前真实客户端与平台 POC

EA-1A 通过只允许进入公共实现，不构成客户端支持声明。beta 前必须在锁定正式版本的 Claude Code、Cursor、Codex 中实际完成 `tools/list`、get、wait、取消、256 KiB 边界、restart、cwd/root 与项目级审批测试；同时完成 macOS、Ubuntu、Windows 的发现权限、Broker 安全和 npm/pnpm 入口 fixture。缺少任一 required 证据时，对应客户端或平台只能标为 `not-tested`，且专题整体不得进入 `released`；涉及安全边界的缺口还会阻断 beta。

## Gate EA-2：公共模型与协议

完成条件：

- `@spotpatch/shared` 只有一份 Handoff DTO、Zod Schema、errors 和 limits；
- Browser endpoint 常量只定义一次；Broker 私有协议单独版本化；
- annotation 复用 schema v3，不复制目标/Prompt 模型；
- strict unknown-field、字节、数组、时间、cursor 和版本测试；
- package exports 不暴露 Node 私有 token/descriptor 类型给浏览器；
- Changeset 清楚标注 opt-in、development-only、本机实现边界，不宣称客户端已支持。
- HandoffSnapshot 保持单一；requestId、active lease、dispatch lifecycle 使用正交 strict Schema，不把厂商 ID 塞进正文；

## Gate EA-3：Node 核心

实现顺序：

1. 从现有 Agent Job 提取/复用纯 Node Annotation Authorizer；
2. 实现注入 clock/random 的 immutable Store 和发布 requestId 幂等；
3. 实现 Browser Handler；
4. 实现注入 filesystem/network 的 Discovery Publisher 和 Broker；
5. 实现单活 Active Adapter Registry、严格状态转换与 lease/dispatch 超时；
6. 组合幂等 Handoff Manager；
7. 装配 Vite，再装配 Next Sidecar；
8. disabled/production 负向路径。

完成条件：单元、集成、安全、资源泄漏和生命周期测试全部通过；框架层没有复制逻辑。

## Gate EA-4：MCP / CLI Connector

实现顺序：

1. 安全 discovery reader 与项目匹配；
2. 共用 Broker client、Schema、timeout/cancel/redaction；
3. CLI JSON；
4. MCP stdio 四工具；
5. 项目级设置 dry-run/write；
6. resources/prompts 仅在 POC 证明后作为可选。

完成条件：stdout purity、退出码、SIGINT/SIGTERM、重试幂等、协议 mismatch、陈旧 descriptor 和三客户端合同测试通过；get/wait 的 MCP text 前部包含同一个有界任务摘要，不复制 DOM selector/styles/source excerpt/page URL/token 或完整 structured result。

## Gate EA-5：Runtime 交互

- 在现有逐目标工作台增加可选外部交接路径；
- 首次 Session 披露、预览、发送、状态、过期、未发送变更和错误恢复；
- Inbox 的 waiting/picked-up 与主动的 ready/dispatching/dispatched/working/terminal 分层显示，只显示可验证事实；
- active busy 时按钮禁用且服务端仍拒绝；ready 后第二次点击无需用户再提醒 Agent；
- 中英文、键盘、焦点、screen reader、窄屏；
- 能力关闭无 DOM/CSS/listener/request 残留；
- 核心包体保持既有门禁，必要时使用独立私有 lazy chunk。

Runtime 不能依赖任何厂商产品名决定业务流程；客户端卡片只是设置说明。

## Gate EA-5A：通用主动派发核心

完成条件：

- `@spotpatch/bridge` 只有一个 Event Pump/Adapter 端口，Claude/Codex 不复制 discovery、wait、cursor 恢复、heartbeat 或清理；
- adapter 真正 ready 后才 claim；claim 与 current `baselineCursor` 原子完成，禁止 claim 后另读 current；同 kind + 同 `connectorInstanceId` 重试返回原 lease/baseline 并刷新租期，不同 kind/instance 冲突失败；instance ID 不是认证，生命周期上报必须使用 lease token；不重放旧任务；timeout 后继续等待；同一精确 Session 内的 cursor invalid/lease invalid 可重新 claim 并建立新 baseline，但开发 Session 结束或重启后旧 ID 不可复用，旧 Connector 必须停止并提示用户重跑；
- 同一 dev Session 第二个 active lease fail-fast；多个同 root Session 主动发现必须显式选择；dispatch 未终止时第二次 Browser publish 返回 `EXTERNAL_AGENT_BUSY`；
- 复用现有 `BridgeClient` 的 get/wait 自动 ack；pickup receipt 与厂商 dispatch 证据分开，receipt 未记录时 Active Pump 不开始厂商 transport write；
- 连续两个任务均经历 ready → dispatch → terminal → ready；无模型 `wait_for_handoff`；
- adapter 已可能接收但响应丢失时进入 `delivery-unknown`，Pump 停止并释放该 writer且不重试；Browser 只能在明确确认工作区已核对后清除 hazard，旧任务不重发；
- AbortSignal、SIGINT/SIGTERM、stdio close、lease expiry 和 dev-server dispose 后无 wait、timer、listener 或子进程泄漏。

## Gate EA-5B：Claude Channel adapter

- Channel MCP initialize capability 与通知形态符合锁定官方文档；meta 仅含字符串 session/revision/cursor，正文只含固定引用说明；
- Generic `mcp` mode 不声明 Channel、不取得 active lease；Claude active setup 只在显式 mode 下迁移精确匹配的旧 entry；
- notification resolve 最高只记 `dispatched`；exact cursor get 才记 `working`；结果工具才能记 `completed/failed`；
- 非 Channel host、未启用 Channel、会话关闭、busy、策略阻断和未上报结果均不误报 completed；
- 锁定 Claude Code 真实完成“发送 → 执行/上报 → idle → 第二次发送 → 再执行/上报”；保留命令、版本和脱敏证据。

## Gate EA-5C：Codex App Server adapter

- fake App Server 覆盖 initialize/initialized/thread/start、带合法/非法 `emittedAtMs` 的通知 envelope、`mcpServerStatus/list`、`mcpServer/tool/call`、turn/start 的 request correlation、乱序/重复通知、malformed/oversized JSONL、stderr 上限和进程退出；SpotPatch MCP 未 ready、缺少唯一允许的 Session-list tool，或 `spotpatch_list_sessions` 不是只返回精确选定 Session 时都不得 claim；
- 主动命令必须从精确项目根启动，多 Session 用 opaque `--session`；不要求持久 setup，必须断言 `thread/start.config` 使用框架锁定的 inline SpotPatch MCP 入口，Browser/参数不能注入 command/args/environment；持久 Codex Inbox 与主动 inline 配置必须使用完全相同的 `XDG_RUNTIME_DIR` / `TMPDIR` / `TMP` / `TEMP` 名称白名单，且断言不含 `HOME`、`PATH`、token 或 Browser 提供名称；
- PATH 解析后的 absolute executable、realpath/可执行权限/精确版本/项目内二进制拒绝有测试；固定 argv `app-server`、`shell: false`、canonical cwd、workspace-write、network false、approval never，浏览器无法覆盖；
- 已知反向 request 按各自 Schema decline/cancel，未知 method 返回协议错误；thread/start 可能写 project trust 的前后配置副作用有真实 POC 与终端披露；
- 不使用 `turn/steer`、不接管现有 UI thread、不持久化/泄漏 threadId/turnId、不重放重启前任务；
- `turn/start` 成功响应最多记 dispatched，只有匹配 thread/turn 的 started/terminal 改变后续生命周期，失败/中断不会记 completed；completed 文案不得暗示代码或检查成功；
- Codex turn 任务摘要只包含规范化的项目相对源码位置、仅标签名的元素标识和逐目标 instruction，必须排除 DOM selector/styles/source excerpt/page URL/token；绝对路径、反斜杠路径、`.`/`..` 段、空路径段、控制字符、缺少可执行源码位置或多目标的“位置 + 安全标签”投影碰撞都必须在 `turn/start` 前 failed；回归必须证明主动 inline 配置的 `enabled_tools` 只有 Session-list，且状态预检遇到额外 tool 必须 fail closed，使 Agent 不可见 full-context get/wait/ack；记录的 macOS/Next.js/Codex 0.149.0 人工双 revision 通过只解除该指定 happy path，跨平台与可重复真实宿主自动化仍需单独验收；
- exact-session Connector 遇到 Session 结束/重启必须停止并提示重跑；不得对不可能恢复的旧 Session ID 无限退避，也不得静默附着新 Session；
- Connector lifecycle observer 抛错不得改变 Broker phase、adapter 交付结果或继续等待下一个 revision；
- SIGINT/SIGTERM 在 Session discovery、App Server initialize/preflight 与 Event Pump 三个阶段都必须及时取消；初始化中断不得继续到 `thread/start`，已启动的子进程必须进入同一清理链；
- POSIX 上以独立进程组启动 App Server，覆盖 `SIGTERM` 拒绝子孙的整组 `SIGKILL` 清理；Windows 进程树清理未有真实证据时保持 `not-tested`；
- 锁定 Codex 真实完成“发送 → turn → idle → 第二次发送 → 第二个 turn”，保留版本/Schema/脱敏证据。

### ADR-037 managed Codex 增量 Gate

1. **P0 契约**：四状态轴、control endpoints、capability、错误、grant/check/result Schema 与 ADR-037 一致；旧 phase 只有单向兼容映射；

## 回滚与失败策略

- Beta 期间默认配置关闭；出现安全/协议问题可通过配置禁用，不影响选择和 Prompt。
- Broker 初始化失败 fail-open 到核心产品，但 handoff 按钮显示 unavailable，不降级为落盘源码邮箱或公开端口。
- required 客户端升级破坏兼容时，将该版本移出支持矩阵并给出锁定建议；不按错误猜协议。
- Schema 主版本不兼容时 Connector fail-fast；不同时维护多套未测试 decoder。
- 设置写入失败使用原子文件保证原配置不变；JSON 更新保留不可覆盖的私有 `.spotpatch.bak`。Codex TOML 不做通用合并：仅当文件全文精确等于上一版生成的、无 `env_vars` 的单 SpotPatch entry 时，先创建不可覆盖的私有备份再原子迁移；其他现有 TOML 只给手工片段。
- 厂商 adapter 可整包/整开关删除；公共 Handoff Snapshot 和 MCP tools 保持可用。
- active delivery unknown 时不尝试自动恢复为另一 adapter；停止 writer、保留 Inbox Handoff，并要求用户先核对工作区。

## 实施中的代码纪律

- 每个 commit 只跨一个 Gate 的单一关注点；协议和实现不得混进一笔不可审 diff。
- 先测试失败，再实现；安全负向测试与成功路径同一阶段提交。
- 不创建未消费 public type、空 adapter、未来 provider 枚举或通用工具包。
- Node/browser 入口严格分离；MCP SDK 只能存在于 Connector Node graph。
- 所有外部输入从 `unknown` 解析；禁止 `any`、非必要断言、字符串错误分支。
- 文件、socket、waiter、listener、signal handler 均返回/进入一个幂等 dispose 链。
- 新 endpoint、错误码、limits、消息键和设计令牌都有唯一来源和真实消费测试。
