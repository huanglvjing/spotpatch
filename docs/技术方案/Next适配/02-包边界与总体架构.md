# Next.js 适配包边界与总体架构

## 现状问题

当前 `@spotpatch/vite` 同时承载四类职责：Vite 生命周期、通用 JSX source transform、通用本地 HTTP/编辑器服务、Runtime bundle 注入。直接让 `@spotpatch/next` 依赖它会产生以下错误架构：

- Next 用户被迫安装 Vite peer dependency。
- Next 与 Vite 适配器形成反向耦合，任何 Vite 生命周期调整可能破坏 Next。
- 公共服务和转换逻辑只能复制或跨包访问内部文件，违反单一事实来源与发布边界。
- 生产裁剪、测试和安全责任无法按框架分别验证。

因此 Next 适配不是在新包里复制 Vite 目录，而是先建立框架无关 Host Core，再由两个平级 Adapter 消费。

## 目标包图

```text
@spotpatch/shared
  ↑        ↑              ↑
compiler  agent       react-adapter
  ↑        ↑              ↑
  └──── dev-server ───────┘
           ↑       ↑
      vite adapter  next adapter
           \       /
            runtime
```

图只表达允许依赖方向，实际公共包列表和发布闭包仍由总体架构维护 (见 doc-id:02-architecture-stack)。规划新增：

| 包 | 发布属性 | 单一职责 |
| --- | --- | --- |
| `@spotpatch/compiler` | 公共内部依赖 | 框架无关 JSX/TSX 过滤、source marker 注入、source map 和转换诊断 |
| `@spotpatch/dev-server` | 公共内部依赖、Node-only | 选项最终解析、Source Registry、Session、本地 API、编辑器和 Agent 装配 |
| `@spotpatch/next` | 用户入口 | Next 配置组合、CLI、Loader 桥、rewrite、client/noop entry 与版本门禁 |

“公共内部依赖”表示包必须发布到 npm 以闭合依赖图，但用户文档不要求直接安装。`@spotpatch/vite` 与 `@spotpatch/next` 是平级用户入口；两者不得相互依赖。

## Host Core 接口

框架适配器只能通过稳定窄接口接入公共内核，不得导入另一个适配器的私有路径：

```ts
interface SpotPatchHostDescriptor {
  readonly framework: "vite" | "next";
  readonly frameworkVersion: string;
  readonly root: string;
  readonly mode: string;
  readonly command: "serve" | "build";
}

interface SourceRegistrationClient {
  register(absolutePath: string, signal?: AbortSignal): Promise<string>;
}

interface SpotPatchDevService {
  readonly publicHandler: NodeRequestHandler;
  readonly internalRegistrationHandler: NodeRequestHandler;
  close(): Promise<void>;
}
```

这些类型是规划接口草案，不是当前公共导出；最终字段在实现前通过类型测试冻结。公共产品选项、数据模型和默认值继续只有一个来源 (见 doc-id:03-public-api-models)，Host Core 只负责解析和执行，不建立 Next 专用副本。

## 模块责任

### `@spotpatch/compiler`

- 不依赖 Vite、Next、webpack 或 Turbopack。
- 输入为源码、绝对路径、root、已授权 fileId 与不可变过滤配置。
- 输出为源码和 source map；无变更时返回明确空结果。
- 不读取 provider 凭据、不启动服务、不写业务文件。
- Adapter 只负责把框架钩子翻译为编译器输入 (见 doc-id:next-04-transform-source)。

### `@spotpatch/dev-server`

- Node-only；任何导出不得进入浏览器 bundle。
- 拥有 Session、Source Registry、本地协议 handler、源码读取、编辑器和可选 Agent Manager。
- 凭据、Git、检查和 provider 责任继续委托现有 Agent/Provider 模块 (见 doc-id:16-ai-agent-execution)、(见 doc-id:17-model-provider-credentials)。
- 对 Vite 提供 Connect-compatible 适配；对 Next Sidecar 提供原生 Node HTTP 适配。业务规则相同，承载形态不同。

### `@spotpatch/next`

- 只识别 Next phase、版本、bundler、root 和宿主配置。
- 只在开发 phase 配置 source loader、API rewrite 和真实 client entry；非开发 phase 只提供可被树摇掉的 noop 解析。
- CLI 负责启动/停止 Sidecar 与本地 Next binary，不在 `next.config` 求值期间产生长期进程副作用。
- 不重新实现 HTTP handler、Agent、编辑器、marker 算法或公共默认值。

## 运行拓扑

```mermaid
flowchart LR
  CLI[spotpatch-next dev] --> SIDE[Loopback Sidecar]
  CLI --> NEXT[next dev child]
  NEXT --> CFG[withSpotPatch]
  CFG --> LOAD[Webpack/Turbopack Loader]
  LOAD --> COMP[@spotpatch/compiler]
  LOAD -->|internal auth| SIDE
  CFG --> RW[beforeFiles rewrite]
  INST[instrumentation-client] --> CLIENT[@spotpatch/next/client]
  CLIENT --> RT[@spotpatch/runtime]
  RT -->|same-origin API| RW
  RW --> SIDE
  SIDE --> CORE[@spotpatch/dev-server]
```

Sidecar 公共/内部通道的鉴权和生命周期 (见 doc-id:next-05-sidecar-protocol)，客户端和 RSC 边界 (见 doc-id:next-06-rsc-runtime)。

## 禁止依赖与禁止复用方式

- `@spotpatch/next → @spotpatch/vite`：禁止。
- `@spotpatch/vite → @spotpatch/next`：禁止。
- Adapter 导入其他包 `src/**` 或未声明 export：禁止。
- 把 Vite `Plugin`、Next `NextConfig`、webpack LoaderContext 类型放入 shared/runtime：禁止。
- compiler/dev-server 读取 `process.cwd()` 作为隐式 root：禁止；root 必须由 Host Descriptor 传入。
- 在两个 Adapter 中保留两份 options schema、保护路径、错误码或编辑器命令：禁止。
- 为减少改动暂时复制实现再“以后抽取”：禁止；迁移按可回滚小步完成，但每一步只能有一个活动实现。

## 迁移纪律

1. 先以现有 Vite 测试锁定行为，不同时改公共语义。
2. 抽取 compiler 后，Vite Adapter 改为消费它并通过全部既有测试。
3. 抽取 dev-server 后，再次让 Vite 全量通过，确认生产 bundle 没有新增 Node 代码。
4. 只有公共内核稳定后才实现 Next 桥；Next 失败不得通过在 Adapter 内复制旧实现绕过。
5. 每个迁移阶段独立 Commit 和 Changeset；不把结构迁移、Next 新功能和 UI 改版混成一个不可审查提交。

编码、文件规模和副作用规则继续执行统一规范 (见 doc-id:11-coding-standards)。
