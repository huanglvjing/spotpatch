# Next.js 测试验收与实施计划

## 交付纪律

本计划补充统一测试与实施规范，不替代现有质量门禁 (见 doc-id:12-testing-acceptance)、(见 doc-id:14-implementation-plan)。Next 适配按风险从 POC 到发布推进；任何阻断项失败都回到架构，不进入“先复制能跑代码再补测试”的路径。

## Gate N0：文档与事实基线

完成条件：

- 本目录职责互斥、引用闭合，支持范围明确标为 planned。
- 总索引、产品边界、总体架构、风险/ADR、统一测试/计划已同步。
- 官方来源带访问日期和直接链接；Next/npm 动态版本不写成实现常量。
- 当前 `@spotpatch/vite` 行为与支持声明不变。
- 0 个重复 doc-id、未知引用、孤立 Next 文档或相互矛盾的支持声明。
- 现有源码职责、公共类型所有权、应用/Git/源码 root、进程/IPC、缓存 epoch、LAN 边界和 React 19 现状均有明确归属。

N0 的完成证据必须同时包含：文档 front-matter/引用/链接审计、格式/Lint/strict typecheck/unit tests 全绿、干净 Git diff 审阅以及规范 Commit。完成 N0 只授权进入 N1 实验，不表示 `@spotpatch/next` 可以实现、发布或对外宣称支持。

状态：`completed`（2026-08-09）。本次审计快照为 27 份 active 文档、9 份 planned Next 专题、246 条正文跨文档引用，未知/孤立/依赖不一致均为 0；Prettier、ESLint、strict typecheck、50 个文件/368 个单测、构建、Vite 5/6兼容 fixture、性能测试、16 个 Chromium E2E、5 个生产泄漏断言及 5 个发布包的 publint/类型发布检查全部通过。该结果只证明文档基线与现有 Vite 产品无回归，不是 Next POC 通过记录。

## Gate N1：阻断式 POC

POC 代码必须位于计划目录 `experiments/next-adapter/`，不进入 `packages/**`、公共 export 或 npm 发布闭包。每个 POC 包含锁定依赖的 fixture、可重复命令、机器可读结果和结论文档；实验结束可整体删除，不允许被生产包私下导入。

| POC | 必须证明 | 失败结果 |
| --- | --- | --- |
| Turbopack Loader | Next 15/16 下 TSX/JSX 输出链、`as`/rule 顺序、map、HMR、多 worker、开发 only | 重新评估编译入口；不得自行转译 Next 源码或先发布 webpack-only |
| webpack pre-loader | client/Node/Edge 三次配置、map、Fast Refresh、幂等 | 修正组合层或缩小有证据的支持矩阵 |
| source registration | 并发、epoch 内稳定 fileId、CLI重启 cache 隔离、注册成功后才注入、超时 fail-open、路径拒绝、性能 | 重新设计注册协议；不得写路径或幽灵 fileId 进 DOM |
| rewrite proxy | POST/header/body/状态、NDJSON 流、取消、basePath/trailingSlash | 回到协议承载评审；不得静默改成无认证跨域 |
| CLI/config transport | 对象/同步/异步 config、Next `.env*`、重复求值、ack/超时、direct `next dev`、secret零落盘 | 回到 lifecycle 设计；不得由 CLI 重复求值配置或在 config 中启动服务 |
| loopback boundary | Next 默认 hostname、显式 `-H`、IPv4/IPv6、rewrite 穿透、Host/Origin/Fetch Metadata | 首版拒绝 LAN；无法证明隔离则停止 Sidecar 方案 |
| pre-hydration | 最小 hook 早于 React 18/19 hydration、同步路径小于 16 ms、App/Pages、既有 instrumentation 组合 | 调整 client entry；不得延后到普通组件 `useEffect` |
| RSC marker | SSR、RSC 导航、Suspense、hydration、HMR | 不声称 App Router exact 支持 |
| production strip | webpack/Turbopack noop alias、HTML/RSC/client/server/standalone/static 输出零残留、Key零读取 | 阻断架构，不能靠文档免责声明进入正式支持 |

N1 必须在 macOS 和 Ubuntu 至少各运行一次；Windows 的进程/路径验证可在后续矩阵，但注册协议不能只依赖 POSIX 语义。每个 POC 结论只能是 `pass`、`fail` 或带明确前置条件的 `blocked`；没有日志、锁定版本和可复现步骤的人工截图不能作为 `pass`。

N1 的最小 fixture 组合：Next 15.3.x + React 18 + webpack/Turbopack，以及 Next 16.x + React 19 + Turbopack/webpack。Next 15 默认 webpack并显式验证 `--turbopack`；Next 16 默认 Turbopack并显式验证 `--webpack`，防止只测同一构建器路径。

状态：`in-progress`（2026-08-09）。`experiments/next-adapter/` 已建立不发布的 Loader 编译链实验、锁定 fixture、由 Ajv 执行验证的统一 JSON Schema、脱敏日志和可重复命令 `pnpm test:next-poc`。扩展后的 macOS 本地与 Ubuntu/Node 22 required CI 各有 6 个用例通过：四个开发组合均覆盖 500 个生成 TSX 模块、8 路并发冷请求、Fast Refresh、map、Edge 和暖 cache 重启，生产组合验证零注入；Next 16 私有 App Router 真实宿主另以 `pnpm test:next-real-host` 通过 Turbopack、webpack、Client Component hydration 与生产隔离。实测同时证明 Next 16 webpack 必须将非敏感 epoch 纳入 filesystem cache `version`，不能只依赖 Loader options。Loader 编译链 POC 的范围内状态为 `pass`，唯一结论及 CI 证据见 `experiments/next-adapter/CONCLUSION.md`。仓库随后实现了 N2/N3 公共预览，以便验证真实链路；这不把尚未独立完成的 rewrite、pre-hydration、RSC 和 production-strip POC 自动标为通过，也不豁免正式支持门禁。

## N1 证据契约

每项实验输出以下统一字段，避免只凭“页面看起来能用”做判断：

- 锁定的 Next/React/Node/OS/bundler 版本与启动命令。
- 测试输入、预期、实际结果、退出码和脱敏日志路径。
- 转换前后源码 hash、map 断言、marker/fileId/epoch 断言；不得保存 secret 或 Prompt。
- HMR/重启/取消/崩溃步骤与资源清理结果。
- 生产 fixture 的字符串/模块/环境读取扫描结果。
- 结论、未覆盖边界、对应 ADR 是否仍成立以及复核人日期。

某个 POC 失败时只允许修改该 POC 与架构文档；在新方案重新通过前不得提前创建公共包骨架，避免失败设计沉淀为死代码。

## Gate N2：公共内核抽取

按 (见 doc-id:next-02-package-architecture) 执行：

1. 新增 compiler 包并迁移 transform；Vite 单测/E2E/性能/生产全部保持。
2. 新增 dev-server 包并迁移 options、registry、session、middleware/editor/Agent 装配；Vite全部保持。
3. 建立禁止跨 Adapter 私有导入的结构测试。
4. 更新发布闭包、README、Changeset、publint 和 Are the Types Wrong。
5. 使用覆盖率/引用扫描证明旧 Vite 目录不存在平行死实现。

每次抽取独立提交；N2 未通过不得实现 Next 公共入口。

状态：`completed-preview`（2026-08-09）。`@spotpatch/compiler` 与 `@spotpatch/dev-server` 已成为唯一活动公共实现，Vite 改为消费它们；结构测试、Vite 5/6 兼容开发服务器、性能/生产泄漏、构建、Changeset、`publint` 与 Are The Types Wrong 均通过。首个公共预览发布 compiler/dev-server/next `0.1.0`，但 Registry 可安装性不能替代 Next 正式支持门禁。

## Gate N3：Next Adapter

- 在任何公共 endpoint 落地前，先把通过 POC 的 bootstrap/内部承载规则更新到公共协议唯一事实源和 shared schema；实验路径不能直接成为发布协议。
- 实现并单测 `withSpotPatch` 对对象/同步函数/异步函数配置的组合。
- 实现并单测认证配置消息 schema、串行配置状态机、sealed listener、loopback hostname 门禁和 registry epoch；不得假设 Next 配置一定在直接子进程中求值。
- 实现 CLI 的本地 binary解析、参数透传、信号/退出码、Sidecar所有权和幂等 init/check。
- 实现 Turbopack/webpack Loader桥、内部注册、rewrite 和 client/noop entries。
- 所有新模块有明确 package export；无未使用文件、占位函数、复制常量、`any`、空 catch 或任意 shell。
- 错误使用稳定 code 和双语 UI，不将 Next 内部异常直接返回浏览器。

状态：`public-preview/in-progress`（2026-08-09）。当前 `@spotpatch/next@0.1.0` 公共预览已实现 CLI `dev/init/check`、独立配置与 registration secret、Sidecar、自检、Turbopack/webpack Loader、source registration、bootstrap、client/noop entry 和生产 alias。当前证据为：

- 全仓 Prettier、Typed ESLint、strict TypeScript 通过；新增 Loader CJS marker smoke test进入包 build。
- 最终一次全量运行通过 61 个测试文件/408 个单测，包含 Loader、初始化器和 `withSpotPatch` 配置组合新用例。
- 8 个包构建、`publint` 和 Are The Types Wrong 全部通过；Vite 5/6 开发兼容、生产泄漏与性能门禁通过。
- 私有 Next 16.3/React 19.2 App Router 宿主通过 Turbopack/webpack 开发启动；真实 SSR marker 可换取 bootstrap，并通过 fileId读取 `app/layout.tsx` source context；webpack HMR 修改/恢复生效。
- 独立 `pnpm test:next-runtime-real-host` 在同一 clean 宿主的临时副本中通过 2/2：两个 bundler 均验证单 Runtime、认证 bootstrap、并发 source registration、rewrite 传输和精确 source context；已接入正式适配器的宿主在该历史 POC 中只走 production/noop 分支，避免双 Sidecar 与双 Loader。
- webpack 生产构建完成 18/18 静态页面；完整产物扫描未发现 marker、UI、client state、公共 API 或内部 secret，`next start` 页面为 200、私有 API 为 404。
- 默认 Turbopack 历史 Loader POC 生产构建通过，`.next` 未发现 active POC marker 或 POC 环境键；该扫描范围小于正式适配器的完整生产零残留 fixture。

仍未完成：复杂 `basePath`/`trailingSlash`/matcher rewrites fixture、全浏览器点击/选择/编辑器/Agent链路、完整 RSC导航与 Pages/hybrid、正式适配器的完整 Turbopack 生产零残留 fixture，以及 N4 required matrix。当前私有宿主中的局部 Turbopack 生产通过不能替代这些正式支持证据。

## Gate N4：兼容与 E2E 矩阵

正式支持 required matrix：

| 维度 | Required fixture |
| --- | --- |
| Next | 锁定最低 15.3.x、当前维护 15.5.x、当前 16.x |
| Bundler | 每个正式 Next 主线至少 Turbopack与 webpack |
| Router | App、Pages；另有 hybrid 冲突 fixture |
| React | 18.2/18.3 与 19.x，按 Next 合法 peer 组合 |
| Node | 20.19+ 基线、22、24；以 package engines 与 runner可用性为准 |
| OS | Ubuntu、macOS、Windows 构建/单测；Chromium E2E 至少 Ubuntu required |
| 项目结构 | root/src、basePath、trailingSlash、custom rewrites、custom webpack、MDX/Babel/React Compiler |

CI 不在运行时安装 `next@latest`；fixture 版本进入 lockfile。依赖机器人更新后必须跑完整矩阵。canary/preview 可每日非阻断观察，失败只创建维护信号，不污染正式支持结论。

状态：`pending`。当前单一 Next 16 App Router 宿主和历史 Loader POC 不能替代本表。

关键 E2E：

- 启动、选择、高亮、精确文件/行列、打开 Cursor/VS Code请求。
- Server Component、Client Component、`next/image`、Portal、Suspense、streaming、RSC navigation、Fast Refresh。
- 多目标独立说明、Prompt、AI capability、脏工作区同意、review Apply/Revert。
- Provider跨轮复用 tool ID、无效参数重试和取消。
- Next fatal overlay、hydration error、Sidecar退出、旧 token、rewrite冲突和初始化器失败回滚。
- 生产 build/start/static/standalone 零残留。

## 性能与资源预算

现有 Runtime/Agent预算继续生效 (见 doc-id:12-testing-acceptance)。Next 新增预算在 POC 基线后固化，正式支持前至少包含：

- compiler 纯 transform 中位数/P95不劣于现有共同预算。
- internal registration冷/热缓存分别记录；不得用热缓存隐藏首次启动成本。
- 在固定 500 个可转换模块 fixture 上记录 Next 无插件、启用 webpack、启用 Turbopack的 ready 时间差和 HMR 时间差。
- Sidecar空闲无持续 CPU，内存、Registry、Job 和 worker cache 有界，连续 HMR无增长。
- 核心 Runtime gzip继续满足现有门禁；Next client hook/bootstrap增量单独设置预算，不能并入 React Adapter后掩盖。

在取得跨平台重复样本前不在提案中虚构毫秒阈值；N1 输出基线，ADR 再冻结数值。

## 正式支持条件

全部满足才允许把产品矩阵改为正式支持并移除 `@spotpatch/next` 的公共预览警告：

- N0–N4 全部完成，0 个阻断 unknown。
- 统一格式、Lint、strict typecheck、unit、integration、E2E、production leakage、package validate 全绿。
- GitHub required checks覆盖计划矩阵，不能只靠本机验证。
- npm 包依赖图闭合；空白 Next fixture 从 Registry 安装后可运行。
- README只描述已通过能力，限制和降级可见；Vite 文档不被 Next 接入步骤污染。
- 安全审计确认无 Key/session/internal secret/path 泄漏，无残留 Sidecar/worktree。
- 正式 Changeset、Changelog、版本策略和回滚说明完成。
