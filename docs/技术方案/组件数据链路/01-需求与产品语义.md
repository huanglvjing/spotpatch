# 组件数据链路需求与产品语义

本页在专题交付边界 (见 doc-id:data-flow-00-index) 和现有产品边界 (见 doc-id:01-product-boundary) 内定义需求；实仓分母 (见 doc-id:data-flow-02-repository-audit)，页面交互 (见 doc-id:data-flow-08-ui-interaction)，准确率/性能门禁分别见 (见 doc-id:data-flow-11-testing-acceptance)、(见 doc-id:data-flow-10-security-performance)。

## 用户目标

用户不应再打开浏览器 Network 面板、手工搜索接口 URL、猜测哪个组件使用了哪一条响应。SpotPatch 在开发页面内应支持两条入口：

1. **选中一个组件**：查看与该组件有确定证据关系的请求、参数、响应使用字段和数据位置。
2. **进入一个页面**：查看当前页面实际请求过、源码声明过以及尚未归属的业务接口，并能反查相关组件。

页面接口总览用于发现，组件数据链路用于归因。两者共享同一 observation 和 evidence，不允许维护两套 recorder 或产生矛盾结果。

## 必须拆开的六类问题

| 用户问题 | 产品事实 | 首版答案来源 |
| --- | --- | --- |
| 这是哪个组件 | 组件名、源码位置、组件栈 | marker + Registry + React Adapter |
| 组件接收什么 | props、路由参数、Context 的名称、类型/shape、来源表达式 | AST/TypeScript；运行时只做安全增强 |
| 组件会调用什么接口 | method、URL template、operation、调用路径 | 静态调用图 |
| 当前真的请求了什么 | 当次 method、清洗后 URL、状态、耗时、传输类型 | fetch/XHR observation |
| 哪个请求提供了显示数据 | response path 到 state/store/cache/props/JSX 的链 | def-use + 数据层适配器 + 引用 provenance |
| 数据存在哪里 | local state、Context、client cache/store、Web Storage、可证明的服务端 model/table | 分层证据；外部后端为 unknown |

产品文案必须明确：组件参数不等于接口参数；请求发起者不等于数据消费者；客户端 Store 不等于数据库；源码声明不等于当前已执行。

## 核心用例

### UC-1 选中登录按钮

用户选中 AntD 提交按钮后，先看到“选择动作不会提交表单”。静态报告展示 `Button htmlType=submit → Form.onFinish → Zustand action → Axios callsite`。用户选择“观测下一次操作”并真正提交后，界面合并当次请求结果，但把验证码和成功后的 follow-up 请求单独标注。

### UC-2 选中表格

用户选中 Table 后，界面优先展示“数据由谁提供”：直接请求、经 Store/cache，或父组件请求后经 props 传入。Table 自己没有请求时必须显示“上游提供”，不得显示“该表格调用了接口”。

### UC-3 进入页面

用户打开“页面接口”后，不需要先选组件。界面按当前 route epoch 列出已观测业务请求、源码声明但未执行的请求和未归属请求；静态资源不混入默认列表。

### UC-4 查看参数和返回数据

参数按 path/query/body/header/GraphQL variable 分组，展示 key、类型/shape、来源表达式和敏感状态。响应默认展示有界 shape 与源码实际消费字段，不展示完整业务 payload。

### UC-5 AI 辅助查找

确定性引擎无法完成链路时，用户可预览并显式发送已清洗的证据上下文给现有 Agent/Provider。AI 可以解释候选路径、建议下一步证据或帮助阅读授权源码，但结果始终标为 AI inference，不能覆盖系统事实状态。

## 功能需求

| ID | 要求 | 验收入口 |
| --- | --- | --- |
| FR-01 | 为选中元素解析稳定 source component；不确定时显示降级来源 | 选择 fixture |
| FR-02 | 识别声明的 HTTP 请求 callsite、method、URL template 和参数来源 | 静态 manifest |
| FR-03 | 捕获页面加载起已执行的 fetch/XHR，不依赖 DevTools | 浏览器 fixture |
| FR-04 | 用证据区分 direct、transitive、upstream、unassigned、unknown | 归属 oracle |
| FR-05 | 识别 click、submit、effect、route/load 和显式回调触发语义 | 事件 fixture |
| FR-06 | 展示 request-origin 与 data-fed-by 两条链 | 17-table oracle |
| FR-07 | 展示客户端 state/cache/store/storage；数据库仅可证明时展示 | 适配器 fixture |
| FR-08 | 提供页面接口总览、筛选、详情、源码导航和观测模式 | E2E |
| FR-09 | 默认只展示参数/响应 shape，敏感值全链路不可见 | 泄漏测试 |
| FR-10 | AI 必须显式触发、上下文可预览、输出带证据引用 | AI contract test |
| FR-11 | 分析失败不能影响选择、业务请求、Prompt 和现有 Agent | 非干扰测试 |
| FR-12 | disabled/production 下没有 recorder、endpoint、marker 增量或 UI 代码 | production scan |

## 非功能需求

- **准确性**：宁可 unknown，不可错误归属；百分比定义见 (见 doc-id:data-flow-11-testing-acceptance)。
- **可复核**：每个事实 badge 都能展开证据 ID、相对源码位置、静态路径或 observation。
- **最小侵入**：不得改变 Promise、Request/Response、abort、stream、事件和第三方 wrapper 的业务语义。
- **安全**：默认值最小化，浏览器不接收绝对路径或任意 root；AI 不接收原始 payload。
- **性能**：页面启动只加载小型 prelude；分析器和 UI 惰性加载；预算见 (见 doc-id:data-flow-10-security-performance)。
- **可维护**：共享模型、清洗、默认值和 recorder core 均只有一个实现；适配器插件化。
- **可访问**：键盘可操作，状态不只靠颜色，中文和英文文案类型化。

## 首发支持范围

| 维度 | 首发承诺 |
| --- | --- |
| 宿主 | Vite 5/6/7 development |
| UI | React 18.2–18.3；Chromium required，Firefox/WebKit observational |
| 源码 | 授权 root 内 `.js/.jsx/.ts/.tsx`，静态 import/re-export/alias |
| 网络 | window `fetch`、XMLHttpRequest、Axios 的 fetch/XHR adapter |
| 触发 | JSX onClick、原生 click、form submit/onSubmit/onFinish、effect、显式 timer/callback |
| 数据层 | React local state/props、Zustand、首个锁定版本的 TanStack Query |
| 页面 | CSR route/page epoch；业务请求与资源请求分栏 |
| AI | 可选解释/辅助查找；复用现有 Agent 与 Provider，不自动运行 |

适配器只有在固定版本 fixture 全部通过后才能进入 `supported`。Redux、SWR、Apollo、tRPC、GraphQL client、IndexedDB ORM、Prisma/Drizzle 应逐个门禁，不因模式相似而顺带声称支持。

## 明确不承诺

- 任意混淆、`eval`、运行时生成函数、未知动态 import 或任意元编程的静态全知。
- Worker/Service Worker 内部主动请求、原生模块或浏览器扩展内部请求。
- 浏览器之外的 SSR/RSC/server fetch 的运行时 observation。
- 外部后端、网关或微服务之后的数据库实例、表和实际写入结果。
- cache hit 时虚构一次网络请求；只能报告 cache 数据来源或静态 dependency。
- 在用户只做选择动作时自动执行提交、支付、删除或其他业务操作。
- 展示 token、密码、Cookie、完整 body、完整 response、数据库连接信息。
- 把 AI 推断、文件名相似或相同 URL 当作确定组件归属。

## “无结果”的产品语义

禁止使用“该组件没有接口”作为通用空态，因为它可能意味着：尚未执行、请求在父组件、请求在不支持的 Worker、图预算截断或当前源码未授权。空态必须带原因码：

- `no-declared-dependency-in-scope`
- `declared-not-observed`
- `observed-unassigned`
- `upstream-data-only`
- `analysis-truncated`
- `unsupported-pattern`
- `source-unavailable`
- `capability-disabled`

用户可据此选择观测下一次操作、扩大已授权 sourceRoots、查看页面接口、打开证据或使用 AI 辅助；系统不得自动扩大权限。

## 成功定义

功能成功不是“尽可能多地给出一个接口”，而是：

1. 对可证明链路准确回答并展示证据。
2. 对不可证明链路明确解释缺失的证据。
3. 用户无需打开 DevTools 即可完成页面请求发现和组件归因。
4. 所有新增能力对原页面行为、隐私和生产 bundle 无副作用。
