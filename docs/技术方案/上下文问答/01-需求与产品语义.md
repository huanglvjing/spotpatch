# 上下文问答：需求与产品语义

## 用户问题

SpotPatch 已经能把选中元素组织成 Prompt、内建 Agent 修改任务或外部 Agent Handoff，但当前交互把所有输入都解释为“修改说明”。因此用户问“这个是什么组件”时，系统仍要求逐目标说明、模型必须调用写工具、最终结果必须包含 Diff；没有修改就被视为失败。

目标不是在 SpotPatch 内嵌一个通用聊天机器人，而是增加一个由真实页面选择约束的工程问答动作：用户指出页面中的对象，SpotPatch 负责提供准确上下文，执行器只读分析，答案回到原工作台并能打开引用源码。

## 术语

- **Ask**：只读、单次的上下文问题。没有写工具和写权限。
- **Change**：现有修改流程。每个目标拥有自己的明确修改说明，并经过既有安全执行链。
- **Selection**：至少一个用户显式选中的页面元素及其页面、源码、React、DOM、CSS 和可选代码上下文。
- **Answer**：一个 Ask Job 唯一的结构化终态结果，不等于聊天消息流。
- **Source handle**：服务端为本次 Ask 签发的短期引用 ID；模型可引用，但不能据此扩大读取权限。
- **Change draft**：从答案生成的本地可编辑草稿；不是已创建的写 Job。

## 核心用户流程

### UC-A1：询问一个选中元素

1. 用户选择一个元素；
2. 工作台打开，用户切换到 Ask；
3. 输入“这个是什么组件？”并选择可用执行器；
4. 确认需要的远程数据传输；
5. SpotPatch 只读分析并在原工作台展示答案；
6. 用户点击引用，打开服务端重新授权后的源码位置。

### UC-A2：询问多个选中元素的关系

用户可以选择多个元素并提交**一个全局问题**，例如“这两个按钮为什么状态不同？”。系统把所有目标作为一个有序、原子的选择上下文；不会为每个目标重复提问，也不会生成多个答案。

### UC-A3：从答案进入修改

用户点击“根据回答创建修改”：

1. UI 切换到 Change 模式；
2. 保留原始选择；
3. 展示问题、答案摘要和引用作为只读来源；
4. 恢复用户先前未提交的逐目标修改说明，或显示空的逐目标说明；
5. 用户明确补全/确认每个要修改目标的 instruction；
6. 用户再次点击 Run/Send，才进入写权限、worktree、checks 和审阅流程。

转换动作不得自动调用模型、写文件、创建 Agent Job、复用 Ask 同意为写权限同意，或把答案文本当成可执行 instruction。

### UC-A4：能力不可用

- 没有 Key Provider，也没有通过 Gate 的 Managed Codex：Ask 提交禁用，说明配置动作；选择、Prompt 和 Change 仍可用。
- Key 已配置但模型不支持严格工具调用：显示 `ask-unavailable`，不得降级为从自由文本猜答案 Schema。
- Codex 已安装但 read-only/answer 事件合同不通过：Managed Codex 不出现在可选执行器中；不得借用 managed 写模式冒充 Ask。

## 不可变产品规则

### 至少一个目标

Ask 请求的 `selection.targets` 最少为 1。浏览器禁用按钮只是体验；Node 必须重新验证目标属于当前 Session、Source Registry 和授权 root。没有目标的请求返回稳定错误，不向 Provider/Codex 发起调用。

### 一个问题、一个答案

首阶段一次 Ask 只有一个非空 `question`。执行器内部可以进行有界的源码读取和模型工具往返，但产品只显示一个 Job、一个终态 Answer。流式进度不是多条聊天消息，不形成对话历史。

### 模式由用户显式决定

Ask/Change 使用明确控件和协议判别字段。以下输入仍保持 Ask：

- “帮我看看这个组件，必要的话修一下”；
- “为什么报错，顺便改好”；
- “把这里改成红色可以吗？”；
- Prompt injection 要求忽略只读规则。

系统可以提示“这个问题似乎包含修改意图”，但只能提供“转到 Change”按钮，不能自动切换、并行创建写任务或把自然语言分类结果当授权。

### 问答必须有选择目标

选择是范围和产品价值的一部分，不只是 UI 前置条件。首阶段拒绝：

- “解释整个仓库架构”；
- “帮我随便找找能优化的地方”；
- 没有选中页面对象的自由聊天；
- 通过问题文本要求把读取范围扩到任意绝对路径。

选中目标后，执行器可以在服务端签发的有界项目源码范围内查找相关定义、导入和调用方；“有目标”不等于允许上传整个仓库。

### Ask 不修改工作区

Ask 的成功定义是返回合格 Answer，不是产生 Diff。Ask 不得拥有：

- `replace_text`、`apply_patch`、文件创建/删除；
- `run_check`、任意命令、外部网络工具；
- `workspace-write`、Apply、Revert 或 auto mode；
- 由模型发起的权限升级、用户输入请求或子 Agent 写任务。

答案可以包含解释性短代码片段，但该片段只按文本安全渲染，永远不会被解析、应用或执行。

### 不做长期历史

首阶段 Runtime 只保留当前页面内最新 Ask draft/result；Node 只为取消、取结果和转草稿保留有 TTL 的最新 Job。没有会话列表、历史分页、搜索、恢复、云同步或磁盘正文。页面卸载、Start over、dev Session 结束或 TTL 到期后内容清除。

## 功能需求

| ID | 要求 |
| --- | --- |
| ASK-F01 | 只有 targets ≥ 1、问题合法、执行器 ready、同意满足且无活动 Ask 时可提交 |
| ASK-F02 | Key 与 Managed Codex 输出同一 `AskAnswerResult` |
| ASK-F03 | 答案块引用只能指向本次服务端签发并复验的 source handle |
| ASK-F04 | 引用可显示文件、行范围、目标关联和置信度，并经既有 open-editor endpoint 打开 |
| ASK-F05 | Ask 可取消；取消后不接受迟到答案 |
| ASK-F06 | 同一 UI 只展示一个当前 Ask；新 Ask 必须由用户重新提交，不隐式追问 |
| ASK-F07 | 一键转换生成 Change draft，但不创建或执行 Change Job |
| ASK-F08 | source/session 变化时答案标记 stale，不把旧引用伪装成 current |
| ASK-F09 | 执行器不可用时提供明确配置/诊断动作，不回退到错误语义的 backend |
| ASK-F10 | 所有模型文本使用安全 DOM renderer，不渲染任意 HTML |

## 非功能需求

- **准确性**：组件名称、源码位置和关系必须区分系统事实、模型推断和未知项。
- **安全性**：Browser/模型不能扩大 sourceRoots、文件数、网络、命令或写权限。
- **一致性**：Vite 和 Next 使用同一领域 Schema、HTTP Job 语义和 Runtime extension。
- **可取消**：Abort 必须贯穿 Browser、Manager、Provider/App Server 和临时资源清理。
- **可访问**：键盘、焦点、屏幕阅读器、200% 缩放和 reduced motion 均可完成 Ask。
- **可观测**：只显示真实阶段、读取数量 bucket、耗时和稳定错误；不展示 reasoning 或伪造百分比。
- **可演进**：未来追问与外部回流通过新 capability/version 增量加入，不改变首阶段单次语义。

## 成功标准

首阶段只有在以下体验同时成立时才算交付：用户选择元素后可以问“这是什么组件”，Key 和 Managed Codex 都能在 SpotPatch 内返回答案；答案至少引用一个支持关键结论的真实源码位置，点击可打开；Ask 期间业务仓库零字节变化；点击转修改后只出现可编辑草稿，用户未再次确认前没有任何写任务。
