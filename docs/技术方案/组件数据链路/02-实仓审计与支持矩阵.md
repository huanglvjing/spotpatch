# 组件数据链路匿名审计与支持矩阵

本页只保留能指导通用产品设计的匿名结论。外部项目用于只读验证，不属于 SpotPatch 源码、测试夹具或发布资产；仓库不得保存其品牌、仓库名、本机绝对路径、域名、分支、提交、真实接口清单、存储键或用户数据。可持续回归必须由仓内中性 fixture 和固定 oracle 完成。

## 调研方法

请求统计和归属判断应组合以下证据，不能只扫描 `fetch` 字符串：

1. TypeScript import/symbol identity 与组件边界。
2. click、submit、effect、render、timer、Query 等触发边界。
3. 本地函数、Hook、Store、API client 的有界跨模块调用图。
4. Axios/fetch/tRPC 等调用形式的参数和响应消费字段。
5. 开发期真实 dispatch observation；未执行的静态依赖保持 declared。

外部调研数据只用于判断适配器优先级。任何百分比或数量如果没有可公开、可复现的仓内 fixture，不得写入发布声明。

## 通用项目形态结论

真实 React 项目通常同时存在以下链路：

| 形态 | 仅看组件函数体的错误 | SpotPatch 所需证据 |
| --- | --- | --- |
| 组件直接 fetch/Axios | 可能漏掉动态 URL 和参数来源 | callsite + trigger + runtime observation |
| 组件调用 Store action | 找不到实际请求文件 | import/symbol edge + action invocation + request callsite |
| 父组件请求后经 props 供给 | 会把子组件误判为请求发起方 | response binding + props data-fed-by edge |
| effect/timer 轮询 | 容易误归到同页面按钮 | lifecycle trigger 与 click trigger 分离 |
| React Query/TanStack Query | 声明 queryFn 不等于当次已执行 | adapter binding + declared/observed 分离 |
| tRPC batch/link | 物理 HTTP 不等于逻辑 procedure | logical operation 与 transport 分层 |
| Vite proxy/API gateway | 浏览器 URL 不等于最终上游 | browser dispatch 与 config-derived upstream 分层 |

## 仓内可移植 oracle

`packages/analyzer/src/portable-project-oracle.test.ts` 在操作系统临时目录内创建中性、多模块源码，然后验证以下能力；测试结束后删除 fixture，不依赖仓库外目录或网络：

| 场景 | 固定断言 |
| --- | --- |
| Store 间接认证 | 两个条件 endpoint 均被识别，关联为 `transitive`，敏感值不进入报告 |
| effect/timer 会话轮询 | 与按钮触发分离；参数键、消费字段、React state 和 callback 去向可证明 |
| 表格数据加载 | query 参数、`data.list/data.total` 和两个 state destination 可证明 |
| React Query 轮询 | queryFn 保持 `declared-not-observed`，不因 Hook 存在而伪报已请求 |

这些 endpoint 使用 `/auth/*`、`/models`、`/payments/status` 等中性测试路径，不代表任何真实服务。

## 当前支持判断

| 能力 | 当前 Vite + React 18 Beta | 边界 |
| --- | --- | --- |
| DOM → intrinsic JSX | 支持 | 仍需 source marker 新鲜度校验 |
| DOM → 复合组件源码 | 支持最近已登记业务组件 | 无 exact identity 时明确降级 |
| `.js/.jsx/.ts/.tsx` 模块索引 | 支持授权 root | 不越过 root，不接受浏览器绝对路径 |
| global fetch、常见 Axios method/create | 支持 | alias、callable instance、复杂 interceptor 尚未完整覆盖 |
| React Query v3/TanStack 直接 queryFn | 部分支持 | `useQueries`、QueryClient 全矩阵未承诺 |
| tRPC logical operation | 实验性支持 | batch/stream/WebSocket 真实版本矩阵未完成 |
| fetch/XHR dispatch observation | 支持 | 不读取原始 body、header、cookie 或 response body |
| response consumed fields | 支持源码消费字段 | 不等于服务端完整响应 Schema |
| 数据库/服务端存储 | 无同仓后端证据时 unknown | 不通过 AI 或命名猜测 |

## 发布与隐私规则

- required CI 必须完全自包含，缺少外部目录时也应正常执行。
- 不允许 `skipIf(externalPathMissing)` 伪装成跨平台覆盖。
- 不读取真实 `.env*`，不访问真实 API，不使用真实 token/cookie。
- 第三方项目只能在独立、私有、非发布的评估流程中使用；结果进入本仓库前必须匿名化。
- 仓库级扫描必须阻止已知第三方品牌、域名、本机外部路径和业务密钥进入提交。
- 新增调用形态先进入中性 fixture、证据规则和回归测试，再扩大 README 支持声明。

## 基线漂移规则

以下变化会使旧结论失效：依赖版本、请求 wrapper、sourceRoots、AST 分类器、Runtime recorder 或协议 Schema 变化。可复现报告应记录 `fixtureVersion`、`analyzerVersion`、`schemaVersion` 和依赖快照；无法复现时不得声称达到发布 Gate。
