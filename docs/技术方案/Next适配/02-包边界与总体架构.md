# Next.js 适配包边界与总体架构

## 抽取前问题

抽取前 `@spotpatch/vite` 同时承载四类职责：Vite 生命周期、通用 JSX source transform、通用本地 HTTP/编辑器服务、Runtime bundle 注入。直接让 `@spotpatch/next` 依赖它会产生以下错误架构：

- Next 用户被迫安装 Vite peer dependency。
- Next 与 Vite 适配器形成反向耦合，任何 Vite 生命周期调整可能破坏 Next。
- 公共服务和转换逻辑只能复制或跨包访问内部文件，违反单一事实来源与发布边界。
- 生产裁剪、测试和安全责任无法按框架分别验证。

当前实现没有在新包里复制 Vite 目录，而是先建立框架无关 Host Core，再由两个平级 Adapter 消费。

## 目标依赖图

```text
@spotpatch/shared
  ├──> @spotpatch/compiler
  ├──> @spotpatch/agent
  ├──> @spotpatch/react-adapter ──> @spotpatch/runtime
  └──> @spotpatch/dev-server ─────> @spotpatch/agent

@spotpatch/vite ──> shared + compiler + dev-server + runtime + react-adapter
@spotpatch/next ──> shared + compiler + dev-server + runtime + react-adapter
```

箭头表示“左侧被右侧依赖”。适配器是依赖图叶子；`runtime` 不依赖 Node-only `dev-server`，`dev-server` 不依赖任何框架适配器，两个适配器也不相互依赖。实际公共包列表和发布闭包仍由总体架构维护 (见 doc-id:02-architecture-stack)。公共预览已新增：

| 包 | 发布属性 | 单一职责 |
| --- | --- | --- |
| `@spotpatch/compiler` | 公共内部依赖 | 框架无关 JSX/TSX 过滤、source marker 注入、source map 和转换诊断 |
| `@spotpatch/dev-server` | 公共内部依赖、Node-only | 选项最终解析、Source Registry、Session、本地 API、编辑器和 Agent 装配 |
| `@spotpatch/next` | 用户入口 | Next 配置组合、CLI、Loader 桥、rewrite、client/noop entry 与版本门禁 |

“公共内部依赖”表示包必须发布到 npm 以闭合依赖图，但用户文档不要求直接安装。`@spotpatch/vite` 与 `@spotpatch/next` 是平级用户入口；两者不得相互依赖。

首个公共预览发布 `@spotpatch/compiler@0.1.0`、`@spotpatch/dev-server@0.1.0` 和 `@spotpatch/next@0.1.0`，并同步更新既有依赖包。依赖方向、构建、`publint`、Are The Types Wrong 和 Vite 回归已通过；包可从 Registry 安装仍不等同于 Next 正式支持。

## 现有源码到目标包的迁移表

本表约束迁移归属，避免“抽取”后原目录与新包同时保留活动实现：

| 当前 `@spotpatch/vite` 职责 | 目标归属 | 迁移要求 |
| --- | --- | --- |
| JSX/TSX 解析、marker 注入、source map | `@spotpatch/compiler` | 先锁定 Vite 行为；迁移后删除原活动实现 |
| 通用 include/exclude 解析 | `@spotpatch/compiler` | 只保留框架无关过滤；Vite/Next 虚拟模块规则留在各自 Adapter |
| Session、Source Registry、公共 handler | `@spotpatch/dev-server` | 协议 schema 与错误码继续来自现有唯一事实源 |
| 源码读取、编辑器打开、Agent 装配 | `@spotpatch/dev-server` | 只暴露窄 Node API，不暴露 Adapter 私有上下文 |
| Vite virtual module、middleware、插件生命周期 | `@spotpatch/vite` | 保持 Vite 专属，不迁移进公共包 |
| Next config、CLI、Loader、rewrite、client/noop entry | `@spotpatch/next` | 全部是新 Adapter 代码，不复制 Vite 生命周期 |
| Runtime/React Adapter 浏览器能力 | 既有公共包 | 两个 Adapter 消费同一发布产物，不创建 Next 副本 |

每一步迁移必须有结构扫描证明旧路径不再被导入，并以 Vite 全量回归证明语义未改变。为了降低一次性改动风险，可以拆成多个 Commit，但同一能力在任一 Commit 中只能有一个活动实现。

## 配置与类型所有权

当前 `SpotPatchOptions` 由 Vite 入口导出，Next 包不得依赖该类型，也不得把它复制为同名接口。目标所有权如下：

- 浏览器与 Node 共用的可序列化模型、枚举和 schema 继续由公共数据模型维护 (见 doc-id:03-public-api-models)。
- compiler 只拥有 transform/filter 输入类型，不拥有 editor、AI、Git 或网络配置。
- dev-server 拥有 Node-only 的最终选项解析、默认值装配和环境凭据解析；其内部解析结果不直接成为浏览器类型。
- `@spotpatch/vite` 导出 `ViteSpotPatchOptions`，`@spotpatch/next` 导出 `NextSpotPatchOptions`；二者组合公共子类型并增加各自宿主字段，不相互导入。
- 同一默认值只能在公共 schema/resolver 中实现一次；Adapter 的类型别名和参数适配不得再次赋默认值。
- Next 首版不接受 `allowLan: true`；如果用户传入必须启动失败并解释限制，不能忽略或错误继承 Vite 行为。

以上是所有权契约。Gate N2 已通过 export/type tests 固化当前公共预览表面；0.x API 仍可按 Changeset 做受审查调整，不能把 `0.1.0` 预览 API 当作稳定兼容承诺。

## Root 与源码授权模型

Next Monorepo 不能用一个含糊的 `root` 同时代表应用目录、Git 仓库和源码授权边界。内部 Host Descriptor 必须区分：

| 名称 | 语义 | 首版规则 |
| --- | --- | --- |
| `appRoot` | 本次本地 Next 应用及 `next.config` 所在目录 | 由 CLI 显式解析并 realpath |
| `projectRoot` | Git/Agent 允许修改的项目根 | 必须是包含 `appRoot` 的已验证仓库根 |
| `sourceRoots` | Loader 可登记和读取的源码根集合 | 默认仅 `[appRoot]`，每项须位于 `projectRoot` 内并单独 realpath 校验 |

Turbopack `root`、`transpilePackages`、workspace symlink 或其他应用目录不会自动扩大 `sourceRoots`。首版对 `appRoot` 外源码显示明确“不在授权范围”，不得为了提高命中率自动授权整个 Monorepo；后续如支持显式多根，必须先扩展公共路径安全模型和测试。

## Host Core 接口

框架适配器只能通过稳定窄接口接入公共内核，不得导入另一个适配器的私有路径：

```ts
interface SpotPatchHostDescriptor {
  readonly framework: "vite" | "next";
  readonly frameworkVersion: string;
  readonly appRoot: string;
  readonly projectRoot: string;
  readonly sourceRoots: readonly string[];
  readonly mode: string;
  readonly command: "serve" | "build";
}

interface SourceRegistrationClient {
  register(absolutePath: string, signal?: AbortSignal): Promise<string>;
}

interface SpotPatchDevService {
  readonly publicHandler: NodeRequestHandler;
  readonly internalRegistrationHandler: NodeRequestHandler;
  close(): Promise<void>;
}
```

这些类型用于表达责任边界，不是逐字对应的当前公共导出。当前 `compiler`/`dev-server` 已以更窄的函数和 schema 组合实现同一约束；公共产品选项、数据模型和默认值继续只有一个来源 (见 doc-id:03-public-api-models)，Host Core 只负责解析和执行，不建立 Next 专用副本。

## 模块责任

### `@spotpatch/compiler`

- 不依赖 Vite、Next、webpack 或 Turbopack。
- 输入为源码、绝对路径、root、已授权 fileId 与不可变过滤配置。
- 输出为源码和 source map；无变更时返回明确空结果。
- 不读取 provider 凭据、不启动服务、不写业务文件。
- Adapter 只负责把框架钩子翻译为编译器输入 (见 doc-id:next-04-transform-source)。

### `@spotpatch/dev-server`

- Node-only；任何导出不得进入浏览器 bundle。
- 拥有 Session、Source Registry、本地协议 handler、源码读取、编辑器和可选 Agent Manager。
- 凭据、Git、检查和 provider 责任继续委托现有 Agent/Provider 模块 (见 doc-id:16-ai-agent-execution)、(见 doc-id:17-model-provider-credentials)。
- 对 Vite 提供 Connect-compatible 适配；对 Next Sidecar 提供原生 Node HTTP 适配。业务规则相同，承载形态不同。

### `@spotpatch/next`

- 只识别 Next phase、版本、bundler、root 和宿主配置。
- 只在开发 phase 配置 source loader、API rewrite 和真实 client entry；非开发 phase 只提供可被树摇掉的 noop 解析。
- CLI 负责启动/停止 Sidecar 与本地 Next binary，不在 `next.config` 求值期间产生长期进程副作用。
- 不重新实现 HTTP handler、Agent、编辑器、marker 算法或公共默认值。

## 运行拓扑

```mermaid
flowchart LR
  CLI[spotpatch-next dev] --> SIDE[Loopback Sidecar]
  CLI --> NEXT[next dev child]
  NEXT --> CFG[withSpotPatch]
  CFG --> LOAD[Webpack/Turbopack Loader]
  LOAD --> COMP[@spotpatch/compiler]
  LOAD -->|internal auth| SIDE
  CFG --> RW[beforeFiles rewrite]
  INST[instrumentation-client] --> CLIENT[@spotpatch/next/client]
  CLIENT --> RT[@spotpatch/runtime]
  RT -->|same-origin API| RW
  RW --> SIDE
  SIDE --> CORE[@spotpatch/dev-server]
```

Sidecar 公共/内部通道的鉴权和生命周期 (见 doc-id:next-05-sidecar-protocol)，客户端和 RSC 边界 (见 doc-id:next-06-rsc-runtime)。

## 禁止依赖与禁止复用方式

- `@spotpatch/next → @spotpatch/vite`：禁止。
- `@spotpatch/vite → @spotpatch/next`：禁止。
- Adapter 导入其他包 `src/**` 或未声明 export：禁止。
- 把 Vite `Plugin`、Next `NextConfig`、webpack LoaderContext 类型放入 shared/runtime：禁止。
- compiler/dev-server 读取 `process.cwd()` 作为隐式 root：禁止；root 必须由 Host Descriptor 传入。
- 以 Next `turbopack.root`、workspace 根或软链接目标自动扩大源码授权：禁止。
- 在两个 Adapter 中保留两份 options schema、保护路径、错误码或编辑器命令：禁止。
- 为减少改动暂时复制实现再“以后抽取”：禁止；迁移按可回滚小步完成，但每一步只能有一个活动实现。

## 迁移纪律

1. 先以现有 Vite 测试锁定行为，不同时改公共语义。
2. 抽取 compiler 后，Vite Adapter 改为消费它并通过全部既有测试。
3. 抽取 dev-server 后，再次让 Vite 全量通过，确认生产 bundle 没有新增 Node 代码。
4. 只有公共内核稳定后才实现 Next 桥；Next 失败不得通过在 Adapter 内复制旧实现绕过。
5. 每个迁移阶段独立 Commit 和 Changeset；不把结构迁移、Next 新功能和 UI 改版混成一个不可审查提交。

编码、文件规模和副作用规则继续执行统一规范 (见 doc-id:11-coding-standards)。
